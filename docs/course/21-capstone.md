# 21 · 换一组条件，独立交付一次

先修：[第 20 课](20-faults.md)。本课不再给计算步骤。目标是用换过条件的数据证明你理解时间、电量和故障链，而不只是记住标准场景的答案。

## 独立任务书

仍是 4S 虚拟包，将容量改为 **1.6 Ah**，采样周期改为 **0.05 s**。起始 SOC 为 1，电流在开关闭合时为 1 A、反馈打开后为 0 A。第一个采样点为 0 s，编号从 0 开始，第 6 个编号点起第一节为 2.98 V；其他三节保持原教学值。

欠压阈值仍为 **≤3.00 V**，连续确认时间仍为 **0.20 s**，故障锁存。虚拟开关反馈在 **0.55 s** 打开。模型沿用上一采样点电流保持到下一采样点的约定。所有数字都只是教学配置。

在运行前，独立写出：首次越线时间、首次断开命令时间、命令与反馈的时间差、到反馈打开时放出的 Ah、末尾 SOC，以及不应该发生的故障。不要先打开配套参考答案，也不要先抄 `report.json`。

## 输入、输出和交付约束

用自己的学员文件运行 `transfer`，保留实际命令。交出一个可由他人复核的目录，包含学员实现、输入、逐拍日志、报告和一页解释。保存仓库提交号、Python 版本及摘要；解释中把预期与实际放在相邻两列，不一致时保留失败版本与修正理由。

```sh
python code/course/learn.py check --work .tmp-my-bms.py --through 18
python code/course/project.py --scenario transfer --work .tmp-my-bms.py --out .tmp-my-run/transfer
```

配套控制器不是要求你从零写整套 BMS。本次交付应准确说出自己实现了哪些函数、使用了哪些框架代码。代码来源清楚比把所有功能都称为“我独立完成”更利于评审。

## 再加一个自己设计的反例

在自己的项目副本中，选择修改电流符号、样本时间或远程请求之一，设计一个**能够推翻错误实现**的输入。交出错误实现为什么可能在正常场景通过、为什么你的新输入会使它失败的说明。不要修改参考测试的期望值来让错误消失。

评审者应按原输入独立重跑，再换一个未见过的边界值。一次通过只证明这批软件行为与约定一致；没有真实电芯、仪器精度、执行器与独立保护的验证，不得写成“整包已安全”。

第 6 个编号点为 **0.30 s**。连续 0.20 s 后在 **0.50 s** 发出断开命令，0.55 s 反馈打开，相差 **0.05 s**，不应产生 `ACTUATOR_STUCK`。从 0 到 0.55 s 电流为 1 A，放出 **0.55 / 3600 ≈ 0.00015278 Ah**；SOC 为 **1 − 0.55 / (3600 × 1.6) ≈ 0.99990451，即 99.99045%**，此后保持。

若仍按“三个低样本”触发，会在 0.40 s 提前动作；若把采样周期改短后延时也减半，同样不合格。若到 0.50 s 就停止记电量，则忽略了命令到实际断开的区间。

反例应有明确能拒绝的错误，例如将放电符号写反的实现，在长一点的放电段会错误增加 SOC；或同一时间戳重复的正常数值，能发现只检查电压范围却不检查新鲜度的实现。只改变数据但不解释预期，不能算迁移证明。
