# 阶段 5 教程：通信与集成

> 对应学习路线的阶段 5。目标：让 BMS 接入真实系统——上位机、储能逆变器、整车 CAN；掌握协议逆向方法论。
> 建议用时 2–4 周。前置：阶段 3 验收。

---

## 5.1 通信在 BMS 里的三个层级

| 层级 | 连接 | 典型接口 |
|---|---|---|
| 板内 | AFE ↔ MCU | I2C / SPI / isoSPI |
| 板间 | CMU 从板 ↔ BMU 主控 | isoSPI / CAN / 菊花链 |
| 对外 | BMS ↔ 上位机/逆变器/整车/手机 | UART / RS485-Modbus / CAN / SMBus / BLE |

阶段 3 解决了板内；本阶段解决对外，板间属阶段 6 高压架构。

## 5.2 UART 实战

商用 BMS 最常见的调试/监控口。通用帧模式（几乎每家都这样）：

```
[帧头 2B][地址/命令 1-2B][长度 1B][数据 NB][CRC 1-2B]
```

- **电平**：3.3V TTL 还是 RS232 电平？先量再插；与电池侧共地时要意识到你是在把电脑接到电池包上——**笔记本用电池供电或加隔离 USB 串口**；
- **学习方法**：打开 [esphome-jk-bms](https://github.com/syssi/esphome-jk-bms) 的源码与 README，它就是 JK 协议的事实文档——帧格式、命令字、数据域偏移、单位换算全在代码里。

## 5.3 RS485 与 Modbus

储能逆变器对接的主流。

- **RS485 物理层**：差分 A/B，半双工；总线两端各一个 120Ω 终端电阻；需要偏置电阻让总线空闲时确定电平；方向脚（DE/RE）切换收发的时序是新手第一坑；
- **Modbus RTU**：
  - 功能码记四个：0x03 读保持寄存器、0x04 读输入寄存器、0x06 写单寄存器、0x10 写多寄存器；
  - 帧 = 从机地址 + 功能码 + 数据 + CRC16（Modbus 用反射多项式 0xA001）；
  - BMS 厂商给"寄存器映射表"：SOC 在 0x0100、单体 1 电压在 0x0101…照表实现即可；
- 参考实现：[esphome-seplos-bms](https://github.com/syssi/esphome-seplos-bms)（Modbus/RS485）、[esphome-pace-bms](https://github.com/syssi/esphome-pace-bms)。

## 5.4 CAN 实战

车用与高端储能的骨干。

- **帧结构**：ID（标准 11 位 / 扩展 29 位）+ DLC + 最多 8 字节数据（CAN FD 可到 64）；
- **仲裁**：ID 越小优先级越高，非破坏性仲裁——多主总线不冲突；
- **物理层**：CAN_H/CAN_L 差分，两端 120Ω 终端；电池包上**必须隔离**（隔离收发器 + 隔离电源）；
- **DBC 文件**：CAN 报文的"寄存器映射表"——定义每条报文 ID 里每个信号的起始位、长度、因子、偏移、单位；学会读 DBC 就学会了车规通信的一半；
- **典型交互**：BMS 周期广播单体极值/SOC/故障；充电时与充电机握手（国标 GB/T 27930 定义了充电机-BMS 报文流程，做充电桩对接时研读）；
- 参考：[dexterbg/Twizy-Virtual-BMS](https://github.com/dexterbg/Twizy-Virtual-BMS)（车规 CAN 仿真）。

## 5.5 SMBus 与 BLE

- **SMBus**：笔记本电池的国际标准（Smart Battery System / SBS 命令集）：I2C 物理层 + 标准化命令（Voltage()、Current()、RelativeStateOfCharge()…）。逆向实战看 [BQ20Z70 逆向工程](https://github.com/omarKmekkawy/Reverse_Engineering_BQ20z70_Laptop_BMS)；
- **BLE**：手机 App 监控的主流。GATT 服务模型：服务 → 特征值（read/notify）；厂商私有服务里跑各自的串口透传协议；长数据要协商 MTU + 分包重组。参考 [fl4p/batmon-ha](https://github.com/fl4p/batmon-ha)（支持 JK/JBD/Daly/ANT 多家 BLE 协议，是绝佳的多协议对比样本）。

## 5.6 协议逆向方法论（本阶段最值钱的技能）

面对一块无文档 BMS：

1. **抓包**：逻辑分析仪（UART/RS485/I2C）或 USBCAN（CAN），抓 App ↔ BMS 的完整会话；
2. **控制变量找字段**：只改变一个已知量（如让某节电压变化、记录当前 SOC），对比多帧，找出变化的字节 → 定位字段与字节序；
3. **单位与系数**：字节值与真实值成比例关系（如 电压 = raw × 0.001V），用两个已知点解线性方程；
4. **CRC 反推**：取多组完整帧，逐一试常见组合（CRC8/CRC16、多项式、初值、反射、异或输出）——先用 syssi 仓库里**已知协议的帧**验证你的 CRC 计算程序是对的，再去碰未知协议；
5. **写解析器**：状态机逐字节接收（找帧头 → 收长度 → 收数据 → 验 CRC），加超时重组，坏帧丢弃计数——**绝不因一帧坏数据死机**。

## 5.7 自测题

1. 用电脑直连 BMS 的 UART 调试口有什么风险？怎么规避？
2. RS485 半双工的方向切换为什么容易丢首字节？
3. Modbus RTU 怎么界定一帧的开始与结束？（提示：不只是 CRC）
4. CAN 仲裁为什么能"非破坏"？ID 分配的原则是什么？
5. DBC 文件里"因子/偏移"解决什么问题？
6. 逆向协议时，为什么先用已知协议的帧验证你的 CRC 程序？
7. BLE 长数据传输要处理哪两件事？

## 5.8 动手任务与验收

**动手任务**

1. 用 ESP32 + 隔离串口读取一块商用 BMS（JK/JBD/小翔任一），对照 syssi 源码实现帧解析，把电压/电流/SOC 打印出来；
2. 把它接入 Home Assistant（直接用 batmon-ha 或自写 MQTT 上报）；
3. 进阶挑战：抓一段未知 BMS 的通信，按 5.6 流程定位 SOC 字段并验证 CRC。

**验收清单**

- [ ] 能独立实现一个 UART 协议解析器（状态机 + CRC + 坏帧处理）
- [ ] 能照寄存器映射表写出 Modbus RTU 的读写
- [ ] 能读懂 DBC 并手工解码一条 CAN 报文
- [ ] 完成至少一次真实的协议逆向（哪怕只逆向出一个字段）
