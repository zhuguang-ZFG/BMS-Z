# 教学设计规范：把一个知识点真正讲透

> **适用范围**　书稿、阶段教程、动画、视频、共学任务和配套实验。
>
> **核心要求**　每个单元只承诺一个主要学习结果；内容可以深，但认知路径必须短而连续。

## 六步讲透法

## 制作前先交一张“讲透卡”

没有讲透卡，不进入写稿、画动画或配音。每个单元先写清五项：

1. **唯一目标**：学完只能承诺一件最重要的事。
2. **生活钩子**：一个读者见过的现场，不从术语和目录开始。
3. **贯穿算例**：同一组输入从问题走到答案，中途不换数字。
4. **常见误解**：写出一个“看起来合理但缺证据”的错误答案。
5. **取回交付**：读者关掉页面后，必须能说、算、画或运行出什么。

BMS-Z 的核心问题把这五项写在 `curriculum/concepts.json`：`question`、`teaching.hook`、`teaching.worked_example`、`teaching.misconception` 与 `deliverable`。生成器会把它们写进核心问题地图，检查器会拦缺项。

### 1. 现场问题

先给读者一个能看见的现象，再给名词。

好例子：满电出门，一拧把掉两格，是电量消失了，还是带载电压下去了？

不推荐：本节介绍内阻、极化与端电压模型。

开头必须让读者知道三件事：发生了什么、为什么值得管、学完能回答什么。

### 2. 直觉图景

用一个图景承载机制，但类比必须标清边界。类比负责帮助入门，模型负责保证不误导。

- 油表与油箱可以区分 SOC 与 SOH，但电池不是装液体的桶。
- 最短木板可以解释多约束取最小，但不同约束会随时间和状态变化。
- 晚高峰进站可以解释“来得及不及嵌入”，但不能代替析锂判据。

每个类比后补一句“它在哪儿会失效”。

### 3. 最小模型

公式只为刚才的问题服务。公式出现前先回答：

1. 左边是什么结果？
2. 右边每一项代表哪种物理作用？
3. 哪些量能测，哪些量只能估？

第一次出现的公式优先用一行最小形式。更完整模型放在后面的深挖层，不抢主线。

### 4. 完整算例

一组输入从问题开头一直走到结果，途中不换参数。算例要写：

- 已知条件与单位；
- 每一步为什么这样算；
- 数量级是否合理；
- 结果能支持什么结论，不能支持什么结论。

只给最终数字不算算例；同时摆三组互不相关的数字也不算贯穿案例。

### 5. 反例与边界

至少安排一个“看起来对，其实条件不够”的判断：

- 电压一样，所以 SOC 一样；
- 采样位数更高，所以测量一定更准；
- 滤波更强，所以结果一定更好；
- 测试全绿，所以修改一定安全。

边界应指出缺的证据，而不只是说“这是错的”。

### 6. 取回与行动

读者必须在没有答案提示时做一次输出。优先顺序：

1. 先自己判断；
2. 用给定数字算一步；
3. 解释一个反例；
4. 运行或修改一个最小实验；
5. 写下条件、结果和证据。

“再读一遍”不算练习，“照抄命令但不解释结果”也不算完成。

## 各媒介的职责

| 媒介 | 最适合做什么 | 不应承担什么 |
|---|---|---|
| 书 | 完整推导、条件、来源、工程边界 | 用连续长段代替结构 |
| 阶段教程 | 安排学习顺序、串起任务 | 收录所有延伸知识 |
| 动画 | 展示时间、空间、因果变化 | 只做装饰性闪动 |
| 视频 | 用一个例子带着观众走完过程 | 做资料目录或逐页念稿 |
| 代码 | 复算数字、故障注入、形成证据 | 假装代替真实硬件验证 |
| 练习 | 暴露误解、检查能否迁移 | 只问原文记忆 |

## 书稿规则

- 每章先给现场、故障或异常数字，再在分层导航里写清第一次主线要带走什么。
- “第一次主线／第二遍深挖／动手验证”写进 `chapter-route` 阅读路径组件，不伪装成正文段落；每条只回答去哪里和交什么，不提前复述章节结论。
- 主线正文允许第一次阅读跳过深挖框，跳过后仍能连贯。
- 新术语第一次出现时，用普通话解释，再给严格定义。
- 连续三个抽象段落之后，必须出现图、表、数字例子、问题或实验中的一种。
- 练习固定优先为三题：判断机制、手算量级、指出边界。
- 章末不重复整章摘要，只写“下一步去哪”和“还缺什么证据”。

### 技术书稿精修

这一组规则参考三个持续维护的开源教材项目，只借内容组织，不借原文：

- [《动手学深度学习》](https://github.com/d2l-ai/d2l-zh)把概念、公式、可运行代码和练习放在同一学习单元。BMS-Z 的关键数字也要在章内完成“解释—运行—对账”，不能只把命令丢到章末。
- [OSTEP homework](https://github.com/remzi-arpacidusseau/ostep-homework)按章节绑定模拟器。书中实验先让读者写预测，再运行脚本，最后解释预测与输出为什么不同；只复述终端结果不算完成。
- [The Missing Semester](https://github.com/missing-semester/missing-semester)从真实任务和命令进入原理，并把练习留在同一讲。章节开头因此优先用故障、输出或一笔异常数字，不先做主题综述。
- 同一个判断只完整解释一次。后文需要复用时，补新条件或回链原节；换一组近义词再讲一遍，不算“第二遍深挖”。

精修时先删重复结论、泛化比喻和自我报幕，再处理句子。保留公式、数字、来源、可运行入口和读者必须做出的判断；不能为了“像人写的”制造口语、错字或无关轶事。

## 动画规则

- 一张图只回答一个问题；标题写问题或结论，不写宽泛主题。
- 第一帧已经可读，最后一帧是完整答案。
- 每一拍只新增一个因果部件，新增时旁边直接出现标签。
- 指示物的运动代表真实量：电荷、数据、热、状态或时间。
- 动画外必须有独立文字说明，确保不播放也能理解。
- 配一个观察任务，例如“先盯住最弱单体”“注意第三拍才关断”。

## 视频规则

- 微课 2–5 分钟，只讲一个问题；系统总课可以更长，但必须有明确章节。
- 开头两秒出现现象、错误答案或具体问题，首帧不从黑场、Logo 或目录开始。
- 一个真实输入贯穿全片，不在中途换例子。
- 旁白解释因果，屏幕显示对象、步骤和数字；两者不逐字重复。
- 少用纯文字卡和三卡并列；优先让一张图逐步长出来。
- 每 2–4 秒有新的信息变化，但读文字时文字本身保持稳定。
- 结尾只落一个结论，并给一个可回答的小问题。

## 难度与语言

- 句子优先一层因果：因为 A，所以 B；需要第二层时另起一句。
- 首次出现的缩写同时写中文身份，例如“AFE（模拟前端，负责多串采样）”。
- “显然、容易知道、众所周知”一律改成具体中间步骤。
- 口诀用于取回，不用于代替机制。
- 任何阈值都要写适用对象、条件和来源；教学示例明确写“示意”。
- 一句话一个强动词。名词化拆回动词：“对电压进行采集”写成“采它的电压”。
- 中文句子以 20 字为写作目标、40 字为硬上限。超过 40 字先问能不能断开；断不开（一条算式、一串参数、一个枚举）就保留，不要为凑字数把因果拆散。
- 不用双重否定。“并非不可用”写成“可用，但有条件”，并把条件写出来。
- 段首第一句是本段结论或本段要回答的问题，不把结论藏到段尾。
- 数字和它成立的条件写在同一句里。不写“内阻是 35 mΩ”，写“这台合成电芯在 25 °C、10 s 窗下的内阻是 35 mΩ”。
- 先具体后抽象：先给一次读数、一个故障或一笔算术，再给名字和一般结论。
- 同一个概念全书一个名字。已选定的叫法不再换近义词，换名要全书一起换。

这一组句子规则的来源与当前基线：句长目标与上限参考[阮一峰《中文技术文档写作规范》](https://github.com/ruanyf/document-style-guide)，一句一个强动词、名词化改动词、先具体后抽象参考 [Google Technical Writing](https://developers.google.com/tech-writing) 与 [Microsoft Writing Style Guide](https://learn.microsoft.com/style-guide/welcome/)，“一次只引入一层新信息”对应 Sweller 1988 的认知负荷结论。2026-11 实测全书 36 章正文（剔除代码块、公式、表格、列表后 2513 句）：均句长 31.5 字、中位 27 字、超 40 字的占 24%、超 60 字的占 8%。超限率最高的是第 32、9、31、11、29 章（36%–46%），改写从这几章起。

## 质量检查

一个单元发布前，逐项回答：

- [ ] 能用一句话说清唯一学习目标。
- [ ] 开头是问题或现场，不是定义目录。
- [ ] 至少有一个贯穿案例。
- [ ] 公式前解释了每个量的物理身份。
- [ ] 至少展示一个错误直觉及其缺失证据。
- [ ] 有一次不看答案的取回练习。
- [ ] 数字、单位、符号和来源可复算。
- [ ] 不看动画或不开声音，仍有可访问的理解路径。
- [ ] 学完后明确下一步行动，不把资源清单当作结尾。

自动审计只能发现篇幅、版式和练习密度等风险，不能代替真实读者试学。最终判断仍应来自任务：读者能不能自己解释、计算、诊断或做出一份可复算结果。
