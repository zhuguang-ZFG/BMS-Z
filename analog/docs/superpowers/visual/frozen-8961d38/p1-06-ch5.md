### 5.1 推挽输出（Push-Pull / 图腾柱）

```
        VDD
         │
      ┌──┴──┐
      │ PMOS│  ← 上管：导通时把输出"推"向高电平
      └──┬──┘
         ├────── OUT
      ┌──┴──┐
      │ NMOS│  ← 下管：导通时把输出"拉"向低电平
      └──┬──┘
         │
        GND
```

**工作原理**：两个互补管轮流导通，**两个方向都能主动驱动大电流**：

- 输出高：上管导通，主动供流（source current）
- 输出低：下管导通，主动吸流（sink current）

**优点**：驱动能力强、上升/下降沿都快、静态功耗低
**致命禁忌**：**两个推挽输出直连且电平相反 = 短路**（一个推高一个推低，电流仅受管阻限制，可烧毁 IO）。所以：

- 多设备共享总线时**绝不能**用推挽
- 上下管切换瞬间存在微小共同导通窗口 → 直通电流（shoot-through），CMOS 芯片动态功耗和电源毛刺的来源之一

<img src="assets/photos/web/mosfet-jcs4n65f.jpg" width="240" alt="JCS4N65F N 沟道 MOSFET TO-220 实物（Wikimedia Commons，CC BY-SA 4.0）">

> **实物照片**：分立输出级的主角——TO-220 封装的 N 沟道 MOSFET。金属背板就是漏极：上散热片方便，也意味着背板带电，绝缘垫片与爬电距离在布局时就要算进去。第 4 章的门极电荷、开关损耗，全都藏在这三根脚里。

<!-- slot:intuition -->
> **图问**：上下两管轮流值班，为什么最怕它们同时上岗——那半微秒里发生了什么？

<p align="center"><img src="assets/svg/pushpull-stage.svg" width="720" alt="推挽输出级SVG动画：图腾柱与直通电流"></p>

[动画演示 5.53](p5-00-part5.md#demo53)

**算一笔**（两推挽直连有多狠）：5V 供电、上下管各 25Ω →
$I=\dfrac{5V}{25\Omega+25\Omega}=100mA$。这股电流不经过负载，**纯粹在两只管子之间烧掉**。
所以共享总线（I²C、多设备数据线）绝不能用推挽，必须用开漏或三态（[5.2](p1-06-ch5.md#sec-5-2)、[5.4](p1-06-ch5.md#ch5)）。
另一笔账更隐蔽：上下管换班的几 ns 里两个都半开，VDD→GND 被短暂打通（**直通电流 shoot-through**）。
这正是 CMOS 动态功耗和电源毛刺的主要来源，芯片靠「死区时间」（先关后开）把它压下去。

> **为什么**：两块板子一对接就烧 IO：推挽各占一头车道，中间没收费站，车流直撞进地。路上车能刹车，管子不能：撞上只会顶着管阻越撞越猛，直到烧穿。所以共享总线禁推挽、冲突端串电阻，管的是别两头放行；要并道，先设收费站。

[在线演示：CMOS 反相器](https://www.falstad.com/circuit/e-cmosinverter.html)：点左侧输入换挡，看两只管车永远只有一台放行——输入高，下管把输出停进地道；输入低，上管把它推上天桥。

**典型应用**：MCU GPIO 默认模式、74HC 逻辑输出、B 类/AB 类音频功放的输出级。输出级用 NPN+PNP 互补对管，会有**交越失真**：两管都未导通的死区造成波形过零畸变，AB 类用二极管偏置消除。

**读懂数据手册里的输出参数**：输出级强弱在数据手册里拆成四个量：$V_{OH}$/$I_{OH}$ 与 $V_{OL}$/$I_{OL}$。$V_{OL}$ 必须和 $I_{OL}$ 成对读——"输出为低、且仍保持不高于这个电平"是有条件的，条件就是灌入电流不超过 $I_{OL}$；单抄 $V_{OL}$=0.2V 没有意义。CMOS 推挽的输出管近似受栅压控制的电阻，$V_{OL}$ 随灌电流线性爬升，这条曲线的斜率就是输出阻抗：3.3V 的 MCU GPIO 常见 20~50Ω，74HC 在 5V 下约 50Ω。同一颗芯片供电从 5V 降到 3V，栅极过驱动变小，输出阻抗可能翻倍——"这颗芯片能带多少负载"必须带着供电电压和温度一起说。

**TTL 与 CMOS 输出级不是一回事**：74 系列老 TTL 的图腾柱由 NPN+NPN 构成，上管经限流电阻与射极跟随输出，拉电流能力只有 0.4mA 级，灌电流却有 16mA——严重不对称。这就是"老 TTL 板上 LED 一律低电平点亮"的原因：灌电流路径强。CMOS 推挽上下对称，拉灌能力接近。两代逻辑对接时这条不对称最咬人：TTL 输出高电平最低只有 2.4V，直接推 4000 系列 CMOS（$V_{IH}$=3.5V）不合格，要么选输入阈值按 TTL 修低的 74HCT，要么给 TTL 输出加一个上拉电阻把高电平顶上去。

**边沿速度与串阻**：推挽沿快是优点，也是射频干扰源。边沿 1~2ns 时，10cm 走线已近似传输线，负载端反射打出振铃。常见做法是在驱动端串 22~33Ω：与走线特征阻抗粗配，吸收第一次反射，同时把边沿拖慢到 ns 量级。经验/常见做法：MCU 到板内芯片的时钟线串 22Ω、板间排线串 33Ω，是性价比最高的两个阻值。串阻的另一面是牺牲直流驱动：低电平灌电流要在串阻上产生压降，$V_{OL}$ 预算必须把它算进去，否则多个下游输入同时接入时会顶穿 $V_{IL}$。

**动态功耗的账**：CMOS 推挽静态几乎不耗电，动态功耗 $P=C_LV_{DD}^2f$：每翻转一次，负载电容被充放一次，能量 $CV^2$ 的一半耗在上管、一半耗在下管。一根 20pF 信号线在 5V、10MHz 下只有 5mW，看似无事；64 根数据总线一起翻转就是 320mW，再叠加直通电流项——SoC 的功耗预算里输出级一直占大头。直通损耗与边沿时间正相关：栅驱动越慢，上下管共同导通的窗口越宽。所以给逻辑输入加 RC 滤波拖慢边沿，代价是驱动它的那颗芯片直通损耗上升；滤波是全局决策，不是免费的。

**算一笔**（同一根线，只降电压）：20pF、10MHz 不变，$V_{DD}$ 从 5V 降到 3.3V——$P=CV^2f$ 从 5mW 掉到 $3.3^2\times20\text{pF}\times10\text{MHz}=2.2\text{mW}$。功耗按 $V^2$ 缩、省 56%，这就是低压 SoC 省电的第一性原因；代价是噪声容限与 $V_{IH}/V_{OL}$ 预算同步收紧（5.2 的合围要重跑）。

**常见误设计**：一是两颗不同电压域的推挽 GPIO 直连——5V 输出灌进 3V 芯片的 IO，击穿栅氧，应改电平转换或开漏；二是推挽输出直接驱动 LED 不加串阻，把 $I_{OL}$ 上限当持续功率用；三是用万用表直流档判断输出"正常"，10MΩ 输入阻抗看不出输出阻抗已劣化，应带一个已知负载（如 1kΩ 对地）再看电平掉不掉。

**直推功率 MOS 的坑**：GPIO 推挽直接接功率 MOS 栅极是新手高发事故。栅极不是小负载：功率 MOS 的栅电荷 $Q_g$ 几十 nC，GPIO 用几十Ω的输出阻抗去充，开关沿被拖到 µs 级，每次开关损耗 $Q_gV_{DD}$ 全部烧在 GPIO 的输出管上；开关慢还让半桥里的上下管共同导通窗口变宽，直通电流成倍增加。另外 MOS 的 $V_{GS(th)}$ 按 4V 规格时，3.3V GPIO 根本无法完全开通，管子半开半关、发热惊人。专用栅极驱动芯片用推拉输出、1~2A 峰值充放电流，把这一切问题按价格解决——GPIO 只负责发逻辑，不负责灌栅电荷。

**上电瞬间的默认态**：芯片上电初期 GPIO 大多处于高阻，真正决定系统行为的常常是挂在引脚上的上下拉，GPIO 自己说了不算。BOOT/模式选择引脚在电源上升沿被采样，那一刻上拉还没建立电压，读到的就是随机值——所以配置引脚的上下拉必须直接接死到电源/地，不允许"由另一颗芯片帮忙拉"这种间接设计。复位期间和复位后的默认电平、默认输出模式，是读数据手册时最容易跳过、又最容易翻车的一节。

**输出结构选型的三个问题**：拿到一个接口需求，按顺序问三句。谁连谁？点对点专用线用推挽（最快最省）；多方共享线用开漏或三态。要不要双向？双向线只能开漏或三态，推挽没有退路。有几个电压域？跨域就老实上电平转换，别赌运气。三问的答案定了，输出结构基本就定了，剩下才是取值计算。

**拿到一块板子，怎么判输出类型**：原理图缺失或抄板时，用三步实验判别。第一步，静态电平：驱动器输出高，量线上的电压，贴近 VDD 是强源；明显低于 VDD 一截可能是经电阻上拉的开漏。第二步，轻载试验：经 1kΩ 对地，电平基本不动的是推挽（输出阻抗远小于 1kΩ），被拉掉一半以上的是经大电阻上拉的开漏。第三步，反向注入：让驱动器输出"高"，经 10kΩ 把线往下拉——推挽纹丝不动，开漏轻松被拉低，三态则取决于它当刻是否使能。三步做完，类型基本定案；配合量对 VDD 的电阻值（kΩ 级=有上拉），连上拉阻值都能估出来。

**"8mA 驱动"的 GPIO 档位是干什么用的**：不少 MCU 的 IO 可以配 2/4/8/20mA 驱动档，本质是换输出管的尺寸（宽长比）：档位越高，输出阻抗越低、沿越陡、直通与地弹也越大。配档的依据不是"越强越好"：低速信号配低档，EMI 和地弹都小；只有时钟、长线、大容性负载才值得配高档。地弹值得一提——8 个输出同时翻转、每个 20mA 时，公共地引脚上流过 160mA 的瞬时电流，走线电感上产生 $L\,\mathrm{d}i/\mathrm{d}t$ 的压降，把"地"本身弹起来，其他安静输出的电平跟着抖。这就是为什么大电流翻转要分散、地引脚要够多、高档驱动要省着用。

### 5.2 开漏输出（Open-Drain）

<p align="center"><img src="assets/svg/pushpull-opendrain.svg" width="720" alt="推挽vs开漏动画：为什么I2C选慢的"></p>

[动画演示 5.5](p5-00-part5.md#demo5)

> **精髓**：推挽是"两个人抢着开车"——独享时最快，共享时互撞。开漏+上拉是"大家都能踩刹车"，慢，但永不冲突。I2C 用速度换来了多主仲裁的能力。

**开漏的"线与"为什么安全？** 开漏管只能往下拉（导通灌电流到地），或放手（高阻），永远不会主动往上推。多个开漏输出并在一根线上：任何一家说"低"，线就是低；所有家都放手，上拉电阻才把线"请"回高。没有推挽上管，就不存在"一个推高一个拉低"的电源短路路径。**代价全在上升沿**：放手后线上电压靠 $R_p$ 对总线电容 $C_{bus}$ 充电，$\tau=R_p C_{bus}$。$R_p$ 小了快但静态费电，大了省电但慢。I2C 标准模式 100kHz 用 4.7kΩ、快速模式 400kHz 要 1~2kΩ，就是这笔账的直接体现（[15.x 高速设计](p3-02-ch15.md#ch15) 还会遇到它）。


```
                    VDD
                     │
                  [上拉电阻 Rp]  ← 必须外接（或内部使能）
                     │
OUT ────────────────┤
                     │
                  ┌──┴──┐
                  │ NMOS│  ← 只有下管
                  └──┬──┘
                     │
                    GND
```

**工作原理**：只有 NMOS 下管，漏极悬空：

- 管子导通 → 输出**主动拉低**
- 管子截止 → 输出**浮空**，靠上拉电阻拉到高电平

**三大不可替代用途**：

**① 线与（Wired-AND）总线：I2C 的物理基础**
多个开漏输出接同一根线：**任何一个拉低，全线为低**；全部释放才是高。这天然实现了：

- 多主机仲裁（I2C 逐位仲裁：发 1 时监听总线，发现被拉低就认输退出）
- 时钟延展（从机拉低 SCL 强制主机等待）
- 这就是为什么 **I2C 规范强制要求开漏 + 上拉电阻**

**② 电平转换**
上拉电阻接到目标电压：3.3V 芯片的开漏输出上拉到 5V → 直接驱动 5V 逻辑。双向电平转换芯片（如 PCA9306）内部靠的同样是这一原理。

**③ 共享中断/复位线**
多个芯片的 INT 输出挂在同一根线上，低有效。任何一个都能拉低请求中断，互不冲突。

**上拉电阻计算**（速度 vs 功耗的权衡）：

- 下限（驱动能力）：$R_{p(min)} = \frac{V_{DD}-V_{OL(max)}}{I_{OL}}$，I2C 标准模式典型 3mA → 5V 系统约 1.5kΩ 起
- 上限（上升时间）：总线电容 $C_b$ 充电，$t_r ≈ 0.8473 \times R_p \times C_b$，I2C 快速模式要求 $t_r<300ns$、$C_b<400pF$ → $R_p \lesssim \dfrac{300ns}{0.8473\times400pF}\approx890\Omega$（工程上取 820Ω；总线电容只有 100pF 时才放宽到 3.5kΩ）
- 经验值：**I2C 常用 2.2kΩ~4.7kΩ**；低速/长线偏大，高速/短距离偏小

**0.8473 从哪来**：I²C 规范把上升时间定义为从 30% 爬到 70% $V_{DD}$ 的时间。RC 充电 $V(t)=V_{DD}(1-e^{-t/\tau})$，对 30% 与 70% 分别解出 $t_1=0.357\tau$、$t_2=1.204\tau$，相减得 $t_r=0.847\tau$。它是纯几何结果，与电压无关，3.3V 与 5V 总线同值。下降沿是另一回事：开漏管主动灌电流，时间由导通电阻决定，几十 ns，与 Rp 无关——所以 I²C 波形总是"缓升陡降"，示波器上一眼认出。这也解释了为什么重载总线上减小 Rp 改善的只有上升沿，下降沿纹丝不动。

**Rp 的四个约束一起看**：除了上文的速度上限与驱动下限，还有两条常被漏掉。其三是总线漏电流：全部挂网器件在高温下的漏电叠加（每个 1~10µA），漏电在 Rp 上的压降不能把高电平拉出 $V_{IH}$，即 $R_p\le\dfrac{V_{DD}-V_{IH}}{I_{leak}}$——长总线、宽温、多器件时这条常先卡住。其四是 sink 能力复核：Rp 取小后，拉低器件要灌 $V_{DD}/R_p$；多主仲裁时两主同时拉低，电流叠加，仍须留在 $I_{OL}$ 额定内。3.3V 配 1kΩ、两主冲突即 6.6mA，已超标准模式 3mA 规格——先确认你的总线跑的是哪种模式等级，再决定放多小。

**总线电容怎么估**：$C_b$=每个器件的引脚电容（5~10pF）+走线电容（经验值约 1pF/cm，排线与过孔密时更高）。四颗器件、20cm 走线约 60pF，离 400pF 上限还远；但排线长的背板轻松超过 200pF。设计顺序是先数器件、估走线，算出 Rp 区间，再用示波器实测验证。反推同样成立：实测 $t_r$ 除以 0.847 再除以 Rp，就是总线电容的测量值——这是拿"测得准的量"倒推"测不准的量"的常用手法。

**上拉放哪里**：单主机小系统无所谓；多板系统里上拉应靠近经常拉低的器件（通常是主机或中央从机），缩短大电流回流路径。多电源域各挂各的上拉是禁忌：两域各上一颗，等效电阻减半且电流互灌，必须改用双向电平转换芯片集中处理。

**电平转换的细节**：PCA9306 这类双向转换器的核心是"空闲时靠上拉、拉低时靠体二极管引路"：任一侧被拉低，内部 MOS 的体二极管先导通，另一侧跟随下降，两侧压差超过约 0.3V 后 MOS 开启把两侧短接。理解这一点就明白为什么它要求两侧都配上拉、为什么转换后的低电平略高于源侧（二极管垫了一层）、以及为什么它只能服务开漏信号，推挽波形过不去。

**仲裁为什么只有在开漏上才成立**：I²C 多主仲裁的规则是逐位比拼：主机每发一位，发完立刻读回总线。发出 1 的主机已经松手（开漏的高阻），此时读回 0，说明有别的低电平在——对方发的 0 赢了，自己退出。整个过程没有任何一方受损：赢家继续通信，输家等总线空了重来。这套机制的前提是"发 1 = 什么都不做"，只有开漏做得到。换成推挽，发 1 的主机在物理上把总线顶成高，读回的永远是自己的电平，仲裁无从谈起，两主的输出级还会当场对撞。同理，时钟延展要求从机能拉低 SCL，所以 SCL 也必须是开漏——很多人以为只有 SDA 开漏，其实两根都是。

**更快模式的新账**：I²C 快速模式+（1Mbps）把上升时间压到 120ns、总线电容上限放宽到 550pF，代价是拉低电流规格提高到 20mA。代回上升时间式：$R_p\le\dfrac{120ns}{0.847\times550pF}\approx257\Omega$——上拉已经小到两位数级，静态功耗 $\dfrac{3.3V}{257\Omega}\approx13mA$。这就是为什么 FM+ 系统几乎都用驱动器缓冲或总线保持芯片，而不是死磕小电阻：速度、电容、功耗三条曲线在高速模式集体收紧，靠一颗电阻调和不了。

**实测判据**：测上升沿要按规范定义取 30%→70%，不是示波器默认的 10%→90%——两者差一倍多，拿错定义会误判合格。探头用 10×档，×1 档的探针电容近百 pF，直接把小总线测"坏"。合格线并非"看着陡"：要把 $t_r$ 与模式等级的要求对表；边缘情况多测几台设备、测满温箱温度，因为漏电流与阈值都随温度动。

**算一笔（四种约束合围一个 Rp）**：3.3V 总线、$C_b$=100pF、快速模式（$t_r$<300ns、$I_{OL}$=3mA、$V_{OL}$≤0.4V、$V_{IH}$=0.7×3.3=2.31V、总漏电按 10µA）。速度上限：$R_p\le\dfrac{300ns}{0.847\times100pF}\approx3.5k\Omega$。驱动下限：$R_p\ge\dfrac{3.3-0.4}{3mA}\approx967\Omega$。漏电上限：$R_p\le\dfrac{3.3-2.31}{10\mu A}\approx99k\Omega$（不卡）。单主拉低电流下限不触发。合围结果：967Ω~3.5kΩ，取中间值 2.2kΩ，两头都留余量——这就是"实板常见 2.2k"的完整来历。任何一条约束变了（总线电容加大、模式提速、器件加多），先重跑这道围合，再动电阻。

**上拉电阻自己的额定功率别漏算**：上拉长期耗电 $V_{DD}^2/R_p$，总线被拉低时全部落在电阻上。3.3V、1kΩ 是 11mW，0603 电阻随便扛；但 5V、100Ω 这种强上拉就是 250mW，0402 封装已超 1/16W 额定——设计强上拉时顺手核一下封装功率，别让电阻成为新的发热点。脉冲场合（总线偶尔拉低）按平均占空比折算即可，长亮的指示灯线才按连续功率算。

**开漏与三态、推挽放在一张桌上比**：三者输出"高"的方式完全不同——推挽用上管硬顶（强、快、费硅），开漏靠电阻慢慢充（弱、慢、零冲突），三态干脆不输出高（让给别人或交给偏置）。选型口诀：独占线求快选推挽；共享线求不冲突选开漏；分时复用的大总线选三态+时序。三态本质是推挽加一个"闭嘴开关"，所以它继承了推挽的全部冲突风险，只是把冲突时机交给了时序设计去管理——这一点决定了 5.4 里那些时序规矩为什么一条都不能少。

**开漏家族的另一位成员：比较器的集电极开路输出**：LM393 这类比较器的输出就是裸的开集（BJT 版开漏），配上拉才能出波形。它的上拉取值逻辑与 I²C 同一套：阻值决定上升沿，灌入电流不能超比较器的吸流能力（LM393 典型 16mA 上限内还要留余量）。常见误设计有两个：一是上拉取 100kΩ，上升沿几 µs，比较器明明 0.4µs 响应，输出却像被糊住——把响应速度与输出沿速度混为一谈；二是拿这种输出直接推动 CMOS 输入但上拉过大，高电平建立慢，施密特门在中间区多次翻转，现象是"一个边沿触发好几次"。比较器输出线上挂个小容量 RC 或直接用施密特输入门整形，是标准配套动作。

### 5.3 上拉电阻与下拉电阻

**为什么需要**：逻辑输入端不能浮空（高阻态）。浮空引脚像天线，随机感应高低电平，导致误触发、功耗异常。原因是 CMOS 输入停在半电平时，内部两管同时微导通，形成直通电流。

**表 5-1　上拉与下拉电阻：接法与默认电平**

| 类型 | 接法 | 默认电平 | 典型场景 |
|---|---|---|---|
| 上拉 | 信号线→电阻→VDD | 高 | 低有效按键、开漏总线、EN 引脚默认使能 |
| 下拉 | 信号线→电阻→GND | 低 | 高有效按键、未用 MOS 栅极防误导通 |

**取值原则**：

- 太弱（阻值大）→ 抗干扰差、翻转慢；太强（阻值小）→ 浪费功耗、驱动器拉不动
- 经验范围：**1kΩ~100kΩ**，常用 10kΩ
- MCU 内部上拉通常 30~50kΩ，属弱上拉，仅供防浮空，**不能**当 I2C 上拉用。

**按键与 EN 引脚的取值账**：按键场景，上拉决定两件事：按下时灌 $V_{DD}/R_p$（10kΩ、3.3V 即 0.33mA，电池设备要评估按键常被按住的概率），以及断开时的抗扰门限——阻值越大，引脚越容易被邻近走线耦合出假边沿。经验/常见做法：面板手按按键用 10kΩ；长走线或强干扰环境用 4.7kΩ；引脚自带内部上拉且只求防浮空时可以省掉外部电阻。EN/BOOT 类配置引脚的上下拉同样取 4.7~10kΩ：太大挡不住漏电与干扰，太小则在跳线动作时白白耗流。

**抖动与消抖**：机械按键闭合与断开伴随 1~20ms 的弹跳，示波器单次触发能看到一串毛刺。硬件消抖用 RC 加施密特输入：10kΩ 上拉配 1µF 对地，时间常数 10ms 量级，弹跳被积分抹平；RC 太小等于没消，太大则松手后恢复慢、连击会被吞掉。软件消抖（连续 20ms 读到同一电平才认）是更省料的常见替代，两者取一即可，不必叠加。

**上下拉与漏电流的竞赛**：任何上下拉都要赢过输入端漏电流。手册给 $I_{IL}/I_{IH}$（室温 ±1µA 量级，高温翻几倍），上拉电流至少比总漏电大一个数量级，电平才稳。这是"上拉不能无限大"的第二条物理理由：100kΩ 只提供 33µA，几路漏电一叠加，高电平就沉到 $V_{IL}$ 附近——现场现象是"常温好好的，整机烘到 60℃ 就误触发"。

**上电与掉电的隐形路径**：上下拉都接电源，就多出一条电流路：本芯片已断电、上拉电源还在时，信号经引脚 ESD 二极管反灌进芯片，出现"没供电的芯片把总线拉死"的经典事故。对策：下拉改接真正的信号地；选带失效保护（fail-safe）输入的接口器件——RS-485 收发器常见此特性，总线空闲时输出状态确定；或在供电时序无法保证的地方加隔离开关。

**未用引脚**：没有第二用途的 GPIO，要么配成输出并固定电平，要么输入配上/下拉，唯独不能浮空——浮空输入反复翻转不仅误触发，还推高整机静态电流。模拟部分的未用引脚按手册推荐接地或接参考，别照搬数字引脚的习惯。

**浮空判据**：拿到"输入乱跳"的板子，先用示波器高阻探头看引脚：电平在中间徘徊、随手指靠近而移动，是浮空或上拉太弱；电平稳但逻辑错，才是真干扰或真信号。两种病的药方完全不同，判据先分清。

**内部上拉的真相**：MCU 的"内部上拉"不是电阻，是一只导通电阻很大的 PMOS。它的电流随电压非线性变化，30~50kΩ 是厂商给的一种折算值，实际伏安特性两端平缓、中间陡。影响有二：其一，用它做 I²C 上拉时，接近高电平处充电电流比同值电阻更弱，上升沿比计算值更长；其二，不同芯片的内部上拉离散大（同型号实测可差一倍），依赖它做时序敏感的设计等于把参数交给运气。外部电阻是确定性的，关键信号一律外接。

**一张上下拉复查清单**：出图前过五条。① 每个输入引脚都有确定的默认电平（上拉、下拉、或驱动器常驻）？② 每条开漏/三态线上拉是否按总线电容与模式算过区间，而不是照抄参考设计？③ 上下拉接的电源与信号域一致？掉电顺序走查一遍？④ 高温漏电复核过吗——上拉电流比漏电大十倍以上？⑤ 未用引脚全部处理？五条全过，浮空类故障基本与你无缘；这五条的排查成本都不到一根电阻钱，事后返工却常常要重新投板。

**休眠电流的一线两用**：电池设备里按键线常兼作唤醒源，上拉还是下拉直接决定休眠功耗。低有效按键（按下接地）配上拉，休眠时只要没人按键就不耗电；反过来配下拉，按键闭合期间持续耗流。唤醒沿的方向（按下产生下降沿还是上升沿）由此被硬件定死，写驱动前先看原理图——这是软硬件接口处最容易错位的格子。有可关断上拉的芯片（休眠时自动断开）是更好的解，但别想当然：查手册确认该引脚在休眠域还是常开域。

### 5.4 三态（Tri-State）与高阻态

<p align="center"><img src="assets/svg/tristate-bus.svg" width="720" alt="三态总线SVG动画：谁说话谁闭嘴"></p>

[动画演示 5.51](p5-00-part5.md#demo51)

第三种输出状态：上下管**都关断** → 高阻（Hi-Z），相当于与总线断开。配合片选信号，多个三态器件可共享并行总线，这就是内存总线的原理。三态总线必须有机制保证**同一时刻只有一个器件驱动**，否则回到推挽冲突的地狱。

**算一笔**（悬空总线能撑多久）：总线电容 $C=20pF$、上拉 $R=10k\Omega$ →
$\tau=RC=0.2\mu s$。也就是**全部驱动器高阻后，总线电平在 0.2µs 量级就开始被上拉/漏电改写**。
所以高速总线的「空档期」必须远短于这一时间常数。否则还没等下一个驱动器接管，电平就已经漂了。
这也解释了为什么 I²C 用**开漏+上拉**（永远不会直通），而并行总线靠**严格的片选时序**分时驱动。

**高阻不是断路**：高阻的"高"是相对驱动器几Ω到几十Ω的输出阻抗而言。数据手册给每个三态输出的漏电流 ±10µA 量级，N 个器件挂同一条总线就是 N 倍叠加——这给总线偏置电阻的上限又添一条约束。总线电容则始终在那里：最后一个驱动器松手后，线上保留它最后驱动的电平，按上面算出的时间常数缓慢漂移。此刻去读总线的器件，读到的是"上一次会话的残留"，而且不会收到任何报错——这类错误极难在软件层复现，只能靠时序设计消灭。

**Bus keeper：给总线配记忆**：并行总线的标准解法是总线保持器（bus keeper）：两只反相器首尾相接构成锁存环，以几 kΩ 的等效弱驱动把总线"含"在最后电平上，任何真正的驱动器都能轻松压过它。FPGA 的 IO 库普遍有此选项，不少处理器总线内置。它同时解决两件事：空档期电平不漂，上电初期没人驱动时的随机态。注意取向差别：上拉把总线定死在一侧，keeper 让总线停在任意一侧——低有效的复位线该用上拉，双向数据线该用 keeper。

**交接时序不是自觉，是设计出来的**：三态总线靠时序保证同一时刻只有一个驱动器：控制器先释放上一个驱动器，等它真正进入高阻（手册给禁用时间 $t_{DIS}$，典型 10~30ns），再使能下一个（使能时间 $t_{EN}$），两段在波形上就是一小段无驱动空档。使能窗口重叠哪怕 10ns，也是一次微型推挽对撞——单次不致命，反复发生烧 IO、抬功耗。排故办法：示波器开余辉（无限余辉/持久显示模式），看总线低电平上有没有叠出来的细毛刺，这是发现交接重叠最直接的手段。

**一个反直觉的实板案例**：8051 的 P0 口作外部总线时必须外接 10kΩ 上拉排阻，因为 P0 是开漏结构——很多人默认"所有 GPIO 天生推挽"，第一次画 P0 外扩 RAM 的板子就会地址全乱。看原理图先确认每条总线的输出结构，是硬规矩。

**上电期是天然的冲突高发期**：电源爬升阶段，各芯片尚未复位完成，三态使能引脚处于随机电平——多器件总线上电的最初几毫秒正是推挽对撞的高发窗口。规范化的做法是给每个使能脚配默认禁用的上/下拉（低有效使能配下拉），保证芯片没醒时它一定是闭嘴的；或者用电源监控/复位芯片在电压未稳期间强行拉住各使能脚。上电冲突不表现为持续大电流，而是一串微秒级尖峰，整机正常工作后无影无踪，却悄悄降低长期可靠性。

**判别真高阻的小实验**：怀疑某器件没进高阻（总线一直被顶在某电平），可以让它"释放"，再经 10kΩ 电阻把总线往相反方向推：真高阻时电平顺利翻转，没释放时电平顶在原地且推拉电阻发热。这个测试不用拆器件、不用断线，两分钟定案；比"焊下来测"快得多。反向也成立：让器件驱动，经 1kΩ 对地轻载，高电平掉到阈值以下说明驱动能力已损或串阻过大。

**双向总线收发器把三态用到了极致**：74LVC245 这类收发器是三态的现代主力形态——8 根线共享一套使能（OE），一根方向脚（DIR）决定 A→B 还是 B→A。它把"谁说话"压缩成两个引脚的电平管理，但规则也更尖锐：OE 与 DIR 同时切换的瞬间，收发器两侧短暂"接力"，若总线另一端还有驱动器没退场，冲突窗口就在这里产生。习惯做法是切换方向前先撤销 OE（先闭嘴、再转身、后开口），三条控制沿之间留出几十 ns 的间隔。排线两端各挂一只收发器时，这条纪律是保命的；多数事故就出在"方向脚和使能脚同时翻转"这一下。

三种输出结构到此都讲完了。把它们摆到一张桌上对照——谁负责拉高、谁负责拉低、上升沿谁说了算、能不能多点并联、各自怎么死——选型答案会自己浮出来：

### 5.5 故障案例

**表 5-2　数字电路故障案例**

| 故障 | 根因 | 教训 |
|---|---|---|
| I2C 总线全高、无应答 | 忘接上拉电阻（依赖 MCU 弱上拉勉强工作，挂多设备后崩溃） | 开漏必须配强上拉 |
| I2C 波形上升沿"爬坡"缓慢 | 上拉过大/总线电容过大 | 减小 Rp 或降速 |
| GPIO 烧坏 | 两个推挽输出直连冲突 | 共享线改开漏，或串联电阻限流 |
| 按键随机误触发 | 输入浮空未加上下拉 | 10kΩ 上拉/下拉 |
| 复位异常、上电乱码 | NRST 线多个推挽源互怼 | 复位线统一改开漏+上拉 |
| 电池设备待机电流 mA 级 | 开漏总线被拉低后上拉电阻持续耗电 | 休眠前释放总线/加大上拉 |

这张表的每行背后都有一个可操作的排查动作，逐条展开：

- **I2C 全高**：先看 SCL 有没有波形。SCL 有、SDA 全高，多半是从机未上电或地址错；两线全高，先查上拉是否真的焊上——万用表量对 VDD 的阻值，kΩ 量级是焊上了，MΩ 级是空焊。还有隐蔽情况：上拉接在受控电源轨上，主机先动、上拉后到，首批数据全丢，症状是"上电后第一笔通信必错"。
- **总线卡死在低**：一定有个器件在拉低。分段断开法逐个断开从机，断到谁恢复就是谁；或经 1kΩ 电阻注入一个 3.3V 窄脉冲试探：抬得起来是电平竞争，抬不起来是输出级顶死。软件侧先发 9 个时钟脉冲的解锁序列——这是 I²C 圈内通行的从机复位法，多数卡死是某从机的位计数错位，给它凑满一个字节就放手。
- **GPIO 烧坏**：输出管烧穿常表现为对 VDD 或对 GND 短路。二极管档量 IO 对电源、对地，读数明显低于同板其他引脚（硅结 0.5V 量级）即可判死刑。换芯片前先找原因：对接板是否推挽直连、串阻有没有省，否则换上去还会烧。
- **复位线互怼**：NRST 上挂了调试器、看门狗、手动按键三方输出时，统一改成"开漏+一个上拉"：谁都不许推高、只许拉低，系统才没有抢总线的第一优先级，任何一方都能无条件复位全板。
- **上升沿爬坡的量化**：示波器测出 $t_r$ 后反推 $C_b=t_r/(0.847R_p)$，与器件数×走线长的估算对照。实测明显偏大，依次查排线、查密集过孔、查探头地线太长引入的假爬坡（地线环路会把陡沿自己拖慢）。
- **待机电流超标**：逐路断开上拉电源，断到哪路电流下来就是哪条总线在漏。长期解法是休眠前让主机关总线（或上拉改接到可关断电源轨），同时确认从机侧没有靠上拉维持的状态。

这一节的方法论值得单说：输出级故障几乎都能用"两个电阻、一块万用表、一台示波器"定位。电阻做注入与轻载，万用表判短路，示波器看沿与毛刺。先分清"电平对不对、沿够不够快、有没有人抢线"三类问题，再动手换器件——输出级电路里"换芯片就好的"其实是少数，多数病灶在电阻、焊点和时序里。

### 5.6 动态分析：推挽输出级的一个周期（四拍拆解）

> 电路：±12V 双电源、互补射极跟随器（Q1 NPN 上、Q2 PNP 下）、负载 8Ω。跟着信号从负到正走一圈。

**拍 ① 正半周，NPN 上岗**：输入升过 $+V_{BE}$ → Q1 导通、Q2 截止，电流从 +12V 经 Q1 灌进负载。输出跟随输入**减去一个 $V_{BE}$**，这就是"跟随器"名字的由来。

**拍 ② 交越区，两只管子都够不着**：输入在 0V 附近 ±0.6V 之间时，两只管子的 $V_{BE}$ 都没到导通门限 → 都截止。输出出现一段**平肩**：听感"发干"，看波形"断腰"。这是乙类推挽的先天病。

**拍 ③ 负半周，PNP 上岗**：输入降过 $-V_{BE}$ → Q2 导通、Q1 截止，电流方向整个掉头（负载改从 −12V 抽电流）。**一只管子只管半周，合起来才是一个完整正弦。**

**拍 ④ 致命的第四拍，直通（Shoot-through）**：若 Q1、Q2 因偏置错、驱动时序错、或上电瞬间**同时导通**，+12V 就经 Q1→Q2→−12V **直接短路**。电流只受 $V_{BE}$ 倍增电路与走线电阻限制——**毫秒级烧管**。

**算一笔**：8Ω 负载、±12V，理想峰值 12V → $I_{pk}=1.5A$、$P_{out}=9W$、B 类效率上限 78.5%。但若发生直通，两管 $R_{CE(sat)}$ 之和按 1Ω 估：$I=24/1=\mathbf{24A}$，瞬时功耗 $24^2\times0.5=\mathbf{288W}$ —— 远超 TO-220 的 60W 极限，**几十毫秒就冒烟**。所以 AB 类的偏置必须"够小不交越、够稳不直通"，靠 $V_{BE}$ 倍增 + 热耦合把它钉死。

**B 类交越失真有多宽**：死区宽度由输入斜率决定。输入 $V_p\sin(\omega t)$ 的斜率峰值是 $\omega V_p$，输出平肩近似持续 $\Delta t\approx\dfrac{2V_{BE}}{\omega V_p}$。1V 峰、10kHz 时约 19µs——周期的五分之一里输出在"断线"，THD 轻松上百分之几，听感发毛。频率越高、摆幅越大，交越占比越小，所以大信号听感反而干净：交越失真要在小信号、低频时才最容易暴露，这也是测试规范里专门保留小信号 THD 项的原因。

**AB 类偏置怎么钉住**：$V_{BE}$ 倍增器是接在两管基极之间的"可调电池"：一只晶体管配两个电阻，$V_{bias}=V_{BE}(1+R_2/R_1)$，电阻比取 3 时给 2.4V，正好顶开上下管各一个结还留余量。关键不在"能调"，而在**热耦合**：倍增管贴在功率管散热器上，功率管发热，倍增管的 $V_{BE}$ 以约 −2mV/℃ 跟着下降，偏置自动收紧。没有热耦合的偏置是定时炸弹：功率管升温、阈值下降、静态电流增大、更热——热失控，几分钟烧管。静态电流量级是经验值：中小功率每管 20~50mA，让两管交接处轻微重叠导通，平肩消失。

**射极电阻 Re 的双重身份**：两管射极各串 0.22~0.47Ω。它既是直流负反馈——电流增大、Re 压降增大、净偏置被拉回，热稳定性成倍改善；也是限流——输出短路时电流被它顶住，给保护电路争取时间。代价是摆幅与效率：8Ω 负载串 0.33Ω 约吃掉 4% 摆幅，工程上普遍接受。

**管耗与散热的账**：B 类每管最大耗散不出现在满输出，而在输出幅度约 2/π 处，$P_{T(max)}\approx0.2P_{out}$。9W 输出即每管 1.8W。TO-220 不装散热器的热阻约 65℃/W，温升 117℃，25℃ 环境下结温已到 142℃——"60W 极限"是理想散热下的实验室数字。实际设计按结温倒推散热器：允许结温 105℃、环境 40℃，热阻须 ≤(105−40)/1.8≈36℃/W，一片小型散热器即可满足。这段算术是功放结构设计每天要做的。

**β 预算与复合管**：1.5A 峰值负载电流，功率管 β=50 时基极要灌 30mA——推动级必须给得出，否则输出在峰值处提前限幅，症状是"大信号才削顶"。达林顿接法把 β 平方、推动电流降到毫安级，代价是两个 $V_{BE}$ 串联（交越死区翻倍）与更深的饱和压降（效率下降）；Sziklai 复合（NPN+PNP 交叉接）保留单结压降又拿到高 β，是集成电路内部更偏爱的组合。分立设计选哪种，本质是在"推动级电流能力"与"死区宽度"之间做交易。

**死区的工程折中**：防直通的死区时间由驱动电路产生——分立方案用 RC 延迟（两只二极管+两颗电容让上升沿慢于下降沿），集成方案由驱动芯片内置死区锁死。功率 MOS 半桥的典型死区 0.2~1µs：太窄，MOS 关断拖尾未结束对管就开通，直通；太宽，正负半周之间出现无输出间隙，失真与"死区损耗"上升。死区不是越大越安全，它是一个双向误差，按开关拖尾实测值取 3~5 倍是常见做法。

**过流保护怎么接**：经典限流是在输出管射极串小电阻，压降达到一个 $V_{BE}$（约 0.6V）时保护管导通、把驱动电流分流掉。限流点即 $I_{lim}\approx0.6V/R_E$：0.33Ω 给约 1.8A，正好卡在 1.5A 负载峰值之上。设定要核对两件事：比正常峰值高 20% 以上（否则正常音乐信号反复触发保护，听感"喘气"）；在管子安全工作区（SOA）之内（短路瞬间管子既要扛限流值又要扛几乎全部电源电压，SOA 图上这是一条最苛刻的工况线）。

**换 MOSFET 做输出级会怎样**：MOS 的 $R_{DS(on)}$ 为正温度系数，多管并联自动均流，且没有热失控与二次击穿，保护压力小一截。代价在驱动侧：栅极是纯电容负载，需要专门的驱动电路灌栅电荷；开通后是电阻不是恒压降，轻载效率优于 BJT（无 $V_{CE(sat)}$ 死区税），重载时导通损耗看 $I^2R$ 反超。音频功放里两种技术路线长期并存，选型看供电电压、负载阻抗与驱动复杂度的组合，没有全胜的一方。

**实测判据**：交越失真这样看——小信号（峰峰值 1V 以下）、低频（1kHz），示波器放大过零点，B 类会有清晰平肩，AB 类应只剩轻微弯曲；一眼看不出时接失真仪或声卡做 THD。静态电流这样测——断开负载、输入接地，串万用表电流档量电源电流，减去前级消耗就是输出级静态电流，落在设计的 20~50mA/管即偏置正常。直通电流这样测——空载、无输入，用示波器电流探头看电源线，翻转测试信号时不应出现与翻转同步的电流尖峰；有尖峰说明死区不足或驱动时序错。

**负载从 8Ω 换成 4Ω 意味着什么**：扬声器阻抗减半，同摆幅下峰值电流翻倍（1.5A→3A），β 预算、射极电阻压降、线损全部跟着翻。管耗却不是简单翻倍：B 类最大管耗 $0.2P_{out}$，摆幅不变时输出功率翻倍、管耗也翻倍（每管 1.8W→3.6W），散热器要重算；若电源因此下垂、摆幅缩小，账要按实际电压重做。很多功放"8Ω 版"直接推 4Ω 会过流保护或烧管，根因都在这一串连锁。反过来，扬声器不是纯电阻——感性部分让电流相位滞后于电压，瞬时"电压高、电流也大"的工况落在 SOA 的右上角，比纯阻负载更苛刻，这是正弦测试发现不了、音乐信号却经常踩到的坑。

**输出级的地线与去耦是性能的一部分**：1.5A 峰值电流从电源经上管、负载回到电源地，这条大电流回路必须短而粗，且不能与小信号地共用一段走线——共用的那几毫米铜箔上，1.5A 电流产生毫伏级压降，直接串进前级输入，症状是"输出一大波形就抖"。去耦电容（470µF 电解并 100nF 陶瓷）要贴着输出级供电脚放：扬声器的瞬态电流取自这颗电容，不是远处的电源，否则引线电感让峰值供电塌陷，听感"软脚"。分立功放的布线检查顺序：先大电流回路，再散热，最后才是信号走向。
