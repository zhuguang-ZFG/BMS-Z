# 共学：协议五天

> **本篇你会学到**　帧头、长度、CRC 怎么把一串字节切成帧，以及坏 CRC 后面如何把好帧救回来。
> **预计用时**　5 天，每天大约 45–90 分钟。
> **前置**　Python 3.10+。不需要串口盒，也不要为了这一期去拆商用电池包。

⚠️ 这里的帧是教学抽象：`AA 55 | addr | cmd | len | data | crc8`。它不是 JK、JBD 或某一家的协议。电压数字是字段换算，不是万用表读数。真机共地会烧口，见 [阶段 5](../stages/stage-5-通信与集成.md)。

## 第 1 天：字节流没有格子

**读**　[阶段 5 §5.2](../stages/stage-5-通信与集成.md#52-uart商用-bms-的方言普通话-应用)。UART 只是一根字节的管子，帧界是协议自己画的。

**看**　[UART 字节状态机](../circuits/assets/uart-byte-machine.svg)。不看动画：找帧头、收长度、收数据、对 CRC，失败就计数并重新同步。

**跑**

```bash
cd code/protocol && python3 -m pytest tests/ -q
```

2026-10-06 本仓库输出末行：`31 passed in 0.05s`（秒数可以不同，`31 passed` 不该变）。

**交**　贴 `31 passed` 那一行。用一句话写：帧头在这套教学帧里是哪两个字节。

**口诀**　没有帧头，字节只是一队人，不知道谁和谁一伙。

**今天你解锁了**　解析器测试在你机器上是绿的。你还没「逆向一块板」，你已经会跑裁判。

## 第 2 天：CRC 先用已知帧验手

**读**　[阶段 5 §5.6](../stages/stage-5-通信与集成.md#56-协议逆向方法论当一回协议侦探-分析) 里关于 CRC 的那几条。多项式、初始值、反射、异或，错一个，结果就整段不对，而且你没法从错误结果倒推出是哪一项。

**看**　仍看 [UART 状态机](../circuits/assets/uart-byte-machine.svg) 里「对 CRC」那一拍。仓库没有单独的 CRC 动画，不要另外找一张图凑数。

**跑**

```bash
cd code/protocol && python3 -m pytest tests/test_crc.py -q
```

本仓库：`6 passed`。

**交**　写一句：为什么要先拿已知帧验证 CRC 程序，再去碰未知协议。对照教程即可，不要发明一种新多项式。

**口诀**　已知帧都算不对，就别去碰未知帧。

**今天你解锁了**　你知道 CRC 不是「加个校验和就行」，它有一串必须对上的旋钮。

## 第 3 天：坏帧要计数

**读**　还是 [§5.6](../stages/stage-5-通信与集成.md#56-协议逆向方法论当一回协议侦探-分析)，看五条军规里「坏帧丢弃并计数」。静默丢掉的坏帧，现场无法判断是线坏了还是程序坏了。

**看**　[UART 状态机](../circuits/assets/uart-byte-machine.svg)。失败的那一拍要留下计数。

**跑**

```bash
cd code/protocol && python3 -m pytest tests/test_frames.py -q
```

本仓库：`25 passed`。和第 1 天的 31 加在一起对得上：CRC 6 项 + 帧 25 项。

**交**　从 `code/protocol/frames.py` 的计数器名字里挑两个（例如 `frames_bad_crc`、`resyncs`），各用一句话写它在数什么。不要改文件。

**口诀**　坏帧可以丢，不能不记账。

**今天你解锁了**　你能指出「没打印」和「没发生」不是一回事：计数器就是账。

## 第 4 天：垃圾前面也能同步

**读**　[code/README 的 protocol 走读](../../code/README.md#protocol五条军规逐条落对应阶段-5-应用)。长度或 CRC 失败之后，只丢掉当前这个坏帧头，剩下的字节还要再扫。

**看**　[UART 状态机](../circuits/assets/uart-byte-machine.svg)，想象帧头前面还有两个废字节。

**跑**（教学帧，不是电芯电压）：

```bash
cd code/protocol && python3 -c "from frames import Frame, parse_stream; raw=Frame(1,3,bytes([0x0c,0x1a])).to_bytes(); print(raw.hex()); frames, parser = parse_stream(b'\x00\x11'+raw); print(parser.frames_ok, parser.resyncs, frames[0].cell_voltage_mv(0))"
```

本仓库三行：

```text
aa550103020c1a34
1 2 3098
```

`3098` 是数据 `0x0C1A` 按「大端 × 1 mV」换出来的教学值。前面的 `00 11` 是故意塞的垃圾。`frames_ok` 是 1，`resyncs` 是 2。

**交**　贴这三行，并写：如果解析器在垃圾处放弃，好帧还会在吗。

**口诀**　帧头可以迟到。迟到了就从头再找，不要把后面的好帧一起扔了。

**今天你解锁了**　你亲手看过「垃圾 + 好帧」仍能解出 1 帧。

## 第 5 天：从坏信封里救出好帧

**读**　[阶段 5 §5.6](../stages/stage-5-通信与集成.md#56-协议逆向方法论当一回协议侦探-分析) 收束。再看擂台第二题的规则：[擂台](../擂台.md)。

**看**　[UART 状态机](../circuits/assets/uart-byte-machine.svg)。这一题的差别是：好帧藏在一个 CRC 错误的外层载荷里面。整段跳过的解析器会跨过去；逐字节重扫的解析器还能看见。

**跑**（仓库根）：

```bash
python3 challenges/02-frames/score.py
```

2026-10-06 仿真结果，种子 `20261006`，194 字节里埋了 10 个好帧：

| 解析器 | 救回 | 误收 | 得分 |
|---|---:|---:|---:|
| 坏 CRC 整段跳过 | 4 | 0 | **4（基线）** |
| 仓库解析器 | 10 | 0 | 10（参考，不是基线） |

得分 = 救回 − 误收。要胜过基线，得分就要 **大于 4**。把仓库解析器原样再跑一遍，得到 10，请注明「复现仓库解析器」。

**交**　贴两行得分，并写你打算改弱解析器的哪一条（整段跳过，还是失败后重扫）。

**口诀**　CRC 错了，只说明这一帧头不可信，不说明后面没有好帧。

**今天你解锁了**　你能把「丢掉坏帧」和「把坏帧后面的好帧一起丢掉」区分开。
