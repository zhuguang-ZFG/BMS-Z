# 第 22 章 开源架构：读结构，也读取舍

::: story 现场
你把 foxBMS 2 的 CAN 驱动搬进自己的应用层，改了十处适配，跑通了。三个月后 upstream 更新，你 merge 了三天，还丢了两个补丁：一个去抖计数、一个故障快照。（教学合成场景）

问题不在 git，在**分层**。你搬走的是“实现”，不是“边界”。补丁丢在应用层的褶皱里，upstream 永远不知道你存在过。
:::

## 22.1 读大项目学结构，读小项目学取舍

一边是 foxBMS 2：模块化、带文档、OSHWA 认证，像一套工业级骨架。另一边是 SmartBMS 的四件套：ATtiny 采单体、Arduino Mega 主控、继电器 Limiter、手机 App 看数据，成本压进 DIY 范围。

它们解同一道题，站在不同的台阶上。**读大项目学结构，读小项目学取舍。**

关键事实（以仓库与附录 B 为准）：

- foxBMS 2 软件 BSD-3-Clause，硬件与文档 CC BY 4.0，OSHWA 认证 UID DE000128；
- 目标覆盖锂离子、固态、锂硫、钠离子、超级电容、液流与燃料电池；
- 文档入口在 Fraunhofer 站点，先读总览与安全章节，不要从 main.c 顺序读到尾。

## 22.2 foxBMS 2：三层是怎么切的

foxBMS 2 把固件切成 application、engine、driver+os 三层。这不是目录洁癖，每一刀都有理由：

| 层 | 装什么 | 切出来的好处 |
|---|---|---|
| application | 应用任务、SOA 策略、接触器请求 | 产品差异留在顶层，换项目不重写 |
| engine | 状态机、保护判定、去抖、故障快照 | 安全相关逻辑沉底，可审、可测 |
| driver + os | AFE / CAN / 接触器驱动、RTOS | 硬件可替换，driver 可单测 |

三刀对应三个老问题。**可测试性**：driver 藏在接口后面，mock 掉寄存器就能单测。**安全分解**：engine 只依赖配置与输入，评审不用翻驱动细节。**硬件可替换**：换一颗 AFE，改动停在 driver 层。

电池数从 8 串变 16 串走哪条路？走配置矩阵：串数、阈值、映射尽量是数据，不是代码。加一串要重编译，说明配置漏进了实现层。

## 22.3 小项目的取舍课

**SmartBMS 四件套**：Cell Module 采电压温度带均衡，Control Unit 汇总并控继电器，Limiter 限流，App 蓝牙看数。保护很朴素：过压、欠压、均衡时把充电限到 1 A。完整，但紧耦合：模块间是私有契约，换一件动全身。可借鉴的是划分与开源硬件认证；不能直接量产——缺冗余采样、绝缘监测、接触器粘连检测。

**diyBMS 节点式**：中央控制器加每串一个 ATTINY85 节点，隔离通信，各管采样与被动均衡。它倒在两处：功能蔓延——每代加特性，固件越来越不敢动；单点维护——关键路径压在一个人身上。README 已明言被 v4 取代。读它的价值，是理解**为什么迭代**。

**esphome-jk-bms**：只做接入层。经 UART-TTL 或 BLE 读 JK-BMS，暴露成传感器接入 Home Assistant。保护留在 BMS 本体，云端自动化不进实时闭环。这是边界感——接进来的是数据，不是决策权（对外总线的边界见第 19 章）。

## 22.4 许可证即架构

许可证决定代码能不能带进产品，是和引脚定义同级的架构决策，三类影响要分清：

- **BSD / MIT**：可闭源商用，保留版权声明即可。foxBMS 2 软件走 BSD-3-Clause，商用固件可以借用。
- **GPL**：衍生作品须同一许可证开源。商用闭源固件链了 GPL 驱动，要么开源，要么绕行重写。
- **CC 系**：偏硬件与文档。CC BY 要求署名，CC BY-SA 还要求改版以同许可分享；底线是署名。

diyBMS 与 esphome-jk-bms 的许可证以仓库为准，动手前先读 LICENSE 文件。**许可证不等于认证**，更不等于免责（认证见第 25 章）。

## 22.5 四步读法

读大项目别从 main 顺序啃，按四步走：

1. 入口：任务怎么起、数据流怎么转；
2. 配置：阈值、串数、模块开关在哪；
3. 状态机：保护与接触器逻辑落在哪层；
4. 测试：哪个用例覆盖了这个驱动。

带着问题读：它的去抖在第几层？故障快照存了什么？接触器粘连判据在哪？（去抖与回差见第 7 章，失效判据与二次保护见第 8 章。）能答上来，结构才算读懂。

## 22.6 把开源当供应商

用开源组件，按供应商管理，不做一次性搬运：

- **版本钉死**：锁 commit 或锁 release，不追 main 分支漂移；
- **补丁回流**：本地改动做成可回流的补丁，否则每次升级都重演 merge 三天；
- **SBOM**：列出组件、版本、许可证，随产品交付，漏洞来了知道波及谁。

回到开头的现场：丢的两个补丁，一个本该回流，一个本该留在 engine 层。**开源降低起步成本，不降低认证成本**——危害分析、需求追溯、验证证据一样不少。

::: principle 一句话
**foxBMS 教你系统应该长什么样，DIY 项目教你哪些地方可以省、省了会怎样。**
:::

::: trap 坑
把 DIY 项目的阈值直接搬上生产。电芯、结构、散热、认证假设都不同，阈值是示例不是规格；许可证同理，读一遍 LICENSE 再谈借用。
:::

::: lab 动手
用四步读法在 foxBMS 2 里定位 CAN 驱动的实际位置：入口、配置、状态机引用、测试四栏各写一行链接。然后回答：换掉这颗收发器，要动几层？
:::

## 练习

1. 给 5 个功能归层：均衡电阻驱动、SOA 功率限制、去抖计数、接触器粘连检测、CAN 报文收发。各写一句归层理由。
2. 商用闭源产品分别用了 GPL 驱动和 BSD 驱动，各有什么后果？各给一条合规路与一条规避路。
3. 用四步读法在 foxBMS 2 仓库找一个驱动的实际位置，写出四栏证据与链接（可验证）。
