# 开源 BMS 原理图与 PCB 剖析

> **方法**　不看一张漂亮渲染图就下结论。每个案例固定到提交 SHA，从“电流怎么走、信号怎么进、故障怎么断、热往哪散、证据在哪里”五层拆。
>
> **边界**　开源、打过样、测试通过都不等于符合你的车型与法规。本文用于学习和设计审查，不提供可直接量产的阈值或投板许可。

案例清单由 `curriculum/hardware_cases.json` 维护；运行 `python tools/check_hardware_cases.py` 检查车辆路线、固定提交和许可证字段。

## 案例 1：LibreSolar BMS C1——高功率集中式板怎样分区

**固定版本**　`LibreSolar/bms-c1@0ca09706f49906bdc73f6ccf99635de349d47474`，PCB 标题栏为 **v0.4.2 / 2026-03-29**。硬件采用 CERN-OHL-W-2.0，文档采用 CC BY-SA 4.0。

项目 README 将它描述为 3–16 串、按 MOSFET 与热沉配置约 70–100 A，使用 BQ76952、ESP32-C3、集成高边 MOS 和电流传感，应用包括离网储能与轻型电动车。开发状态是 eval：已测试原型，但仍可能有问题。

### 先把它想成三条路

```text
测量路：电芯抽头 → 20 Ω / 220 nF 输入滤波 → BQ76952 → I²C / ALERT → ESP32-C3

大电流路：BAT+ / CHG+ / PACK+ → 充放电高边 MOS 组 → 外部负载与充电器
          BAT- / PACK- → 300 µΩ Kelvin 分流器 → 电流测量

通信路：ESP32-C3 → CAN 或 RS-485（复用连接器与 MCU 引脚）/ USB / UART / BLE / Wi-Fi
```

这三条路在原理图里分成 `bq76952.kicad_sch`、`power-part.kicad_sch`、`esp32-c3.kicad_sch` 与 `power_supply.kicad_sch`，顶层再把 BAT、PACK、CHG、SHUNT、CHG／DSG／PDSG 和通信网连接起来。分层的价值不是“文件好看”，而是让审查者能分别追测量误差、关断路径与通信故障。

### 1. 采样链：先滤，再送进 AFE

BOM 中 R1–R17 为 **20 Ω**，C1–C16 及相关输入电容为 **220 nF**，对应多串电芯输入的限流与滤波。学习重点不是照抄数值，而是检查：

1. 每根抽头的 RC 是否对称；
2. 开线检测与输入滤波是否互相打架；
3. 采样线回流是否远离 MOS 栅极与大电流铜皮；
4. 100 V 级器件与实际最高故障电压是否匹配。

BQ76952 同时输出 `CHG`、`DSG`、`PDSG`、`FUSE` 与 `ALERT`。这说明 AFE 不只是 ADC：它还承担硬件保护、功率开关驱动和主控告警，是“MCU 死机时谁还能关闸”的核心审查点。

### 2. 功率路径：八颗 MOS、一个分流器、一条预放电支路

BOM 列出 Q2–Q9 共 **8 颗 IPT012N08N5** 功率 MOS；R45 是 **300 µΩ、Kelvin 引出**的分流器；R63 是 **40 Ω** 预放电电阻。顶层把 `BAT+`、`CHG+`、`PACK+` 分成不同节点，测试报告也分别测量三点，证明充电路径与放电路径可以独立关断。

预放电支路的用途可以想成“先开一条窄门”：面对 1200 µF 母线电容，先通过 40 Ω 电阻把总线抬高，再打开主 MOS，避免直接把电容当短路。它与电动汽车的接触器预充原理相同，但器件、能量和故障安全等级完全不同。

### 3. PCB：四层不是为了显得高级

PCB 源文件声明四个铜层，外层与内层铜厚均写为 **0.07 mm**。`In1.Cu`、`In2.Cu` 被标为 power 层；板上使用 M5 功率端子，并在背面安装热沉。

看板时按这条顺序：

- 先找 BAT／PACK／CHG 端子与大电流铜区；
- 再找八颗 MOS 到背面热沉的热路径；
- 再找 300 µΩ 分流器的 Kelvin 采样线，确认它没有从大电流焊盘随便取点；
- 最后看电芯抽头、AFE 与 ESP32 是否被大电流回路包围。

如果一上来只看“走线粗不粗”，就会漏掉真正决定测量精度的 Kelvin 点和模拟回流。

### 4. 通信：接口很多，不代表可以同时随便用

ESP32-C3 子图包含 CAN 收发器 SN65HVD230、RS-485 收发器 SN65HVD75、USB 与无线通信。原理图文字明确说明 CAN 与 RS-485 **复用 MCU 引脚和总线，一种应用只能选其一**。这类 DNP／复用关系必须回到 BOM 和装配变体审查，不能只看接口名单。

### 5. 测试证据：版本要对得上

仓库的 `testing/v0.3` 报告验证了预放电、MOS 独立开关、均衡、OV／UV、充放过流、过温与热性能。69 A、约 18 °C 环境、60 分钟测试中，报告称分流器达到 **45.6 °C**，是最热部件；它再按 I² 比例估算 100 A 温升。

但要特别注意：测试对象是 **v0.3**，当前固定 PCB 是 **v0.4.2**。这份报告可以证明测试方法和旧版本结果，不能不做差异审查就替 v0.4.2 签字。版本错位本身就是工程剖析必须指出的证据缺口。

### 6. 这块板不能直接教你的

- 它不是 GB 17761 电动自行车认证样板；
- 它不是电动摩托车公告产品；
- 它也不是带 HVIL、IMD 和主从 CMU 的电动汽车牵引 BMS；
- 70–100 A 依赖 MOSFET、热沉、环境与装配，不是只看八颗 MOS 就成立；
- CAN、RS-485、Wi-Fi、BLE 接口存在，不等于它们都能进入安全控制链。

## 后续剖析顺序

1. **电动自行车低压拓扑**：LibreSolar BMS 8S50 IC，重点看高边 MOS、功耗和紧凑布局，同时解释它为什么不能直接代表 48 V 产品。
2. **电动汽车主从式**：ENNOID-BMS，重点看 Master-HV／Master-LV、LTC6811/12/13 从板、isoSPI、接触器与预充。
3. **电动汽车研发平台**：foxBMS 2，重点看硬件版本号、Master／Interface／Slave 的发布边界和测试体系。
4. **社区分布式对照**：diyBMSv4，重点看单体模块、控制器、均衡热与非商业许可证边界。
