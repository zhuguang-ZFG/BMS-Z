# protocol：帧解析与 CRC [应用]

主层级是 **应用**：把「找帧头 → 收长度 → 验 CRC → 坏帧计数」做成能跑的状态机。拿已知帧对照未知帧，是 [分析]，在走读的军规 4、5 和阶段 5 §5.6。

> **先读/后读**：先 `python3 -m pytest tests/ -q`（应用），再读 [逐行走读](../README.md#protocol五条军规逐条落对应阶段-5-应用)。帧格式是教学抽象，不是某家商用协议。

> **原理**　UART 字节流没有天然帧界。状态机用帧头、长度和 CRC 自己把边界找回来；坏帧必须计数，不能静默吞掉，否则现场无法判断是线坏了还是解析坏了。
> **证据**　可核验实验：`code/protocol/tests/`（CI 会跑）。真实帧格式对照 [esphome-jk-bms](https://github.com/syssi/esphome-jk-bms)（英文，可选）。
> **延伸阅读**　[阶段 5 §5.6 协议逆向](../../docs/stages/stage-5-通信与集成.md)（锚点见该页目录里的「协议逆向」）。

不要用这份解析器驱动真电池的保护。共地风险见阶段 5。
