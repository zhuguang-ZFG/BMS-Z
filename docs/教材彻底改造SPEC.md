## 0. 一句话

陌生读者能走完这条闭环，并能合上页面复述因果：

> 现场问题 → 机制 → 手算 → 边界 → 一次验证

彻底改造不是把内容削薄。主线负责第一次理解，选读负责深化，完整页负责查阅与旧锚点。公式、实验数值、条件、安全边界、来源与授权不得因改写丢失。

**本版额外硬要求**：原理必须「讲透且简单」——一眼能抓住因果；动画与实物图必须够密，让读者先看见再算，而不是先背定义。

**本版核心加码**：每个知识点必须沿「识名 → 讲清 → 手算/跑通 → 会判 → 能交付」五级梯子改造（见 §9）；禁止只停在定义或只挂一个 Bloom 标签。

## 1. 产品闭环与分层

### 1.1 媒介职责

| 媒介 | 职责 | 真源 / 流水线 |
|---|---|---|
| 阶段教程 | 第一次通关主线：短、可跟、有完成标志 | `docs/stages/` |
| 伴读书 | 深读与查阅：主线 / 深挖 / 验证分层 | `bms-book/` |
| SVG 动画 | 一个因果变化的可暂停证据；静态帧仍可读 | 现有 `docs/circuits/` 与构建门；按 §3.5 加密度 |
| 实物照片 | 器件、接线、台架「长什么样」的第一证据 | 本库实拍或已授权素材；按 §3.6 补洞 |
| 视频 | 总课建全景；微课/短片按 §4 矩阵出片 | 总课：`tools/video/`；新片：§4 |
| 代码 | PC 可复算证据；不断言「已上板」 | `code/soc` · `protocol` · `firmware` |
| 静态插图 / 封面 / 信息图 | 一图一问的视觉证据 | **handraw-style 为唯一真源**（§3） |

### 1.2 内容三层

| 层 | 回答 | 典型长度 | 主要载体 |
|---|---|---:|---|
| 先懂 | 为什么发生 | 2–5 分钟 | 微视频、单张动画、手绘机制图、实物特写 |
| 会算 | 数字怎么得到 | 10–30 分钟 | 教程、书中算例、PC demo |
| 会做 | 怎样验证与交付 | 30–120 分钟 | 实验、挑战、共学、工程清单 |

### 1.3 阅读角色（每个阶段 / 长章只承担一种主角色）

| 层级 | 读者目的 | 建议规模 | 必须保留 |
|---|---|---:|---|
| 主线 | 第一次建立因果链 | 单页约 0.8–1.5 万字符；超过即评估再拆 | 最小公式、贯穿算例、关键安全、一次取回、**足够动画/实物** |
| 选读 | 旁支、推导、工程深化 | 尽量不超过 1.5 万字符 | 完整条件、推导、反例、来源 |
| 完整查阅 | 搜索、旧锚点、系统复习 | 不设硬上限 | 全部原始信息与稳定锚点 |
| 速查 | 工作时找参数或步骤 | 一到三屏 | 单位、适用对象、版本、回链 |

不算完成分层：顶部写「后面可跳过」却仍一次加载整页；只拆文件不写阅读顺序；选读重复主线整段解释。

## 2. 单元契约、原理简化与去 AI 味

### 2.1 九项契约

可独立阅读的单元必须具备下列九项；某项不适用时要写明原因，不能默默缺失。

1. **唯一目标**——读完只承诺一个主要能力。
2. **现场问题**——先出现现象、故障或异常数字，不从定义开场。
3. **对象身份**——首次缩写与变量用普通话说明它是什么；能指物则配实物图或特写。
4. **最小机制**——只引入回答当前问题所需的结构与公式；先动画/图景，再符号。
5. **贯穿算例**——同一组输入走到结论，中途不换数字。
6. **可见证据**——实物、波形、日志、图解或实验结果至少一种；主线优先「实物 + 动画」成对。
7. **反例边界**——指出一个合理但证据不足的判断为什么失败。
8. **取回任务**——不看答案也要判断、手算、画图或运行一次。
9. **下一步**——明确去下一主线、选读还是实验，不用资源堆收尾。

制作前先交「讲透卡」（见教学设计规范）：唯一目标、生活钩子、贯穿算例、常见误解、取回交付。核心问题五项写在 `curriculum/concepts.json`。

每个 KP 的主线单元除满足上述九项外，还必须把 §9 五级梯子覆盖到该 KP 约定的 `bloom_ceiling`（主线至少到「手算/跑通」）。

### 2.2 原理「讲透但简单」细则（本版加码）

目标：读者第一次读完，能用自己的话讲清「谁变了、为什么变、结果是什么」，而不是背术语表。

**必须遵守**

1. **先看见，再命名**：现场问题或实物/动画出现之后，才给出术语；禁止开篇定义墙。
2. **一问一机制**：一个小节只推进一条因果；第二条因果另起小节或另开动画。
3. **口语身份 + 工程身份**：第一次出现的量，先说「它管什么」，再说符号与单位。例：内阻 → 「电池自己的拦路虎，电流一过就吃掉一块电压」。
4. **类比必须标边界**：类比只负责入门；下一句写「它在哪儿会失效」。
5. **公式三问**：左边是什么结果？右边每一项是哪种物理作用？哪些能量测、哪些只能估？
6. **同一组数字走完全程**：钩子里的数 = 算例里的数 = 动画标注的数 = 取回题的数。
7. **数量级常识检查**：算出结果后写一句「这个量级合不合理」。
8. **画面优先于形容词**：少写「非常重要」「复杂精妙」；多给一帧能停住的图。

**简单化清单（改写时逐条勾）**

- [ ] 删掉对当前问题无用的旁支术语，或移入选读。
- [ ] 长句拆成「原因句 + 结果句」；超过两层因果就配图。
- [ ] 标题写成判断或问题（「带载为什么掉压」），不写「内阻概述」。
- [ ] 段首不复读标题；段尾不空喊「综上可见」。
- [ ] 读者合上页后，能用 ≤3 句复述机制（写在讲透卡的取回交付里）。

**生动形象，但不油腻**

- 允许生活钩子、拟人化一句、口诀一句；每单元最多各一次，且必须服务机制。
- 禁止堆梗、鸡汤、夸张语气和「赋能式」口号。
- 动画里的运动必须是证据（电流走向、状态翻转、阈值越过），不是装饰闪烁。

### 2.3 必须做到（文字）

- 一段只推进一个判断；因果超过两层就拆句或配图。
- 结论第一次完整解释；后文只加新条件或回链，不换近义词重讲。
- 公式前说结果是什么、输入从哪来；公式后写数量级和能/不能支持的结论。
- 数值写清对象、工况、版本和来源；教学数字标「示意」。
- 安全动作区分命令、反馈、故障判定和最终处置。
- 主语具体：写「AFE 采样」「BMU 下令」「接触器反馈」，少写「系统进行处理」。

### 2.4 应删改

- 「众所周知、显而易见、值得注意的是、综上所述」等无信息转场；
- 「从……到……」「不仅……更……」连续成簇的模板句；
- 没有新增判断却重复的「原理—证据—延伸」空框；
- 三个近义词并排当强调；
- 先宣布「下面将详细介绍」再把标题复读一遍；
- 无来源的「通常最高等级」「行业普遍认为」「绝对安全」。

去 AI 味采用 **语义保全**：只改成簇空泛铺垫、口号与复读；不做关键词清洗。单个合理的对比句或三项列表可以保留。过度清洗会删掉安全边界。

### 2.5 不得为变短而删除

公式与单位、实验输入输出与误差、适用范围与失效条件、安全警告与法规版本、图片作者许可证与原始链接、可复现命令、**为理解所必需的动画与实物图**。

### 2.6 主线页顺序

1. 读完能做什么  
2. 一个现场问题  
3. 实物或现象（优先照片）  
4. 最小机制图或动画（一问一动）  
5. 一组贯穿数字  
6. 正常到异常的连续过程（连续帧或动画）  
7. 一个反例和适用边界  
8. 三题以内的取回  
9. 下一篇主线与选读入口  

选读页开头写清「什么时候需要读」。完整查阅页开头指回短主线，并说明保留旧锚点。

## 3. 视觉真源、动画密度与实物图

### 3.1 真源边界

- **静态插图、封面、信息图、社媒结论卡**的画风与构图提示词，以 [yang0/handraw-style](https://github.com/yang0/handraw-style)（`handdraw-style-prompter` 及文章/封面相关子 skill）为唯一真源。
- 默认先出双语提示词；只有明确要求「生成 / 出图 / 预览」才调用生图。
- 风格编号与主题色未指定时，按主题语义动态推荐一组，禁止维护「关键词→固定编号」死表。
- 本机生图通道不可用时：交付同画风矢量/可入库替代物，双语 prompt 存档（如 `bms-book/ILLUSTRATION-PROMPTS.md`），通道恢复后按存档重出 raster 替换；不得编造「已实拍」身份。
- **机制动画的真源是逐帧手绘序列**（`docs/circuits/handraw/storyboard/<slug>/frame-NN.svg` → WebP 帧 → `exports/<slug>.webp`），由 `tools/export_handraw_animation.py` 导出为可暂停动画。旧几何 SMIL 流水线**不再新增**，已迁移条目归档到 `docs/circuits/assets/archive/`。仍成立的两条：静态图不得冒充可暂停动画（必须有 ≥3 帧与 `loop=0` 导出）；动画也不得充当唯一解释（静态模式与打印版须可读）。

### 3.2 五类图

| 类型 | 回答 | 最低要求 |
|---|---|---|
| 实物照片 | 器件、接线、台架长什么样 | 标观察对象；作者、来源、许可证齐全；非本库拍摄不得称「实拍」 |
| 手绘机制图 | 电流、热、数据或状态怎样传递 | 一图一问；箭头有物理含义；颜色符号全库一致 |
| 连续图 | 前后顺序与中间状态 | 3–6 帧；每帧只新增一个变化 |
| 动图（SVG） | 哪个量随时间或操作变化 | 第一帧可读；末帧是完整答案；正文有观察任务与静态解释 |
| 波形 / 数据图 | 证据在哪里 | 轴、单位、工况、采样条件、关键点齐全；示意不得冒充实测 |

### 3.3 组合与审查间距

- 器件识别：照片 + 手绘剖面或等效电路。  
- 动作时序：接线图 + 连续帧/动画 + 关键波形。  
- 算法：输入 → 中间状态 → 输出误差（可用动画逐步生长）。  
- 故障：正常/异常对照 + 冻结帧或日志 + 处置时间线。  
- 连续三个抽象段落后，必须出现图、表、算例、问题或实验之一。  
- 每 **400–800 字**（本版收紧）检查一次是否需要视觉证据；主线遇到新器件或新动作时，不得连续两段纯文字无图。

### 3.4 禁区

微缩器件摆拍、装饰电池、发光芯片等科技感填空；示意图标成示波器/台架/产品内部；图中塞长正文；为凑数重复同一结论；插画内默认不写数字（含数字必须逐字溯源正文）；图注回指正文。

传播层（一页纸、3:4 卡、讲师版）产物落可入库、可 CI 验证的路径（当前实践：`docs/public/spread/`）；`media/` 被 gitignore，不得作为可审查交付落点。

### 3.5 动画演示加码（详细条款）

**目标**：157 张基线之上，主线「先懂」层每个关键因果至少有一张可暂停动画或等价连续帧；缺动画的主线页不得标「改造完成」。

**一张动画的完成定义**

1. 标题直接写问题或结论（「预充时接触器谁先谁后」），不写「示意图」。  
2. 只解释一个因果变化；第二个变化另开一张。  
3. 第一帧读者不按播放也能读懂初始状态。  
4. 运动表达证据：电流路径、开关状态、数值越过阈值、时序先后。  
5. 正文含：观察任务一句 + 暂停帧问题一句 + 不播放也能懂的静态解释。  
6. 关键数字与贯穿算例一致，并在图注标明示意或实测。  
7. 通过现有 SVG 风格与数量对账门；新增动画同步进动画索引表。

**优先补动画的主题（W3/W4）**

1. 带载掉压与内阻  
2. OCV 静置与回弹  
3. 过充/过放保护动作链（采样→确认→命令→反馈）  
4. 预充与接触器时序  
5. 均衡电流路径  
6. SOC 漂移与校正瞬间  
7. SOP「取最短板」  
8. 热与内阻随温度变化  
9. HVIL / 绝缘下降示意（教学级）  
10. 通信帧：CRC 错与重同步  

**密度规则**

- 阶段主线每一「现场问题」至少 1 张动画或 3–6 帧连续图。  
- 书稿每一章主线至少覆盖「开场钩子动画/连续图 + 章内最难机制动画」两处；已有可复用则复用并写清图号。  
- 视频微课引用的机制，必须能在站内找到对应可暂停动画或静态连续帧，避免「只能在视频里看见」。

**不做**

- 不为了数量把同一结论拆成多张闪法不同的装饰动画。  
- 不把 handraw 静态插画改成假 SMIL 冒充动画。  
- 不删旧动画的静态可读性来换「更炫」。

### 3.6 实物图片加码（详细条款）

**目标**：读者能指认真实器件与台架，而不是只在抽象框里学习。

**一张实物图的完成定义**

1. 画面主体就是正文要认的对象；图注写清「看哪里」。  
2. 作者、来源、许可证、拍摄或转载日期齐全；身份不明不入库。  
3. 非本库拍摄不得写「实拍」；合成或手绘必须写「示意，非实拍」。  
4. 图注写明照片里**没有什么**（避免读者脑补成完整系统）。  
5. 与机制图成对出现时，先照片认物，再机制讲路径。

**优先补实物清单（缺一张就记决策行，不许拿错图顶替）**

| 优先级 | 对象 | 用途 |
|---|---|---|
| P0 | 单节保护板正反面 | 阶段 2 认板 |
| P0 | AFE/BMU 板全貌与采样接口近景 | 阶段 3 |
| P0 | 分流器或霍尔、NTC 安装位置 | 采样与热 |
| P0 | 主接触器 + 预充电阻同框 | 预充时序 |
| P1 | 熔断器、继电器、HV 连接器 | 高压安全 |
| P1 | 均衡电阻/均衡 MOS 区域 | 均衡路径 |
| P1 | 简易实验台/电子负载与被测板同框 | 实测验收 |
| P2 | HIL 或台架全貌（有授权） | 进阶验证 |
| P2 | 线束、压接、绝缘失效反例（安全许可下） | 故障教学 |

**密度规则**

- 主线第一次引入硬件对象：必须有实物图或「暂缺 + 决策行」；不得只用三维装饰图代替。  
- 连续介绍 ≥2 个硬件对象时，至少 1 张实物图打断纯文字。  
- 书稿与教程共用同一授权照片时，统一资产路径，避免各拷一份导致来源漂移。

**安全与合规**

- 涉及拆壳、带电近景、高压柜的照片：先过安全与授权，再入库。  
- 找不到合规图时：宁可留洞并写「待补」，也不许错标身份。

### 3.7 视觉完成门（改造完成检查表）

一个主线单元标「视觉完成」必须同时满足：

- [ ] 现场问题对应的动画或连续帧存在且可暂停理解  
- [ ] 首次硬件对象有实物图或已登记「待补」决策行  
- [ ] 贯穿算例数字与图内标注一致  
- [ ] 图注可搜索；打印/静态模式可读  
- [ ] 无科技感装饰填空；无示意图冒充实测  


## 3.8 分阶段动画 / 实物配额（硬指标）

配额是**下限**。已有资产可计入；重复装饰图不计入。缺额必须进缺口表，关闭前该阶段不得标「视觉完成」。

计数口径：

- **动画点**：1 张独立 SVG 动画，或 1 组 3–6 帧连续图（算 1 个动画点，不算多张）。
- **实物点**：1 张合格实物照片（§3.6）；同对象多角度且服务不同观察任务时可各计 1 点。
- **手绘机制点**：handraw-style 机制图，一图一问；不与动画点混算。

| 阶段 | 主线篇数（约） | 动画点下限 | 实物点下限 | 手绘机制点下限 | 备注 |
|---|---:|---:|---:|---:|---|
| 0 电芯与充电电量 | 2 | 6 | 3 | 4 | 含带载掉压、OCV 回弹、CC-CV |
| 1 认识 BMS | 1 | 4 | 2 | 3 | 五大保护各至少能指到一张图/动画 |
| 2 保护板实践 | 3 | 8 | 5 | 4 | P0：保护板正反面必有 |
| 3 AFE 与采样 | 3 | 8 | 5 | 5 | P0：AFE 板、分流器/霍尔、NTC |
| 4 SOC/SOH/SOP | 3 | 10 | 2 | 6 | 算法以动画+数据图为主，实物可少 |
| 5 通信 | 3 | 6 | 2 | 3 | 帧/CRC/重同步必须能动起来 |
| 6 高压与量产 | 2 | 8 | 4 | 5 | P0/P1：接触器+预充同框 |
| 7 BMS×AI | 1 | 2 | 0 | 1 | 短页；证据链动画优先于装饰 |

**书稿（bms-book）额外下限**

- 第 1–32 章：每章主线 ≥1 动画点 +（涉及硬件时）≥1 实物点或「待补」决策行。
- 高频章（建议优先加细）：第 1、7、12、14、15、20、21、24、27、30 章——每章主线 ≥2 动画点。
- 章首允许 1 张 handraw 场景插画（零数字）；不计入动画点，可计入手绘机制点仅当它真正讲机制。

**站点首页 / 传播层**

- 首页路线动画保留；不占用阶段配额。
- 传播层卡片不占用教程动画配额；但引用的数字必须与主线同源。

### 3.9 单元制作流水线（写稿前到合并）

每个新主线单元或改造单元按序执行，缺步不得标完成：

1. **讲透卡**（唯一目标、钩子、贯穿数、误解、≤3 句取回）写入 concepts 或章首元数据。  
2. **证据清单**：本单元需要的动画点 / 实物点 / 手绘点 / 波形点，标注「已有路径」或「新建」。  
3. **缺口登记**：新建项写入 `docs/视觉缺口表.md`（若文件不存在则本波次创建），字段见 §3.10。  
4. **先图后长文**：先完成或挂好图位与占位说明，再填段落；禁止正文写完后空着「此处应有图」。  
5. **同数贯穿检查**：钩子、公式、图注、取回题、微课（若有）数字一致。  
6. **静态可读**：关掉动画只看首末帧+图说，仍能完成取回题的机制部分。  
7. **门禁**：`check.py` / 相关 pytest / `visual_gap_audit` / 链接对账；新增 SVG 进索引。  
8. **决策行**：有取舍就写 §8 格式一行。  
9. **合并说明**：PR 写明关闭了缺口表哪些 ID。

### 3.10 缺口表与审计字段

W0 创建并维持两份表（可合并为一文件两个章节）：

**A. 动画缺口表字段**

`id | 阶段或章 | 现场问题 | 现有资产路径 | 缺口类型(无图/需重做/需拆分) | 优先级(P0-P2) | 负责人空窗 | 验收标准一句话 | 状态`

**B. 实物缺口表字段**

`id | 对象 | 对应章节锚点 | 是否P0 | 授权状态 | 候选来源 | 风险 | 状态`

**C. 原理简化审计（抽样或脚本辅助）**

每改造页追加检查（可先报告门）：

- 开篇是否现场问题（是/否）  
- 首个术语是否出现在证据之后（是/否）  
- 抽象段落后距最近证据的字符数  
- 动画点/实物点是否达本阶段单元份额  
- 取回交付是否可 ≤3 句复述（评审勾选）

### 3.11 单页「一点就懂」验收表（评审用）

评审人合上页后填写：

| 题 | 期望 |
|---|---|
| 这页只承诺学会哪一件事？ | 与讲透卡唯一目标一致 |
| 现场现象是什么？ | 能复述，不看原文 |
| 指着图/动画：谁变了？ | 说对对象与方向 |
| 用贯穿数字手算一步 | 量级与结论正确 |
| 一个反例/边界 | 说对「何时不能这么判」 |
| 下一站去哪 | 说得出主线或选读 |

5 题中机制与手算两题必须过；否则退回，不记「改造完成」。

### 4.3 微课形态硬规则

- 一条只讲一个问题；一个具体例子从头走到尾。  
- 开头两秒直接给故障、现象或问题，不先报幕。  
- 屏上只留关键词、数字和步骤，不逐字复述旁白。  
- 结束只留一个结论，不塞整章验收清单。  
- 总课、微课、短切片三者不互相冒充。  
- 优先「逐步生长的图 / 连续变形 / 完整算例」，少用纯卡片报幕。

## 5. 代码契约

- 三个包在 PC 上可跑，并由 CI 守护：`code/soc`、`code/protocol`、`code/firmware`。  
- 每个主线概念尽量对应「输入 → 输出 → 误差或自检」入口；没有代码的硬件任务在正文标明，不强行补伪 demo。  
- **改宽断言不算修好**；合并仍要人签字。  
- 演示数值永不冒充可上板产品参数。  
- 共学与挑战优先交「可复算产物」，不只交读完打卡。  
- 能可视化的 demo（波形、SOC 曲线、帧状态）应输出可截进正文的图或动画源，进入 §3 证据链。

## 9. 知识点「入门→精通」彻底改造

### 9.0 一句话目标

每个知识点（KP）必须能让零基础读者沿固定梯子走到「可独立判断与交付」的精通态；不是只写一篇理解文，也不是只挂一个 Bloom 标签。

### 9.1 五级精通梯子（硬合同，与 Bloom 映射）

| 级 | 白话名 | Bloom 映射 | 读者能做到 |
|---:|---|---|---|
| L1 | **识名** | 记忆 | 说得出对象 / 红线 / 断口名字与单位 |
| L2 | **讲清** | 理解 | 用自己的话讲因果，能指认动画 / 实物 |
| L3 | **手算/跑通** | 应用 | 同一组贯穿输入算出或跑出证据 |
| L4 | **会判** | 分析 / 评价 | 指出反例、选方案、说清证据不足为何失败 |
| L5 | **能交付** | 创造 | 给出别人可复现的最小交付（实验记录 / 补丁 / 报告 / 仿真脚本） |

**硬规则**

1. 主线页至少覆盖到 **L3（手算/跑通）**。  
2. 选读或挑战必须提供 **L4（会判）**。  
3. 阶段毕业 / 挑战提供 **L5（能交付）**；每个阶段至少 1 条贯通到 L5 的毕业向 KP。  
4. **禁止**只停在识名，或只堆定义不设取回。  
5. 每一级必须有：**入口媒介 + 取回任务 + 通过标准（可勾选）**；缺一项不得标该级完成。

### 9.2 知识点（KP）最小数据合同（扩展 concepts.json）

**真源**：`curriculum/concepts.json`（概念 ID 真值表）。  
现库仅 **13** 条核心问题，且多数 `level` 停在理解 / 分析——**不够**，本版加码如下。

#### 必填字段（兼容旧字段，新增不得删旧 id）

| 字段 | 要求 |
|---|---|
| `id` | 稳定 kebab-case；现有 13 条 id **不得删除** |
| `order` / `stage_no` / `domain` | 排序与阶段归属 |
| `title` | ≤20 字；可用现 `question` 压缩，或新增短标题 |
| `question` | 现场问题（保留） |
| `ladder` | 对象，含 `L1`…`L5`；每级 `{goal, entry_path, retrieve_task, pass_check, media[]}` |
| `bloom_ceiling` | 本 KP 主线最高 Bloom / 梯子级（主线默认 ≥ L3） |
| `prerequisites[]` | id 列表（沿用并校核） |
| `next[]` | 推荐下一 KP id 列表 |
| `cross_media` | `stage` / `book` / `animations` / `video` / `practice` / `checkpoint`（沿用现字段并校核；可用扁平字段等价） |
| `mastery_evidence` | 精通态证据类型：日志 / 手算纸 / 仿真输出 / 照片 **之一**（可多选写数组） |
| `status` | `planned` \| `active` \| `gap` |

旧字段（`level`、`teaching`、`precheck`、`answer`、`deliverable` 等）保留；与 ladder 冲突时以 ladder + 九项契约为准，并在 W2 对齐。

#### 配额硬指标（W1 建表，W2–W5 填满）

| 范围 | 指标 |
|---|---|
| 阶段 0–6 | 每阶段主线 KP ≥ **8**（可含子 KP） |
| 阶段 7 | ≥ **4** |
| 全库 | `active` KP 目标 ≥ **60**（先从现有正文 / 小节标题抽取，再补洞） |
| 骨干 | 现有 13 条保留为骨干 KP，必须补全 L1–L5，不得删 id |
| 毕业向 | 每个阶段 ≥ 1 条贯通到 L5 的 KP |

### 9.3 改造流水线（每个 KP）

1. **抽现状**：正文锚点、动画、实物、代码、视频片段 → 写入 `kp_gap_audit`。  
2. **填 ladder 五级**；缺入口 / 取回 / 通过标准标 `gap`。  
3. **按九项单元契约**改主线文（§2）；主线对齐到约定 `bloom_ceiling`（≥ L3）。  
4. **补动画 / 实物**到「讲清 / 手算」级（§3）。  
5. **微课**只服务一个 KP 的一个梯子级（通常 L2 或 L3）（§4）。  
6. **门禁**：concepts 校验脚本（新增，W1 起计划）检查必填字段、死链、梯子缺项；失败不得标完成。

### 9.4 与现有结构的对齐

| 现有物 | 改造方向 |
|---|---|
| 阶段 0–7 | 仍是默认练习场顺序 |
| `docs/stages/bloom-map.md` | 每层入口改为指向 KP ladder 对应级，不再只是散落小节目录 |
| Bloom「记忆→创造」六层 | 映射到 L1–L5（评价并入 L4；创造 = L5） |
| `按目标选路线` 六条捷径 | = KP 子集路径；每条捷径列出 KP id 序列 |
| 伴读书章节 | 必须回链 KP id |
| 动画索引 / 微课分镜 | 标注服务的 KP id + 梯子级 |

### 9.5 验收（陌生读者）

抽 **3** 个 KP（跨阶段）。读者从未读过库，按 ladder 走，应能：

- **L2**：口述机制 ≤3 句  
- **L3**：不看答案完成取回  
- **L4**：指出一个反例  
- （若该 KP 宣称到 L5）交出可复现最小物  

失败则该 KP `status` 回 `gap`，不得标完成。试读记录回写 `docs/陌生读者试读记录.md`（或等价路径）。

### 12.2 五阶段能力路径

总目标：读者逐步获得「看懂电池、测得可信、控制可靠、验证算法、交付系统」的能力，而不是完成章节阅读。每阶必须写明前置知识、必修内容、动手项目、交付物和过关条件；前置以短任务核对，不以「读过某章」判定，过关以可观察证据判定。

读者版导航见 [五个能力阶段](stages/能力阶段.md)；该页只做阶段检查与链接，不复制课程正文。

#### 入门——看懂电池与安全边界

- **前置**：四则运算、单位换算、能读简单曲线；不要求电化学。入口短任务：说清 V/A/Ah/Wh 各自描述的对象与电流方向约定。
- **必修**：电芯、模组、电池包与 BMS 的职责；电压、电流、容量、能量、倍率与串并联关系；充放电过程，温度、内阻、极化对端电压的影响；开路电压与端电压的区别，SOC 不能直接等同于电压百分比；不同化学体系的差异与实验安全边界。
- **动手**：使用注明来源的公开数据或仿真数据，画充放电的电压、电流、温度和累计 Ah/Wh 曲线。
- **交付物**：曲线图 + 数据来源、单位、工况 + 「这组数据能/不能支持什么」的短说明。
- **过关条件**：独立复算容量与能量，统一单位和电流方向；解释负载掉压与静置回弹；指出数据不能支持哪些结论。

#### 基础——让测量结果可信

- **前置**：完成入门；会分压/分流、代数和采样基本概念。入口短任务：给一条采样链标出参考点、量程和电流方向。
- **必修**：分压、分流器、NTC 与 ADC 的工作原理；采样时序、量化、偏置、增益误差、温漂与标定；测量误差预算，误差合成时区分独立性与相关性；滤波效果与检测延迟之间的取舍；电流测量偏置如何造成 SOC 累积漂移。
- **动手**：完成一条电压或电流测量链的设计说明、误差预算、标定与独立验证。
- **交付物**：测量链说明、误差预算、标定数据、独立验证数据与对比报告。
- **过关条件**：标定数据与验证数据分开；能比较修正前后误差；解释不同量程与温度下的表现；量化误差对后续算法和保护的影响。

#### 进阶——让采集、保护与通信可靠协同

- **前置**：完成基础；了解中断/任务、超时、CRC 与状态机基本概念。入口短任务：画一次超时后的故障锁存与恢复。
- **必修**：AFE 采样、开线诊断、均衡条件与限制；MOS、接触器与预充过程；保护阈值、迟滞、去抖、锁存与恢复条件；MCU 驱动、CRC、超时、重试、看门狗与数据新鲜度；上电、自检、运行、故障、降级与恢复状态机。
- **动手**：在模拟输入或受控低能量台架上，完成「采集→判断→动作→恢复」完整链路，并注入断线、通信超时、CRC 错误、复位与陈旧数据。
- **交付物**：状态转移表、故障注入用例、可重放日志与测试记录。
- **过关条件**：每个状态转移都有输入条件、时限、输出动作和恢复条件；输入失效后不得继续使用旧数据获得运行许可；所有关键故障有可重放日志与测试证据。

#### 工程——用证据建立 SOC、SOH 与 SOP

- **前置**：完成基础与进阶；具备线性代数、概率统计和数据划分基础。入口短任务：说明辨识数据与验证数据为何必须分开。
- **必修**（按序）：
  1. 电流积分及误差累积；
  2. OCV 校正的温度、静置、滞回与平台区限制；
  3. 等效电路模型、HPPC、参数辨识与离散化；
  4. 可辨识性、激励条件与独立数据验证；
  5. EKF 的状态、观测、雅可比、噪声协方差、初始化与残差分析；
  6. SOH 指标、参考值来源，以及 SOP 的多约束预测。
- **动手**：在相同验证工况下比较电流积分、OCV 辅助与 EKF；分析容量、内阻与功率限制随温度、SOC 与老化的变化。
- **交付物**：模型卡、参数集、辨识记录、验证报告、SOP 约束与预测时间窗。
- **过关条件**：辨识数据与验证数据隔离；报告平均误差、最大误差、收敛时间和失效场景；能解释算法何时优于基线、何时失效；不以同一模型生成的数据验证自身后宣称已获实测验证；SOP 必须说明预测时间窗，并考虑最弱单体、电压、电流、温度和老化约束。

#### 精通——解释取舍并交付可复现系统

- **前置**：完成工程；具备需求、版本、测试与 V&V 基本概念。入口短任务：把一条需求写成可观察的验收条件。
- **必修**：需求追踪、整包误差与时序预算、功耗预算、异常降级、保护独立性、系统故障注入与版本化发布。
- **综合项目**：针对明确的化学体系、串数、用途和温度范围，交付一套参考 BMS。
- **交付物**：需求与架构说明、数据及来源、模型参数、代码、依赖说明、测试用例、测试结果、运行日志、发布说明和已知限制。
- **过关条件**：另一位读者能在干净环境复现约定结果；关键需求都有对应证据；能解释模型、滤波、保护时间和恢复策略的选择依据。教材项目通过不等同于获得认证或满足量产安全要求。

### 12.5 视觉与实验要求（补充）

§3.5、§3.6 与 v3 细则 §6 继续有效；下列要求是读者可见的补充验收项：

1. **手绘图**解释结构、因果与能量或信号路径，沿用已定稿画风与色板；一图一问，不用装饰图凑数。
2. **动画**解释时间过程，支持暂停与关键帧阅读；每个关键帧标明时刻、条件、单位和方向；第一帧与末帧不播放也可读。
3. **实物照片**用于识别器件、测点和接线，注明来源与适用条件；区分「实拍 / 示意 / 非实拍」，并写明照片里没有什么。
4. **实测、仿真和原理示意必须明确区分**；每张图服务一个具体学习问题，图注写清它回答什么、不能证明什么。
5. **危险故障**只通过模拟输入、数据注入或受控限能台架验证；不安排真实电芯过充、短路实验。涉及带电、拆壳、高压柜的试验须先有场地、仪器、适格人员和停止条件；PC 仿真不得写成 HIL 或「BMS 在环」。
6. **出版版本的静态替代**：每张动画都要有可理解的静态替代（首末帧、图注与观察任务），使打印、EPUB 和离线读者不依赖播放也能完成机制部分。

### 12.6 实施顺序与验收记录

在既有波次内，内容收口按下列顺序优先；这不是新的时间表，也不改变执行表的进度状态：

1. **理顺能力主线**：把入门 / 基础 / 进阶 / 工程 / 精通映射到现有课程、阶段页、D/B/R 单元与项目；补前置核对与导航，不重复建页。
2. **完成三个样板**：测量误差、保护状态机、SOC 基线按 §12.3 六步闭环与 §12.5 视觉/实验要求做透。
3. **接通系统故障测试**：断线、通信超时、CRC 错误、复位、陈旧数据与保护动作/恢复形成可重放证据链。
4. **完成参考发布与复现**：在干净环境按版本、依赖、数据、模型参数、测试与日志复现约定结果。
5. **扩展视觉和高阶选读**：前四步有证据后，再扩动画/实物与 R01–R04 研究支线。

该顺序是内容验收的优先级；与 W0–W5、P0–P8 的具体排期冲突时，进度只认执行表，内容验收按本节更严口径。独立章节、图源和来源补证可并行；共享 manifest、构建器与模板由一位集成负责人写入。

每项验收记录至少包含：

| 字段 | 要求 |
|---|---|
| 对象 | 单元、章节、图或实验的稳定 ID |
| 文件 | 实际路径，不用「某章」代替 |
| 版本 | commit / tag / 内容版本；历史记录保留原日期与范围 |
| 检查方法 | 命令、读者任务或硬件步骤，须可重跑 |
| 证据 | 日志、截图、数据、试读记录或测量记录的路径 |
| 结论 | `通过` / `不通过` / `待核查` + 一句理由 |
| 未核实项 | 外部待验、硬件待验或读者待验，写明责任条件 |

`通过` 只在证据存在且方法可复现时使用；`待核查` 不得计为通过或缺失；`不通过` 必须写失败行为与影响，不能只写「需改进」。软件检查分别报告 passed / failed / unverified，不用一个绿灯代替技术审读、最终版式、真人试读或硬件实测。所有数值门限按具体器件、化学体系、工况和应用需求约定，不把示例参数写成通用量产要求。

### 12.7 与既有合同的对齐

| 本节条目 | 既有合同 | 关系 |
|---|---|---|
| 五个能力阶段 | §9.1 五级梯子 L1–L5 | 不同轴：能力阶段是课程推进顺序，梯子是单个 KP 的精通深度；一个阶段不要求所有 KP 到 L5 |
| 必修主线 / 方向选读 / 工程查阅 | §1.3 阅读角色 | 同层改名，不新增页面类型 |
| 六步单元闭环 | §2.1 九项契约、§3.9 流水线、v3 G01–G10 | 六步是读者可见的讲解与验收顺序；九项契约与 G 环节仍是底层最低要求 |
| 三个样板 | S1–S3 出版样章、C1–C3 项目 | 样板是跨媒介闭环示范；样章与项目保留原身份，复用不复制 |
| 视觉与实验补充 | §3.5、§3.6、v3 §6/§9 | 补充关键帧、静态替代与危险试验边界，不降低原图门 |
| 验收记录 | v3 §10 状态模型 | 本节只补记录字段与「待核查」口径，不另建状态机 |

判断标准只有一句：读者是否更容易建立因果链，并能自己把它重新推出来——最好还能指着实物和动画把机制讲给别人听，并沿「识名→能交付」梯子交出证据。
