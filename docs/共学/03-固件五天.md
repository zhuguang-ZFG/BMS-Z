# 共学：固件状态机五天

> **本篇你会学到**　保护去抖、故障快照、均衡退出和快照回放，怎样落在一次 `bms_tick` 里。
> **预计用时**　5 天，每天大约 45–90 分钟。
> **前置**　有 gcc（或别的 C99 编译器）。不烧板，不接电芯。

⚠️ `code/firmware` 是教学骨架。预充、充电过流、欠温没有实现。阈值在 `test_bms.c` 里是示例，例如过充 4250 mV、去抖 3 次。**不要抄到真电池上。** 骨架没有开线标志：0 mV 会被记成欠压。

## 第 1 天：同一时刻只停在一个状态

**读**　[阶段 3 §3.4](../stages/stage-3-AFE-MCU智能BMS.md#34-固件架构四层--一台状态机-应用)。四层谁干什么，状态机集中管迁移。

**看**　[状态机巡游](../circuits/assets/state-machine.svg)。令牌一次只停在一个圆里。底栏的 4.25 V / 4.15 V 是这张图的示意门槛，不是 `test_bms.c` 里的 4250 mV。两套数字不要加在一起。

**跑**

```bash
cd code/firmware && gcc -std=c99 -Wall -Wextra -Werror -o test_bms bms.c test_bms.c && ./test_bms
```

PowerShell：

```powershell
cd code/firmware ; gcc -std=c99 -Wall -Wextra -Werror -o test_bms.exe bms.c test_bms.c ; .\test_bms.exe
```

通过时最后一行是：

```text
ALL BMS TESTS PASSED
```

中间每一行 `ok ...` 是一个场景。没有 `ALL BMS TESTS PASSED` 就还没做完，把编译器原文贴出来。

**交**　贴最后一行，并写：为什么不在十个函数里各写一句「电压高了就关 MOS」。

**口诀**　同一时刻只停在一个状态。保护事件可以打断它。

**今天你解锁了**　你编译并跑通了 BMS 状态机骨架。板子还在后头，逻辑已经在你机器上响过一次。

## 第 2 天：尖峰不是故障

**读**　仍是 [§3.4](../stages/stage-3-AFE-MCU智能BMS.md#34-固件架构四层--一台状态机-应用) 里「去抖」那几句。连续 N 次超限才动作，正常输入把计数清掉。去抖是为了放过尖峰，不是为了把短路拖慢——短路在这套骨架里是另一条路。

**看**　[过流分档延时](../circuits/assets/oc-level-delay.svg)。延时随档位变，是示意，不是上面那条 gcc 命令的打印。

**跑**　同一条编译命令。在输出里找到这一行：

```text
ok ovp debounce+snapshot
```

```bash
cd code/firmware && gcc -std=c99 -Wall -Wextra -Werror -o test_bms bms.c test_bms.c && ./test_bms
```

PowerShell：

```powershell
cd code/firmware ; gcc -std=c99 -Wall -Wextra -Werror -o test_bms.exe bms.c test_bms.c ; .\test_bms.exe
```

**交**　贴那一行 `ok`。用自己的话写：去抖计数在「还没满」的时候，状态机允许怎样，满了之后又怎样。对照源码，不要编一个新的毫秒数。

**口诀**　一次超限先记账。账满了才动作。

**今天你解锁了**　你能把「看到一次高电压」和「确认过充」分开。

## 第 3 天：第一现场不能被后来的故障涂掉

**读**　[§3.4](../stages/stage-3-AFE-MCU智能BMS.md#34-固件架构四层--一台状态机-应用) 里故障锁存，以及 [固件 README](../../code/firmware/README.md) 关于第一现场的那句。显示用的主故障可以升级；第一次记下的快照不覆盖。

**看**　[故障锁存](../circuits/assets/fault-latch.svg)。电压已经回到示意恢复线以下，锁存仍是 1。图上的 4.25 V / 4.15 V / 4.10 V 是示意。

**跑**　在昨天的输出里找到：

```text
ok first-snapshot kept
```

命令与第 2 天相同。

**交**　贴这一行。写一句：后来的短路可以把屏幕上的故障名改掉，为什么不该把第一张快照也改掉。

**口诀**　进故障很容易。自己走出来不行。第一现场留着。

**今天你解锁了**　你分得清「现在最严重的故障」和「第一次是谁触发的」。

## 第 4 天：均衡会在该停的时候停

**读**　[code/README 的 firmware 走读](../../code/README.md#firmware五条纪律的代码落点对应阶段-3--6-应用) 里均衡那一条。充电器不在、电流不是正的、电压跌破门槛，都要在同一拍把均衡关掉。

**看**　[被动均衡分时](../circuits/assets/balance-scheduling.svg)。谁在放电、能量去了哪里，图说写了。效率空表仍然空着，不要在打卡里填一个 η。

**跑**　同一条 `./test_bms`。找到这两行：

```text
ok balance entry/exit
ok balance exits on reversed current
```

**交**　两行都贴。写一句：压差还在，但是电流反向了，这一拍均衡应该怎样。答案在测试名里，用你自己的话再说一遍。

**口诀**　均衡是充电时的细活。电流一反，细活立刻停。

**今天你解锁了**　你知道「压差还大」不能单独决定均衡继续开着。

## 第 5 天：在电脑上回放一次故障

**读**　[阶段 6 §6.2.5](../stages/stage-6-精通与毕业项目.md#625-故障注入与快照回放-应用)。`hil_replay` 不改 `bms.c`。它不是实验台，没有开线检测。

**看**　[HIL 台示意图](../circuits/assets/hil-testbench.svg)。图注如果写着示意图，就不要把它当成你实验室的照片。仓库里这张是教学动画。

**跑**

```bash
cd code/firmware && gcc -std=c99 -Wall -Wextra -Werror -o hil_replay bms.c hil_replay.c && ./hil_replay
```

PowerShell：

```powershell
cd code/firmware ; gcc -std=c99 -Wall -Wextra -Werror -o hil_replay.exe bms.c hil_replay.c ; .\hil_replay.exe
```

2026-10-06 末行：

```text
HIL REPLAY PASSED
```

前面会看到过充快照停在 `cell2=4300`、`I=2000`，随后显示故障变成 `SCD`，快照仍是 `OVP`。另一段把一串打成 0 mV，骨架记成欠压，并说明真实验台要另注入断线。这些毫伏和毫安是回放脚本里的数，不是示波器抓的。

**交**　贴 `HIL REPLAY PASSED`，外加你看到的那行「说明：本骨架没有开线标志……」。

**口诀**　回放是在电脑上重演脚本。脚本没写的故障，骨架不会变出来。

**今天你解锁了**　你在没有电池的情况下，看过一次「后来的短路盖不住第一张过充快照」。
