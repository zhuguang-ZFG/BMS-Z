# 第 3 练：审一段 AI 改过的 diff

> 合成教学夹具。没有真实电芯、阈值或硬件，也不改动 `code/protocol`。脚本按 MIT，和 `code/` 一样。

## 场景

同事让模型改一版教学帧闸门。交回来的是 [`review.diff`](review.diff)；`project/` 是应用后的代码，可见测试全绿，`project/gates_report.txt` 也「更新」了。

你的任务不是重写，而是只做审查：哪一行危险、为什么危险、要补哪条测试。不要让它一边审一边重写——重写会把证据一起改掉。

## 怎么练

1. **只看 diff**　先读 [`review.diff`](review.diff)。不要先打开 `project/`、`verify.py` 或 [`ANSWER.md`](ANSWER.md)。
2. **写五类**　按 [AI 陪练卡 · 写代码的五个关卡](../../docs/AI陪练卡.md#写代码的五个关卡)里关卡 4 的五看逐项过：测试 / 异常 / 行为 / 依赖 / 生成物。每条写文件、行号、危险信号、要补的测试和判定。
3. **对答案**　写满五类再打开 [`ANSWER.md`](ANSWER.md)。答案按类别列，不按你写的顺序。
4. **跑自检**　最后运行：

   ```bash
   python challenges/03-ai-review/verify.py
   ```

   它会跑可见测试（应绿）、四条隐藏检查（应红）、依赖扫描（应发现一个外部包）和生成器对账（应出现不一致）。

> **退出码 0 不表示你审对了**　它只表示夹具完整：可见测试仍然全绿，五类问题都还在。你的审查记录要自己写。

## 边界

- `review.diff` 的路径相对于 `project/`，不是仓库根。
- 可见测试是绿的，因为夹具只覆盖 ASCII 载荷、63 字节以内的载荷，并且把断言改宽了；这不代表实现正确。
- 夹具不接 CI，也不进 `scripts/local-gates.sh`：隐藏检查本来就该红。
- 这里没有真实协议、真实阈值或真实硬件。练的是审查动作，不是产品验收。

**练完你会怎样**：你能在一段「测试全绿」的 diff 里指出哪条断言被放宽、哪条异常被吞、哪处行为漂移、哪个依赖是新塞的、哪个生成物被手改，并要求补对应的测试。
