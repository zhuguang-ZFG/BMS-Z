# 23 · 把需求变成可执行的验证

先修：[第 22 课](22-hardware.md)。完成本课，你能将一句保护要求拆成输入、时间界限、输出和证据，而不只写“测试正常”。

## 要求必须说得出失败是什么

“欠压能断开”太宽。给 PC 模型写成：**在采样有效且按约定周期到达时，单节连续 ≤3.00 V 达到 0.20 s，首次满足条件的处理拍必须禁止输出；故障保持锁存。** 这里计时起点是首个观察到的欠压样本，不是未知的物理越线瞬间。

| 需求 ID | 输入与反例 | 应观察到什么 | 证据 |
|---|---|---|---|
| R01 数据可信 | 新样本、重复时间戳、缺节、NaN | 无效样本禁止使能，SOC 标记无效 | 原始输入与质量日志 |
| R02 欠压确认 | 持续低压、短一拍、恢复后再低压 | 持续才动作，未触发前恢复则清计时 | 阈值与时间线 |
| R03 动作反馈 | 命令断开、反馈及时/超时 | 超时追加故障，保留原故障 | 命令与反馈两列 |
| R04 远程边界 | 消息新鲜/过期、本地故障 | 远程请求不能绕过本地禁止 | 接收时间与使能日志 |
| R05 电量收支 | 改容量、周期、充放电符号、缺段 | 与 Ah 手算一致，未知区间不冒充已知 | 输入、SOC 与质量 |

每个需求至少有正常、临界和失败输入。只测 3.70 V 正常值，无法证明 3.00 V 的包含关系，也无法证明短脉冲会被正确处理。

## 从采样周期算真实时间上界

先假设采样**严格等间隔 0.10 s**，观察到欠压后确认 **0.20 s**，正好是两个完整周期，处理和下令的额外延迟上界为 **0.01 s**。若真实越线刚好发生在一次采样之后，最坏还要等近一个周期才被看见。在这组条件下，从真实越线到命令的保守预算为：

**0.10 + 0.20 + 0.01 = 0.31 s。**

若只知道采样间隔不超过 0.10 s，而允许抖动，确认期限到达时可能还没有下一拍；若确认时间不是周期的整数倍，也会发生向后取整。此时应再预算最多一个采样周期，或改用独立定时器并验证其调度。不能把严格等间隔的计算直接当作抖动系统上界。

这只是按给定假设计算的设计预算。PC 回放没有测量操作系统调度、总线时延、ADC 转换与执行器响应，不能因为 CSV 显示 0.50 − 0.30 = 0.20 s，就宣称真实硬件总响应 0.20 s。工程还要验证丢样处置和独立快速保护；未知区间也不能继续当作已知电流更新可信 SOC。

## 自动测试与真实验证分开交付

配套行为测试可在仓库根运行：

```sh
python code/course/test_course.py
```

它检查短脉冲、延时边界、缺样、重复时间、反馈锁存、帧破坏、序号回绕，以及检查器能否拒绝错误的学员答案。测试通过证明这些软件样本满足约定，不能证明焊接、传感器精度、MOS 分断能力或功能安全等级。

提交验证矩阵时，把“已执行”“未执行”“失败待修”写成明确状态。每个已执行项附版本、输入、命令和结果路径；真实硬件项可以先给试验方法与停止条件，但没有记录就不能勾成通过。进一步流程见[量产与毕业专题](../stages/stage-6-主线-量产与毕业.md)。
