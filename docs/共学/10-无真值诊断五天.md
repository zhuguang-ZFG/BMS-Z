# 共学：无真值诊断五天

> **本篇你会学到**　手里没有参考 SOC 的时候，怎么知道模型坏没坏：新息（残差）$z - h(\hat x)$ 是什么、它的均方根与 NIS 各管什么、**参数错**和**传感器坏**在残差上长得不一样（一个跟着电流走、一个只是整体偏），以及为什么温度注入不会让新息跳变。
> **预计用时**　5 天，每天大约 30–60 分钟。
> **前置**　做过 [SOC 五天](01-soc五天.md) 或读过 [阶段 4 §4.5](../stages/stage-4-SOC-SOH算法.md)。装好 Python 3.10+、在仓库根 `pip install -r code/requirements.txt`，并且跑过一次 `python code/soc/real_data.py`（生成 `code/soc/real-data-output/`）与 `python code/firmware/pc_demo.py`（生成 `code/firmware/pc-demo-output/`）。不接电池。

⚠️ 本篇的两个数据源都不是「真值考试」：`real-data-output` 的参考 SOC 是**用同一路实测电流算出来的库仑参考**，不是独立测量（报告里 `independent_soc_truth` 是 `false`）；`pc-demo-output` 是合成仿真，故障是采样端注入。新息能帮你**发现对不上**，不能替你宣称「实际 SOC 精度是多少」。

## 第 1 天：新息是什么

**读**　[阶段 4 §4.5 卡尔曼滤波](../stages/stage-4-SOC-SOH算法.md) 里「用观测修正预测」那一段：每拍先按模型预测，再拿真实测量和预测**对一次账**，差值就是新息。

**看**　[库仑计零漂与 EKF 的残差拉回](../circuits/assets/coulomb-ekf-loop.svg)。红线只靠积分按天漂走，蓝折线每拍先预测、再被电压残差拉回——残差不是误差，它是**你能算出来的那个差**。

**跑**（手算一次新息，仓库根）：

```bash
cd code/soc && python3 -c "
from cell_model import ocv
soc, i, r0 = 0.50, 2.0, 0.020
h = float(ocv(soc)) + i*r0
z = 3.8050
print('模型预测 h = %.4f V' % h)
print('仪表测量 z = %.4f V' % z)
print('新息 z - h = %+.2f mV' % ((z-h)*1000))
"
```

2026-10-09 输出：

```text
模型预测 h = 3.7900 V
仪表测量 z = 3.8050 V
新息 z - h = +15.00 mV
```

$h = \mathrm{OCV}(0.50) + I R_0 = 3.7500 + 0.0400 = 3.7900$ V，表给 3.8050 V，新息 **+15.00 mV**。这个数的原材料**全在你手里**：模型的预测和仪表的读数，不需要任何参考 SOC。

**交**　贴输出，并回答：这 15 mV 更像「SOC 猜低了」，还是「电压表偏了」？为什么这一拍分不出。

**口诀**　新息是仪表和模型吵的那一架，和真值无关。

**今天你解锁了**　你能用一行减法算出新息，并说清它为什么不需要参考值。

**短自测**　为什么新息不能直接当成 SOC 误差？

<details>
<summary>先自己答再展开</summary>

因为它是**电压**的差，不是 SOC 的差；而且这一拍的差可能来自 SOC 猜错、R0 写错、电压表偏置、温度变化或单纯噪声——一个方程，多个未知。要把它换成 SOC 误差，得靠观测敏感度 $C = \mathrm{dOCV}/\mathrm{dSOC}$：[电芯建模五天](09-电芯建模五天.md) 里 SOC 0.05 处 $C = 6.8$ V/SOC，同样 15 mV 只对应 0.2% 的 SOC；平台区 $C = 0.8$ V/SOC，同样 15 mV 就是 1.9% 的 SOC。**同一个新息，在不同 SOC 点意味着不同的东西。**
</details>

## 第 2 天：没有参考值也能判断

**读**　[SOC 真实数据专题](../SOC真实数据专题.md)（它的 `report.json` 从 v1.6.0 起多出 `diagnostics` 一段）与 [阶段 4 §4.5](../stages/stage-4-SOC-SOH算法.md) 里关于新息协方差的部分。

**看**　[标量卡尔曼增益 K = P/(P+R)](../circuits/assets/kalman-gain.svg)。R 更大（测量更吵），平台更低——新息被信多少，是权重问题，不是对错问题。

**跑**（读实测记录的两套参数）：

```bash
python3 -c "
import json
d = json.load(open('code/soc/real-data-output/report.json', encoding='utf-8'))
for k, v in d['diagnostics'].items():
    print('%-14s 新息 RMS %6.3f mV   均值 %+6.3f    NIS %.4f' % (k, v['innovation_rms_mv'], v['innovation_mean_mv'], v['nis_mean']))
print('电压 RMSE  generic %.1f mV / calibrated %.1f mV' % (d['voltage_rmse_mv']['generic'], d['voltage_rmse_mv']['calibrated']))
print('reference_kind =', d['reference_kind'])
print('independent_soc_truth =', d['independent_soc_truth'], '| model_fitted_on_validation =', d['model_fitted_on_validation'])
"
```

2026-10-09 输出：

```text
ekf_generic    新息 RMS 15.137 mV   均值 -0.338    NIS 0.5340
ekf_calibrated 新息 RMS  3.699 mV   均值 +0.492    NIS 0.0325
电压 RMSE  generic 186.3 mV / calibrated 21.8 mV
reference_kind = coulomb_reference_from_same_measured_current_and_separate_calibration_capacity
independent_soc_truth = False | model_fitted_on_validation = False
```

三列要分开读：

| 列 | 它回答什么 | 这里读出什么 |
|---|---|---|
| 新息 RMS | 模型和测量**一般**差多少 | 15.137 → 3.699 mV，差 4 倍 |
| 新息均值 | 差是**一边倒**还是两边晃 | −0.338 与 +0.492，都没偏成百毫伏 |
| NIS | 差**相对噪声**算不算大（卡方归一） | 0.5340 → 0.0325，一个偏大一个偏小 |

**没有参考 SOC，这三列照样算得出来**——它们只用模型预测和实测电压。最后两行是诚实标注：参考 SOC 不是独立真值（`independent_soc_truth = False`），模型也没在验证段上调参（`model_fitted_on_validation = False`）。看一眼电压 RMSE 就明白差距的来源：generic 模型 186.3 mV，标定后 21.8 mV——**同一个滤波器，参数换了，残差跟着变**。

**交**　贴输出，并回答：如果只看新息均值，能判断出 generic 模型差在哪吗？

**口诀**　RMS 看大小，均值看见偏，NIS 看见「相对噪声算不算大」。

**今天你解锁了**　你能在没有参考 SOC 的情况下报出三个诊断数，并说清每个数的含义与边界。

**短自测**　为什么 `independent_soc_truth = False` 这条要写进报告，而不是省掉？

<details>
<summary>先自己答再展开</summary>

因为它是**这份报告最容易被读错的地方**：参考 SOC 由实测电流积分而来，与被评估的估算器共享同一路电流和同一份标定容量——两者不是独立测量。省掉这一行，读者会把「和参考差 0.2%」当成「精度 0.2%」。诊断数的价值在于**相对比较**（generic 对 calibrated），不在于宣称绝对精度。
</details>

## 第 3 天：参数坏，还是传感器坏

**读**　[阶段 4 §4.5](../stages/stage-4-SOC-SOH算法.md) 的观测方程 $z = \mathrm{OCV}(\mathrm{SOC}) + I R_0 + U_{rc} + v$，以及 [阶段 4 §4.4b 在线辨识](../stages/stage-4-SOC-SOH算法.md)：参数该由数据来改。

**看**　[采样线断线检测](../circuits/assets/open-wire-detection.svg)。采样线断开时引脚被检测电流拉向异常电平——**传感器坏**是这一类事，和模型参数错不是一回事。

**跑**（同一段工况、同一个种子，四种情形，看新息与电流的关系）：

```bash
cd code/soc && python3 -c "
import numpy as np, compare
from estimators import EKFEstimator
from cell_model import TheveninCell

def run(make, v_bias=0.0):
    rng = np.random.default_rng(42)
    cell = TheveninCell(compare.Q_TRUE_AH, compare.R0, compare.R1, compare.C1, soc0=0.8)
    cur = compare.drive_cycle(compare.N_STEPS, compare.DT_S, 42)
    est = make(); inn = []; im = []
    for k in range(compare.N_STEPS):
        i_true = cur[k]; v_true = cell.step(i_true, compare.DT_S)
        i_meas = i_true + compare.I_OFFSET_A + rng.normal(0.0, compare.I_NOISE_A)
        v_meas = v_true + rng.normal(0.0, compare.V_NOISE_V) + v_bias
        est.step(i_meas, v_meas, compare.DT_S)
        inn.append(est.last_innovation_v*1000); im.append(i_meas)
    inn = np.array(inn); im = np.array(im)
    load = np.abs(im) > 1.0
    return np.median(np.abs(inn)), inn.mean(), np.corrcoef(inn[load], im[load])[0,1]

cases = [('模型与观测都对', lambda: EKFEstimator(0.7, 9.5, 0.020, 0.015, 3000.0), 0.0),
         ('模型坏：R0 十倍', lambda: EKFEstimator(0.7, 9.5, 0.200, 0.015, 3000.0), 0.0),
         ('观测坏：电压偏 +50mV', lambda: EKFEstimator(0.7, 9.5, 0.020, 0.015, 3000.0), 0.050),
         ('容量错：9.5->5.0Ah', lambda: EKFEstimator(0.7, 5.0, 0.020, 0.015, 3000.0), 0.0)]
print('%-20s %10s %10s %12s' % ('情形','新息中位','新息均值','与电流相关'))
for name, make, bias in cases:
    med, mean, corr = run(make, bias)
    print('%-20s %8.2f mV %8.2f mV %11.3f' % (name, med, mean, corr))
"
```

2026-10-09 输出：

```text
情形                         新息中位       新息均值        与电流相关
模型与观测都对                  3.64 mV     0.06 mV      -0.004
模型坏：R0 十倍                6.41 mV     9.76 mV      -0.288
观测坏：电压偏 +50mV            4.25 mV     3.99 mV       0.060
容量错：9.5->5.0Ah           3.64 mV     0.01 mV      -0.062
```

这张表是本篇的判据，读法四句：

1. **都对**：中位 3.64 mV，均值几乎为 0，与电流的相关 **−0.004**（没有关系）。
2. **模型坏**（R0 十倍）：均值 **+9.76 mV** 抬起来了，而且与电流的相关掉到 **−0.288**——电阻是乘在电流上的，电流一大，模型就错得更多，所以残差**跟着电流走**。
3. **观测坏**（电压偏 +50 mV）：均值 **+3.99 mV** 也偏，但相关只有 **0.060**——偏置和电流没关系，残差是**一整块平移**。
4. **容量错**（9.5 → 5.0 Ah）：三个数几乎不动（3.64 / 0.01 / −0.062）——有电压观测在，容量误差被兜住了，[电芯建模五天](09-电芯建模五天.md) 第 5 天那张表说的是同一件事。

**相关 ≈ −0.3 对 +0.06**，就是「模型坏」和「传感器坏」在这一列上的分界。看均值和看相关要一起看：只看均值，后两种情形都「偏了」。

**交**　贴输出，并回答：如果电压偏置是 −50 mV，第三行会变成什么样？

**口诀**　跟着电流一起错的，是模型；一整块平移的，是传感器。

**今天你解锁了**　你能用两列数（均值与电流相关）把「模型错」和「传感器错」分开，而不是笼统地说「残差变大了」。

**短自测**　为什么第四行（容量错到一半）反而不喊？

<details>
<summary>先自己答再展开</summary>

因为容量只影响积分的**长期**走向，而电压观测每拍都在把它拉回来——滤波器把「容量不对」这件事推给了估计值本身，而不是留在残差里。反过来说：**残差小 ≠ 参数全对**，它只说明你交给它的观测还能被解释。想把容量也钉住，得换上 [阶段 4 §4.4b](../stages/stage-4-SOC-SOH算法.md) 的在线辨识或专门的低电流标定段。
</details>

**短自测**　第 47 拍新息为什么比第 46 拍小（55.55 对 71.68），明明采样一直停在 4300 mV？

<details>
<summary>先自己答再展开</summary>

因为滤波器在**学习这个错**：第 46 拍的大新息把它自己的状态（SOC 与 RC 电压）往观测那边拽了一点，模型预测随之上移，第 47 拍的对账就小了一截。这正是「持续偏置会被积分进状态」的现场版——所以只看单拍新息会漏掉慢故障，才要 [第 2 天](#第-2-天没有参考值也能判断) 的均值和 [第 3 天](#第-3-天参数坏还是传感器坏) 的相关性。
</details>

温度从 25.0 °C 跳到 65.0 °C，新息**没有出现新跳变**——它沿着上一天看到的衰减继续往下走（39.18 → 29.17 → 22.69 …）。`fault` 那一列倒是当场翻成了 `OT`：**固件看见了，估算器没看见**，因为温度根本不进观测方程。

这也是 `pc_demo` 验收里那条 `innovation_flags_sensor_faults` 只用 `ovp_sensor` 与 `short_sensor` 两段的原因：拿温度段去算「新息有没有喊」是问错了对象。

**交**　贴两段输出，并写一句话：这条边界对你的诊断代码意味着什么。

**口诀**　不进观测方程的量，残差不负责。

**今天你解锁了**　你能说清一个诊断手段**负责哪几个量**，并指出它不该被用来声称什么。

**短自测**　如果想让温度也进入「模型对不上」的诊断，最小改动是什么？

<details>
<summary>先自己答再展开</summary>

把温度放进模型与观测方程：让 OCV、R0、R1 成为温度的函数（查表或插值），再让估算器吃到温度这一路采样。改动之后要注意两件事：一是参数表本身要标定过，否则你只是把一个未知换成另一个未知；二是**「诊断到温度故障」和「诊断到模型失配」又会缠在一起**，得像第 3 天那样再找一个判别量（例如温度通道自身的合理性检查：NTC 断线、短路、开路）。
</details>
