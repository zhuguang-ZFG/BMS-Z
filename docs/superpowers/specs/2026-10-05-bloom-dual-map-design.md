# BMS-Z 布鲁姆双层地图设计（已批准）

日期：2026-10-05  
仓库：https://github.com/zhuguang-ZFG/BMS-Z  
参照：通往 AGI 之路（WaytoAGI）飞书 wiki 式分层导航 + 科研深度

## 目标

把 BMS-Z 改成「布鲁姆能力地图 + 阶段练习场」双层结构；格式对齐飞书 wiki 式目录/分层导航；每节达到「原理 + 证据链接 + 延伸阅读」的科研深度。内容质量优先：该拆该并就拆并。阶段教程、电路详解、`code/` 文档本轮全纳入。

## 顶层：能力地图

- 新建 `docs/stages/bloom-map.md`
- 六层：记忆 → 理解 → 应用 → 分析 → 评价 → 创造
- 每层：1 句 BMS 能力目标、若干入口（阶段小节 / 电路 / code）、1 个自检题
- 映射草案：
  - 记忆：术语、化学、保护名词
  - 理解：BMS 形态与模块关系
  - 应用：保护板实测、PC 配套代码动手
  - 分析：故障叠加、误差预算、协议对照
  - 评价：方案选型与安全边界
  - 创造：毕业项目与共建产出
- README「从这里开始」首条指向能力地图
- `docs/stages/按目标选路线.md` 每条捷径标注对应布鲁姆层

## 练习场：阶段 0–6

- 保留阶段文件为主阅读顺序
- 小节标题加短标签：`[记忆]` `[理解]` `[应用]` `[分析]` `[评价]` `[创造]`
- 混层小节拆开；同层同任务可合并；评价/创造不塞进记忆段
- 编号/锚点变动写入 `docs/stages/bloom-migration.md`（旧 → 新）

## 电路与 code

- `docs/circuits/` 四篇 + README：小节/动画标层，混层拆开，能力地图直链具体入口
- `code/soc`、`code/protocol`、`code/firmware` 的 README 标明主层级（多为应用/分析），并挂到能力地图
- **不**重写算法/固件实现逻辑

## 格式（飞书 wiki 式）

- 顶层目录清晰：能力地图 → 阶段 → 电路 → code
- 每篇长文顶部「本页目录」；统一小节标题；跨文相对链接
- getting-started / 按目标选路线 改成「先选层或目标，再进正文」

## 科研深度（每节三件套）

每节尽量具备：

1. **原理**：机制说明，不只步骤清单
2. **证据**：可点击的 datasheet / 标准 / 论文 / 可核验实验或仿真
3. **延伸阅读**：可选加深（英文标可选）

缺证据：本轮补齐，或标「待补证据」并写入 `docs/共建任务板.md`

## 落地顺序

1. 写入本规格到 `docs/superpowers/specs/2026-10-05-bloom-dual-map-design.md`（若目录不存在则创建）
2. 建 `bloom-map.md`、`bloom-migration.md`、小节模板约定
3. 扫阶段 0–6：贴标签、拆并、补三件套
4. 扫电路与 code README
5. 改 README、getting-started、按目标选路线入口；门户 HTML 仅加能力地图入口（不做视觉大改）
6. 跑现有 CI（links/tests）；修断链；migration 覆盖本轮改动锚点

## 验收

- 零基础可从能力地图选层进入第一节，不必先通读七阶段表
- 每个阶段小节、电路主要小节、三个 code 入口都有明确层级
- 混层已拆或显式「先读/后读」
- 目标小节有原理+证据+延伸（或明确待补）
- CI 绿；migration 覆盖改过的锚点

## 明确不做

- 不改固件/算法代码逻辑
- 不重做门户视觉大改版
- 不建站外问答系统
