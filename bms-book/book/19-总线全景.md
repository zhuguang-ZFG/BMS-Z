# 第 19 章 总线全景

::: story 现场
拆开一台储能 BMS 的盖板，你会同时看到三种“通信”：AFE 与 MCU 之间是板内的 SPI 走线，几厘米；主控与几块从板之间是菊花链，几十厘米；对外端子上挂着一对双绞线，RS485，要穿过整个集装箱去找逆变器。

三种连接的要求不同：板内优先速度，板间关注隔离，对外还要匹配协议与设备生态。
:::

::: chapter-route 阅读路径

- **第一次主线**：读 §19.1–§19.4。先分清板内、板间与对外通信，再认识 UART、RS485／Modbus 和 CAN 的核心差异。
- **第二遍深挖**：读 §19.5–§19.6。补齐 SMBus、BLE、超时、认证与写操作边界。
- **动手验证**：为一个实际接口写出物理层、帧格式、信号映射、刷新周期和失联降级，缺一项就不算“已经接通”。
:::

**先自己判断**　两块设备都带 RS485 接口，是否意味着它们接线后一定能互相读懂？

## 19.1 通信在 BMS 里的三个层级

**表 19-1**　BMS 通信三个层级与典型接口（定性对照）

| 层级 | 连接 | 典型接口 |
|---|---|---|
| 板内 | AFE ↔ MCU | I2C / SPI / isoSPI |
| 板间 | CMU 从板 ↔ BMU 主控 | isoSPI / CAN 菊花链 |
| 对外 | BMS ↔ 上位机/逆变器/整车/手机 | UART / RS485-Modbus / CAN / SMBus / BLE |

第 5、6 章处理板内测量链，第 18 章处理字节成帧。到了对外接口，还要把物理层、帧格式、寄存器映射（或 DBC）分别对上；三者少一个都不能叫兼容。

::: principle 一句话
**物理层、帧、寄存器映射是三件不同的事。** RS485 只是差分物理层，Modbus 才是跑在上面的协议。两者常被混着叫，先分清层，再谈兼容。
:::

## 19.2 UART：商用 BMS 的私有协议

调试口和监控口常使用 UART。各家帧格式不同，但通常包含相近的基本字段：

`[帧头 2B][地址/命令 1-2B][长度 1B][数据 NB][CRC 1-2B]`

这是常见抽象，不是法律：有的协议没有长度字段、有的 CRC 位置不同。**拿到新协议先抓包或读厂商文档确认帧结构，别套模板。** JK 协议的事实文档就是 esphome-jk-bms 的源码与 README：帧格式、命令字、数据偏移、单位换算全在代码里。

- 字节时间 t = 10000/波特率（ms）：9600 是 1.042 ms，115200 是 0.087 ms。波特率越高越贴近 0，但不到 0。
- 衔接第 18 章：帧状态机负责找帧界，CRC 错了要计数并重新找帧头，坏帧不能静默丢掉还不计数。
- 两个动手前的提醒：**先量电平再插线**（3.3 V TTL 还是 ±12 V 的 RS232 电平，插反可能烧口）；**共地要过脑子**：UART 共地意味着电脑和电池包连成一体，笔记本用电池供电、或加隔离 USB 串口，别把市电地引进电池包。

## 19.3 RS485 与 Modbus：储能设备的常用组合

- **物理层 RS485**：A/B 差分、半双工。三个必考点：总线两端各一颗 120 Ω 终端电阻（少了就回波丢包）；偏置电阻让总线空闲时电平确定；方向脚 DE/RE 切换收发。**切换时序是新手第一坑**：切早了丢尾字节，切晚了丢首字节。
- **协议层 Modbus RTU**：功能码记四个就够干活：`0x03` 读保持、`0x04` 读输入、`0x06` 写单寄存器、`0x10` 写多寄存器；帧 = 地址 + 功能码 + 数据 + CRC16（反射多项式 `0xA001`）；BMS 厂商给“寄存器映射表”（SOC 在 `0x0100`、单体 1 电压在 `0x0101`……），照表实现。
- 帧边界靠 **3.5 字符静默间隔**：帧间至少停 3.5 个字符时间，接收端才敢说上一帧结束；帧中间停超过 1.5 个字符时间，这帧作废，不要拿残缺字节去碰 CRC。波特率不超过 19200 时按字符时间算；再高就用规范里的固定间隔。注意方向脚切早切晚丢掉的是首尾字节，和这个静默定时器不是同一件事。

## 19.4 CAN：车辆网络的常用总线

- **帧结构**：ID（标准 11 位/扩展 29 位）+ DLC + 最多 8 字节（CAN FD 到 64）。
- **仲裁**：显性 0 盖过隐性 1，标识符从高位开始逐位比，小的留下；输家自动退出发送，**赢家甚至不知道发生过竞争**，所以叫非破坏性仲裁。BMS 的故障、限功率报文要拿小 ID，单体明细拿大 ID。
- 仲裁只比标识符，不检查载荷；载荷对不对看后面的 CRC。先抢到发言权，再读格子里的数。
- **物理层**：CAN_H/CAN_L 差分，两端 120 Ω 终端；电池包上**必须隔离**（隔离收发器 + 隔离电源）。
- **DBC 文件**记录每条报文里各信号的起始位、长度、因子、偏移和单位。换一家协议，字节位置和比例都可能变化；解析代码必须对着当前 DBC 写。
- **位填充**：连续五个相同位就插入一个相反位。教学示意（不是标准摘录）：500 kbit/s 时一位 2 µs，64 位数据段无填充是 128 µs。最坏情形是每五位就触发一次填充，而填充位本身要算进下一段的连续计数，所以 64 位最多插 1 + ⌊(64−5)/4⌋ = **15** 位，时长拉到 **158 µs**。按 128 µs 排总线，最坏的 158 µs 会挤进下一帧。

GB/T 27930 的直流充电握手也走 CAN。四步依次是：辨识与握手（互报身份、协议版本）→ 参数配置（BMS 报电池类型、总压、允许上限；桩确认能力）→ 充电循环（BMS 周期下发需求电流/电压，桩跟随并回传实测）→ 正常结束或故障中止。工程要点（细则以现行国标文本为准）：

1. **BMS 是需求方**：桩按 BMS 当前允许的电流/电压输出，所以 SOP 与温度降额必须实时写进“充电需求”报文；
2. 对方超时未应答，视为通信失败，**必须停充**，不能“假装还连着”继续灌电；
3. 通信 OK ≠ 可以合接触器，仍要走第 7 章的预充与合闸时序。

储能侧与 PCS 的对接协议各家不同，但“辨识 → 参数 → 周期设定点 → 超时停机”四段骨架高度同构。

::: principle 一句话
车辆先发送充电需求，充电机按协商值输出。需求或状态报文超时后应进入停机流程，不能继续沿用过期设定点。
:::

## 19.5 SMBus 与 BLE：笔记本的与手机的

**表 19-2**　SMBus 与 BLE 的形态、标准化与典型坑（定性对照）

| | SMBus | BLE |
|---|---|---|
| 主场 | 笔记本电池 | 手机 App 监控 |
| 形态 | I2C 物理层 + SBS 标准命令集 | GATT：服务 → 特征值（read/notify） |
| 标准化 | `Voltage()`、`Current()`、`RelativeStateOfCharge()` 等命令字固定 | 厂商私有服务里跑各自的串口透传协议 |
| 典型坑 | 电压原始值不是 SOC | 长帧要协商 MTU + 分包重组 |

- SMBus 细节：`Voltage()` 是 `0x09`，两个字节、单位 mV、低字节在前；7 位地址常见 `0x0B`，先扫再假定；电量百分比是另一条命令，不要把电压原始值当成 SOC。
- BLE 细节：默认 ATT MTU 是 23 字节、有效载荷大约 20 字节；一帧 BMS 数据往往更长，会被切成多条通知，接收端按帧头和长度把片拼回去，超时的半帧丢掉。只连得上却收不到完整数据，先查 MTU 与分包重组。MTU 谈大了片数变少，重组还是要做。

## 19.6 可靠与安全：超时账与上锁清单

板间菊花链断了以后，你等的主要是超时，不是那点飞行时间。教学示意（**不是某颗 AFE 的手册时序，也不是标准摘录**）：t = 2.0 + 0.05k（ms），k 是断点前面还答得上的跳数。第一跳就沉默 2.00 ms，断在第 3 跳之后 2.15 ms，六跳之后才断 2.30 ms。最后一次答得上的节点，就是断点的上游。

> 先自己判断：把这个 2.0 ms 的超时改成 1.0 ms，是不是就能早一毫秒报出断链？

**不能，还会制造新故障。** 按同一条示意式，第 6 跳健康节点的正常应答已经要 2.0 + 0.05×6 = **2.30 ms**，比 1.0 ms 的新门限还长；门限一改短，整条链上活着的远端节点全部会被判死。超时下界由最慢的健康节点决定。断链后停用下游，不能靠缩短超时来补救。

对外通信还必须考虑信息安全。强制性国标 GB 44495-2024《汽车整车信息安全技术要求》于 2024-08-23 发布、2026-01-01 实施；管理体系可对照 ISO/SAE 21434，出口型式批准还会涉及 UN R155。通信安全已经成为产品准入的一部分。

攻击面可从近到远逐层检查：

- UART/RS485 维护口：出厂时锁定，现场服务使用签名令牌，不保留通用密码；
- CAN：报文白名单与网关隔离，控制报文检查计数器，不接受陌生 ID 的写请求；
- BLE：绑定配对，弃用固定 PIN，密钥不得明文写入日志；
- 云端 MQTT/TLS：每台设备独立凭据，固件更新必须验签；
- UDS 刷写口：按会话划分 0x27 安全访问等级，写参数先验身份，镜像同时具备签名与回滚保护。

CAN 帧没有源地址认证。19.4 的仲裁只决定谁先发送；身份、完整性和新鲜度仍要在系统层补齐。物理调试口也在攻击面内：JTAG/SWD 出厂要熔断或加访问保护，否则拆壳后可以绕过上层通信限制。

::: trap 坑
能写进去的口，都要先验明身份；只读的口，也要防着被人灌满。种子-响应算法用固定密钥等于没锁，解锁等级和被保护的写服务没对上等于留后门。
:::

**高压从板与隔离：几十串以上，采样怎么传回主控？**

串数一多，每块从板的参考地都跟着电池堆往上抬，板与板之间出现几十到几百伏的共模差。普通导线把两边地连起来，就把高压引到了低压侧。isoSPI（隔离串行外设接口）用变压器耦合传差分信号，两侧没有电气直连；数据逐级接收、再生、转发，主控只碰隔离后的低压侧。

**沿着这组输入做一遍**

1. 单颗 LTC6811 覆盖 12 串；96 串包按 96÷12=8 颗从板来分。
2. 8 颗从板串成一条菊花链，每级之间都过隔离变压器，共模差留在各自那一段。
3. 核对所选隔离器件、供电和主控接口的额定边界，不能把示意隔离符号当作已完成安全验证。
4. 所以链路长度增加的是转发级数和超时，不是把各地直接连成一张网。

**边界与反例**　变压器与隔离布局都有额定耐压、爬电距离及通信配置要求。没有直流导通不等于可承受任意共模差，必须按适用手册与整机条件核验。

**看图任务**　看红色共模线怎样随串数抬高、蓝色差分线怎样穿过变压器；两侧地有没有直接连在一起。

**对应图解**　[bq769-evb-isospi](../../docs/circuits/assets/bq769-evb-isospi.svg)


**通信分三层：说「BMS 通信」时，到底在说哪一层？**

先问数据正在跨哪一层：板内是 AFE 把测量交给主控，板间是从板把多串读数交给汇总端，对外才轮到上位机、充电机或整车。每层的电平、隔离和故障判据不同。断链时延迟常由等待超时主导，不是线上的传播时间；盲目把超时缩短，会把本来能及时回答的设备误判失联。

**沿着这组输入做一遍**

1. 教学式 t=2.0+0.05k ms 中，2.0 ms 是固定等待，k 是经过的跳数。
2. 第一处沉默约 2.00 ms，三跳后约 2.15 ms，六跳后约 2.30 ms；增加几跳只多零点几毫秒。
3. 沿最后一次成功应答的节点定位断点上游，再分别核对物理连线、等待条件和节点状态。

**边界与反例**　传播预算只在该教学拓扑下成立。降低超时必须有最坏应答时间与调度证据，不能为了报故障快就任意减小。

**看图任务**　把板内、板间、对外三层分别沿一遍，定位断链在哪一层，再比较等待尺与传播尺。

**对应图解**　[daisy-fault-recover](../../docs/circuits/assets/daisy-fault-recover.svg)


**仲裁与DBC解码：仲裁赢了，载荷就一定是对的吗？**

CAN 多个节点同时开始发时，先用标识符仲裁：显性 0 能盖过隐性 1，发现自己发 1 却读到 0 的节点退出，让优先消息继续。这不叫数据互相撞坏。仲裁赢了也不代表载荷真实；后面的校验、应用层身份与新鲜度还要分别查。DBC 则说明字节怎样换算成物理量，不负责决定谁先发送。

**沿着这组输入做一遍**

1. 500 kbit/s 下每位 2 µs，单算 11 位标识符为 22 µs，不能把它当整帧时长。
2. 数据段若有 64 位，不计填充时是 128 µs；教学最坏填充估计再加 15 位，得到 (64+15)×2=158 µs。
3. 158 µs 仍只是这里的数据段量级；排总线还要加入其他字段、帧间隔和重发预算。

**边界与反例**　ID 的数值来自实际协议，不是看到教学 0x180 就认定某厂固定用途。总线调度必须按真实帧格式、填充与负载验证。

**看图任务**　逐位找第一次 0 与 1 不同的位置，看退出的是哪个发送者；再把仲裁段和载荷段分开计时。

**充电握手四段：充电机和 BMS 谁说了算，怎么对上？**

充电不是一接线就送大电流，而是一段段建立共同条件：先确认连接与辅助电源，再辨识协议和设备，交换电池与充电机边界，最后按请求与反馈调整输出。每一步都要能及时等到对方。失联后继续沿用最后一次大电流请求，会把‘曾经允许’误当成‘现在仍允许’。停止和结束也需要明确握手。

**沿着这组输入做一遍**

1. 按正文对应版本区分 BHM/CHM 的辨识、BCP/CTS/CML 的参数阶段，再进入充电中的请求与反馈。
2. 教学周期 BCL=50 ms、CCS=50 ms；若示例允许连续缺失 5 周期，则超时量级为 5×50=250 ms。
3. 超时处理按既定安全时序先降低输出再断主回路，记录缺失的是哪条消息，不做无限等待。

**边界与反例**　250 ms 是给定周期与缺失次数的教学乘法，不是所有版本的统一条文。交流 CP 占空比与这里的直流协议流程不能混作一套。
