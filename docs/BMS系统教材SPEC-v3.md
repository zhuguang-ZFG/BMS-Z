## 1. 为什么需要这次改造

24 课解决的是第一次上手：单位、基本测量、保护、电量账本和软件回放。每课一张独立手绘改善了可读性，但不能证明整个 BMS 知识体系已经讲透。第 24 课仍主要把读者送往 HPPC、EKF、热模型和工程专题，没有提供连续的深入教学。

现有 32 章并非没有深度：测量、RC、HPPC、EKF、热和高压已有推导、脚本与反例。本轮要解决的是**深度材料的先修断层、证据分散、符号差异，以及图只说明局部概念而未支撑完整论证**。不再以新增页数、图片总数、测试总数充当教材质量结论。

### 1.2 继承与覆盖

本规格优先规定后续的知识组织、内容深度、视觉验收和执行顺序。旧 SPEC 的公式保全、事实来源、媒体授权、硬件边界和发布门禁继续有效。W0–W4 历史完成记录不删除；其完成状态不能转移成 v3 已完成。

旧规则要求同一组数字贯穿，适用于**同一个示范算例**；独立练习必须更换条件，答案不得藏在前文插图里。旧图量配额只作为库存下限与工作量记录，不再作为“讲透”验收。具体许可证和产品适用范围以各资产自身记录为准。

## 2. 最终要教会什么

读者面对陌生电芯、采样链、工况或故障时，应能提出模型和假设、计算约束、作出取舍、设计反证，并交出可复核的证据。书本可以支持这些能力的形成，不能授予真实工程资质或保证产品安全。

| 能力层 | 读者可交付的证据 | 不能替代它的东西 |
|---|---|---|
| 基础理解 | 能解释单位、方向、时间、质量及命令/反馈差别，独立改输入回放 | 背术语、运行参考答案 |
| 模型与分析 | 从物理关系推到方程，给单位、离散方法、假设及有效范围 | 只复制最终公式或滤波器代码 |
| 设计与权衡 | 比较至少两种可行方案，用误差、时间、热、成本或诊断约束作决定 | “越精确越好”“越快越安全”等口号 |
| 验证与诊断 | 用未参与拟合的数据、故障注入及独立参考检验设计，解释失败 | 训练集低 RMSE、单次全绿 |
| 工程交付 | 需求、设计、版本、数据、测试与未解决项可追踪，接受独立复核 | 页数、证书式“精通”宣称、模拟台架截图 |

**一段正文只设一个维护源**。D01–D28 是学习单元 ID，不等于必须新建 28 篇重复文章。计划阶段的“复用”表示候选材料；P0 要完成逐段归属，确定重写、提取、保留、废弃或仅回链。一个完整旧章可优先整体复用；跨章组合必须先有稳定块 ID 和去重检查。新增文稿仅承载现有材料确实缺失的内容。

正文产品初期保持现有构建器可用。平台改造必须服务内容交付，不能先投入大规模框架重写，再以“架构完成”代替样章。基础册、完整本、工程深研册的版本、清单、输出前缀与验收报告分别登记。

## 5. 深研单元的内容合同

每个单元在写作前填写讲透卡，并在实现后提供证据。结构检查只查漏项；“有没有讲对、讲清”仍需要领域审读。

1. **问题与任务**：用一个具体观测或设计矛盾开场，写读后能交什么及不能证明什么。
2. **先修入口**：每个首次依赖的数学、器件或代码概念有补课位置和短核对题。
3. **物理对象**：画出端子、参考点、极性、流向和时间，变量分成已测、已知、待估及不可观测。
4. **连续推导**：从关系式到可计算结果；列假设、单位、初始/边界条件、采样约定和近似误差。禁止只摆最终矩阵。
5. **同一设计案例**：需求、参数、图、手算、代码和结论共用一份带 ID 的参数表；中途改变条件必须明示。
6. **方案取舍**：至少比较两种对本问题确实可行的策略，说明一种在哪些条件下更合适。
7. **正常与失败**：最小正确例、边界例、能够暴露错误实现的反例；“出现异常请检查接线”不算失败解释。
8. **独立验证**：用未参与拟合/整定的输入，保存预测、实际输出、指标及不成立的结论；无真值时改为诊断声明。
9. **逐步撤掉帮助**：示范任务给完整过程，迁移题只给输入输出和判据，研究题要求自己设计验证；核对标准默认折叠。
10. **来源与下一步**：技术断言回到具体版本/页节/数据，下一单元使用本单元实际交付物。

字数、页数和图数均记录但不设“达数即过”的地板。过长且承担多个能力时拆成相连单元；过短但完整时不强行补段。不能仅靠相同小标题、表格或关键字让空文通过检查。

### 5.1 每个单元必须走完的十个环节

下表是执行合同，不是要求读者面对十层管理表。实现者把证据放入对应单元任务记录，读者只看到连贯的讲解、图和实验。源稿和登记表使用相同ID；前一环节的产物必须能直接成为下一环节的输入。

| 环节 | 输入与动作 | 必交产物 | 退出门与退回原因 | 责任角色 |
|---|---|---|---|---|
| G01 定义学习问题 | 基础册已有能力、单元先修、实际设计矛盾 | 讲透卡：问题、可交付任务、已知/未知量、能力边界、补课题 | 独立题确实考本单元能力；只列术语、只有“了解/掌握”则退回 | 教学负责人 |
| G02 审读证据 | 开源固定SHA、手册修订、论文/数据身份；追到具体实现和反例 | 来源表、断言台账、许可/条件、采用和不采用理由 | README主张与实际实现区分；关键事实无来源则保持gap，不能借项目名背书 | 领域负责人 |
| G03 推导与参数冻结 | G01任务、G02事实；由物理关系逐步到离散与计算 | 推导链、单位/方向表、参数配置、解析锚点、有效域 | 单节/整包、正负、初值、时间侧不含糊；假设变更必须新场景ID | 领域负责人，另一执行者复核 |
| G04 最小可复现基准 | 冻结配置和解析式；从最少依赖实现正常工况 | 参考实现、环境、输入摘要、逐拍输出、命令、解析误差报告 | 从空输出目录独立重跑；输出不能充当自身唯一答案；上游静态阅读不能标复现 | 实验负责人 |
| G05 反例与不确定性 | G04基准；挑一项常见错误、边界或失配 | 错误方案/故障注入、预期失败原因、适用域/不确定性说明 | 错误实现必须被合理判据拒绝；不能只检测异常有没有抛出，也不强求不存在的普遍优劣 | 实验与领域负责人 |
| G06 图文共同制作 | G03物理关系、G04/G05轨迹、逐节理解障碍 | 机制草图→技术定稿→图源/成品；配套正文、图注和观察任务 | 电路连线、方向、时序和数据同一身份；每张图回答具体问题，文字卡不冒充机制图 | 内容/视觉负责人按资产所有权并行 |
| G07 撤去提示后的迁移 | 已解释的示范；改变输入/器件/工况 | 独立任务、提交模板、判据、分级提示、折叠核对标准 | 不读取参考输出也可完成；新条件超适用域时正确答案可以是“证据不足” | 教学与实验负责人 |
| G08 交叉技术审查 | G02–G07完整包 | 逐项审查记录：公式/图/代码/数据/边界、发现与修改 | 解决实质错误再标本地通过；记录审阅者身份，另一个AI不等同真人试读或具资质工程评审 | 未负责该实现的审阅角色 |
| G09 阅读与出版核验 | 同一真源、明确产品清单、最终尺寸图 | 手机/桌面/纸面检查、静态HTML/PDF/EPUB、检索与链接证据 | 读者可从图文走到独立题；裁切、缺字、公式错误、离线缺答案或不可检索即退回 | 出版/集成负责人 |

### 5.2 开源审读如何变成教学

本轮实际审读9个专业项目，固定版本和文件见[开源研究记录](superpowers/plans/2026-11-08-bms-open-source-research.md)，并对照NASA数据、公开课程和一例社区缺陷。每个采用项都必须落到具体D/B/R单元与实验ID；仅增加链接不算采用完成。

审读次序是“读者问题→原理/假设→配置入口→一条数据/动作链→失败路径→对应测试→本地最小反例”。开源工程中能运行的默认值不直接成为教材标准答案；例程的拟合图、容量字段、反馈字段或认证标志不自动证明独立验证、SOH估计、物理分断或产品安全。未读的代码链和未跑的例子按范围留白。

基础段保留标准库与可手算基准；PyBaMM/PyBOP等用于后续模型层级、参数优化及研究支线，使用单独冻结的环境。各库的README、代码、参数集、数据和媒体分别核对许可；本轮借方法与实验设计，不移植上游课文、图像或代码。

## 6. 插图体系与视觉验收

### 6.1 五类图各负其责

| 图类 | 适用问题 | 交付要求 |
|---|---|---|
| 手绘机制/剖面 | 电流、电子/离子、热、传感和驱动怎样作用 | 画对象与真实关系；适度手绘线条，电路连接点必须明确，不能把文字装进框就叫机理图 |
| 电路/系统结构 | 拓扑、端子、隔离、责任与接口 | 标节点、电位参考、器件方向、信号类型；网络连线可追踪；Mermaid 适合状态/流程，不替代准确电路符号 |
| 连续帧/时序 | 瞬态、保护、通信、预充与恢复 | 关键阶段一帧一变化，所有泳道共用时间基准；离线有完整静态序列 |
| 科学数据图 | 参数、误差、观测性、热、拟合与验证 | 从代码/数据生成，轴/单位/采样/工况齐全，保留原数据与生成命令，区分合成与实测 |
| 实物/仪器证据 | 器件识别、测点、接线和真正执行过的验证 | 作者、许可、对象身份与测量配置；裁剪不创造新证据，示意不能冒充实拍或示波器截图 |

每个深研单元的配图规划必须逐节指出哪些问题需要上述证据。通常需要机制、过程、结果和失败对照等多个图点，不能沿用“一章一张即完成”。工作量估算可按每单元 3–6 个独立图点准备，复杂单元另拆；复用前先核对数字、拓扑、符号和用途，同一图只按一份资产计数。

长文按 400–800 字巡检视觉断层；相邻图应由完整解释小节连接，原则上有约 400 字上下文，连续超过约 1200 字的抽象推导要评估增图或拆节。连续帧属于同一个图组，不为了间距填充无用文字。特殊的短实验/同轴对照可说明例外；验收以理解需要为先。

### 6.2 统一视觉语言

- 机制图延续暖纸、深墨和普鲁士蓝的手绘语言。结构主色蓝，正常有效状态青绿，比较/不确定性赭橙，失效/禁止朱红；每种状态另有文字、线型或图标，灰度可辨。
- 画风与图型登记沿用 handraw-style 的规范；按实际查到的 canonical ID 记录，不能凭名称猜编号。规划可选中心标注 IG-002、对照 IG-004、流程 IG-008，需核对实际库定义；科学图记录图表类型与生成器，不强套海报图型。
- 手绘线条不改变物理连接和数值位置。电路允许直线；不用随机抖动破坏箭头、波形或比例。
- 中文为主，必须保留的芯片脚名、变量和协议字段保持原文。每张图有明确问题、alt、图注、观察任务和正文锚点。图内不塞整段课文。
- 先绘构图草图，再核对物理，再输出成品。需要生成式画面时保留提示词、工具与来源；没有可用生图通道时标注实际矢量制作方式，不把程序绘图宣传为人工实拍/实绘。

P1先用一套可检查的试版色：纸底`#FFFDF5`、正文/结构`#003153`、有效状态`#176B64`、比较/不确定`#8A5019`、禁止/失效`#A3322A`。四种前景在纸底上的WCAG对比度计算约为13.18、6.20、6.36、6.77:1。现有亮朱红`#E34234`在该底色约4.05:1，可保留作粗线/大标记，不用于普通小字；图内小字以深色为主。以上是本项目试版色值，不冒称官方画风库编号；画风/图型正式编号在制作时从实际库核对。

配色定稿须查看真实图：深浅主题分别核对，状态不只靠红绿区别，灰度仍可按线型/标签读懂。正文用清晰中文正文字体，手写感主要来自对象轮廓、批注和箭头；公式、数据轴、单位与长说明使用易辨认的排版。先用S1信号链、S2等效电路和S3功率回路验证这套语言，再扩到全书，不能先批量生成后补救小字和弱连线。

### 6.3 成品图门禁

每张图应经过技术正确、图文一致、读图任务及终端显示四种检查。手机在 390/820 px 验证，必要时把密图拆为多个可连续阅读面板；不得靠放大整图才能首次看清关键文字。目标主标签不低于约 14 CSS px，辅助不低于约 12 CSS px；低于目标需拆图或有明确可访问的等价说明。PDF 按最终版面实测，关键标签目标至少 9 pt，栅格彩图目标至少 300 ppi；矢量科学图优先。

自动检查覆盖源文件、导出摘要、实际引用、文字边界、缺图、裁切、图注与答案泄露；人工逐图检查电流方向、极性、数量级、连接点、时间轴、对应关系和颜色含义。图片存在、尺寸够大或摘要正确不能替代这次审读。

## 7. 数值、模型、代码与数据合同

### 7.1 统一符号与时钟

新深研读者侧统一**放电电流为正**，SOC 使用 0–1，明确 pp 表示百分点；Ah 与秒换算显式含 3600。旧 `code/soc` 充电正的接口先保留并登记转换：`I_legacy = -I_course`，一阶极化变量按各模型定义作对应转换，不只翻一条公式。

每个模型头部列单位、状态含义、输入采样位置、状态更新时间和输出时刻。例如 `I[k]` 作用于 `[t[k], t[k+1])`，状态更新使用该区间，端电压对应哪一侧必须明示。样本时间、接收时间、本地判断时间、命令时间、反馈时间分别留存。

规则不能混用：基础课程的连续 0.20 s 确认与旧书的连续三拍是不同参数化策略，示例必须标 `scenario_id`。整包与单节量、名义容量与当前容量、温度点、初始 SOC、化学体系和数据来源均不可隐式切换。

### 7.2 实验接口

计划为新实验提供 `--config`、`--out` 和明确的参考/学员模式；最终命令在实现后冻结，计划中的示例不得写成当前可运行命令。输出目录不覆盖已有证据。基础实验尽量标准库；矩阵优化、高保真电化学等需要 NumPy/SciPy/PyBaMM 时使用独立环境，列版本、安装和最小自检。

一个合格证据包至少包括：输入/配置与摘要、实现版本、来源与处理记录、单位/符号、真实命令与环境、逐拍数据、汇总指标、失败原因、未验证项和重跑步骤。输出划分 `synthetic_truth`、`observation`、`reference`、`prediction`；真实数据无独立真值就不生成 `ground_truth_soc` 名称。

参考实现与学员作业分开。回归测试包含解析锚点、守恒或单调性等物理约束、非法输入、独立留出工况，以及至少一个错误实现应失败的样本。不得让出图脚本自身输出同时充当唯一正确答案。

### 7.3 事实与来源台账

借鉴参考项目的 claim ledger，计划登记 `claim_id / block_id / kind / value / units / conditions / source / revision / evidence / status`。`kind` 区分文献事实、推导、教学参数、合成结果、实测结果和工程建议。高风险断言优先登记：电芯限值、器件 SOA、诊断覆盖、延迟上界、精度、SOC/SOH 真值与安全符合性。

厂家手册、标准、论文和开源项目各按其证据能力使用：标准记录版本与条款；硬件记录料号及手册修订；代码钉提交；真实数据记录电芯/循环/温度与许可。社区个案用于发现问题和设计反例，不能代替普遍性证明。资料打不开或授权不清时标待核对，不能编写“来源已验证”。

## 8. 出版、导航和搜索约束

工程册计划采用自己的 manifest、稳定单元/段落 ID 和 `bms-engineering` 前缀。基础 24 课的旧约束继续回归；不能把 24 改成“任意数量”来掩盖产品混用。正文重排保留公开锚点或静态迁移入口；术语、图、claim、实验以 ID 互链，避免按行号追踪造成漂移。

所有离线格式从同一真源装配，包含静态图、公式、完整题目与核对标准；关键阅读不依赖脚本、外链字体或网络。交互可作为增强，必须有静态实验轨迹。按册输出 HTML/PDF/EPUB，封面和报告准确标身份及实现范围，局部样章不标成完整工程册。

**搜索是主站集成与批量扩写的阻塞项**：当前预算剩余约 15.5 KiB。P1 允许在工程真源的未发布分支/独立样章装配中制作和预览，尚不接入主站索引；P2 搜索门通过后，才能合入主站教学导航、交付整站或开始 P3–P6 批量扩写。先审重复索引、规范页和可延迟加载分片；必须保持所有学习页可检索、中文句中关键词命中和离线索引可用。不能把新深研页设 `search:false` 或直接抬限让门禁变绿。若优化后实际需求仍超预算，提交有测量数据的预算变更记录，同时评价首次加载、查询延迟、移动内存与总索引体积。

读者检索与治理文档分别处理：本 SPEC、计划和审计记录设 `search:false`；真正教学正文不能因此被隐藏。

## 9. 工程项目与迁移考核

| 项目 | 必须交付 | 独立迁移与拒收条件 |
|---|---|---|
| C1 测量链设计 | 需求、误差模型、校准/验收分离、滤波与扫描预算、开线诊断方案 | 换通道数/温度/故障相位仍能解释；上界当σ、均值替代缺失单节或无原始记录即拒收 |
| C2 电芯模型与估计 | 数据划分、基线、HPPC 参数、SOC 与不确定性、失配和无真值说明 | 留出电芯/工况、未知偏置/容量变化；用自身估计做真值、只报告训练误差即拒收 |
| C3 功率路径与保护 | MOS/接触器路径、预充能量、动作窗口、独立保护、反馈失效与恢复 | 加重复脉冲、未知初始母线、焊死/拒动及丢反馈；仅凭命令宣称安全即拒收 |
| C4 系统交付 | 将 C1–C3 接入固件/通信/日志，形成需求、版本、测试、残余风险与证据索引 | 由未参与实现者改一组条件重跑；缺版本、结果覆盖、失败被删除或跨平台不可复核则退回 |

每类交付区分 `software_verified`、`hardware_pending/verified`、`reader_pending/verified`。PC 实验不是 HIL；含模拟器但无真实控制板不得写“BMS 在环”。具备场地、仪器、适格人员和停止条件前，硬件部分可交完整试验方案，实际执行状态仍为待验。

W5 使用真实读者背景、作答、卡住原话和作品，样本数量及任务沿用既有试读合同；不把模型自行解题视为真人效果。7 项专项照片继续按原缺口身份验收，通用素材或新插图不能抵扣。

## 10. 状态、完成定义与范围控制

状态使用 `planned → drafting → technical_review → locally_verified → reader_pending / hardware_pending → accepted`，发生实质问题可回到 `gap`。数字教材的仓库交付与外部实测验收分别报告，不以一个总勾选隐藏尚缺证据。

一个单元可标“本地交付”须同时有：完整正文、正确图版、可重跑实验、独立题与判据、来源台账、技术审查、相关自动检查、最终版式核验，以及明确外部待验项。人工审查留具体改动和发现，不接受一行“看过无误”。整本收口还需目录/先修/跨章符号、失败案例和综合任务连贯。

本轮只建立以上合同与执行计划。后续按稳定任务 ID 推进，新增工作要说明修复哪个缺口、依赖什么、怎样证明完成；不得临时以继续补图、继续涨页数替换计划。发现新的严重事实错误优先修复并回写台账，不等待整本出版。
