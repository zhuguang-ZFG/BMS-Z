# BMS-Z 项目改造计划

> **目标**　把“资料很多”升级成“零基础能跟住、学完能复述、动手能验证、出错能定位”的完整学习产品。
>
> **起始日期**　2026-10-30。先做一个跨媒介试点，再批量推广；现有内容、链接和出片流水线继续保留，不推倒重来。

## 一、先解决什么

BMS-Z 已经拥有 32 章伴读书、七篇阶段教程、154 张动画电路图、八集视频、配套代码和练习。下一阶段的主要矛盾不再是“内容不够”，而是以下四件事：

1. **同一知识在不同媒介里各自完整，却缺少统一入口。** 初学者不知道该先看书、动画、视频还是代码。
2. **长内容一次承载太多概念。** 阶段 0、阶段 4，以及第 1、5、7 集都很扎实，但第一次接触时认知负担偏高。
3. **现有质量门偏工程正确。** 数字、链接、图号、音画和构建守得很严；“有没有先讲直觉、是否围绕一个问题、读者能否自己推一遍”还没有统一检查方法。
4. **书、动画、视频、代码之间缺少概念级真值。** 数字已有多处钉死，但“这个概念由哪一章解释、哪张图演示、哪段视频讲、哪个实验验证”仍靠人工记忆。

## 二、改造后的产品结构

项目保留现有七阶段主线，但把内容分成三层。读者不必一次吃完整套。

| 层级 | 回答的问题 | 典型长度 | 主要载体 |
|---|---|---:|---|
| 先懂 | 这件事为什么发生？ | 2–5 分钟 | 微视频、单张动画、生活类比 |
| 会算 | 数字怎么一步步得到？ | 10–30 分钟 | 阶段教程、书中算例、PC demo |
| 会做 | 怎样验证、诊断和交付？ | 30–120 分钟 | 实验、挑战、共学、工程清单 |

每个核心概念最终都要形成一条闭环：

> 一个现场问题 → 一个直觉图景 → 一个最小模型 → 一笔数字账 → 一个反例或边界 → 一次自测 → 一个可运行实验

## 三、统一教学骨架

书、阶段教程、动画和视频统一采用“六步讲透法”，详细规则见[教学设计规范](教学设计规范.md)。

1. **先问问题**：从真实场景开始，不先扔定义。
2. **先给直觉**：用可记住的图景解释变量在做什么。
3. **再上模型**：公式只回答刚才的问题，每个符号先有物理身份。
4. **算一笔账**：使用同一个具体输入从头算到尾。
5. **故意撞边界**：展示常见误解在什么条件下失效。
6. **让读者取回**：合上答案，自己判断、复述或运行实验。

## 四、分阶段改造

### 阶段 A：建立基线与试点

范围：第 1 章、阶段 0、第 1 集，以及它们共用的动画。

- 用“带载为什么掉压”作为贯穿案例，统一书、教程、动画、视频的术语和数字。
- 第一次阅读路径只保留必须概念；固态、钠离子、接口等扩展知识下沉到“继续深挖”。
- 把第 1 集保留为总课，同时拆出 3–5 条单问题微课。
- 每个试点单元补三道取回题：判断、计算、边界。
- 用 `python tools/learning_audit.py` 记录改造前后的篇幅、段数、版式和练习密度。

**通过标准**：陌生读者看完后，能不用原文解释“电量没突然消失，为什么电压会掉”，并能完成一笔 `I × R` 压降计算。

### 阶段 B：重做学习入口

- 首页只保留三个选择：零基础开始、按目标选路线、查一个问题。
- 新增核心问题地图，例如“为什么会过充”“电压为什么会骗人”“SOC 为什么会漂”“保护为什么要延时”。
- 每个问题页同时给出：2 分钟解释、书中深读、动画、视频片段、可运行实验。
- 清楚区分主线、选读和参考资料，避免读者把资源索引当作必修课。

**通过标准**：新读者不看 README 全文，也能在三次点击内进入适合自己的第一课。

### 阶段 C：书籍分层改写

- 每章开头增加“读完只需带走的一句话”和“先自己判断”。
- 长章拆成“主线正文 + 深挖盒子”；第一次阅读不被推导细节打断。
- 公式前固定补三件事：它在算什么、输入从哪来、结果错了会怎样。
- 每章只留三类练习：概念判断、手算一题、工程边界。
- 章末增加跨媒介入口，不重复正文摘要。

优先顺序：第 12、14、24、27 章，其次是第 1、7、30 章。

**通过标准**：主线阅读时每 800–1200 字至少出现一次图、表、算例、问题或实验中的一种；长推导均可跳过而不破坏主线。

### 阶段 D：动画从“会动”升级成“会解释”

- 一张动画只解释一个因果变化，标题直接写问题或结论。
- 先出现最简单的真实图，再一次只增加一个部件；不把完整图一次性扔给读者。
- 运动必须表现证据：电流去哪、状态怎样变、阈值何时越过；装饰性闪动不算解释。
- 每张图配一个观察任务和一个暂停帧问题。
- 保留静态可读版本；不播放动画也能理解结论。

**通过标准**：关掉图说，只看动画仍能说出“谁变了、为什么变、结果是什么”；关掉动画，只看静态图和图说仍能学会。

### 阶段 E：视频重构为“总课 + 微课”

现有八集继续作为系统总课，不废弃。新增长尾友好的微课层：

- 每条 2–5 分钟，只讲一个问题，围绕一个具体例子从头走到尾。
- 开头两秒直接出现故障、现象或问题，不先报幕。
- 屏上文字只给关键词、数字和步骤，不逐字复述旁白。
- 减少纯 `card` 版式；优先使用会逐步生长的图、连续变形和完整算例。
- 一条微课结束只留一个结论，不再塞整章验收清单。
- 总课负责建立全景，微课负责讲透，短切片负责引发问题，三者不互相冒充。

首批建议：

1. 满电一拧把为什么掉两格？
2. 4.2 V 为什么不等于充满？
3. 保护点为什么不是危险点？
4. SOC 为什么越积越漂？
5. SOP 为什么永远听最短的那块板？

**通过标准**：每条微课能用一句话写出唯一学习目标，并至少有一个输入贯穿到最终答案。

### 阶段 F：练习与反馈闭环

- 每个概念增加“看前判断—看后再答—动手验证”三联题。
- 错题按原因归类：概念混淆、单位错误、符号错误、条件漏写、证据不足。
- 共学任务从“读完打卡”改为“交一份可复算产物”。
- 作品墙优先展示过程证据、失败复盘和修正，不只展示漂亮结果。

**通过标准**：每个阶段至少有一个无需硬件、可在 PC 上完成并由脚本判定的结课任务。

### 阶段 G：内容工程化

- 建立概念清单，给核心概念稳定 ID，登记书、教程、动画、视频、代码的对应关系。
- 数字、公式口径和来源由同一份数据驱动，避免跨媒介漂移。
- 现有构建门继续守“正确”；新增教学审计守“是否过载、是否只有卡片、是否缺自测”。
- 教学审计先只报告，不立刻卡 CI；规则经过一个试点周期后再逐条转成硬门。

## 六、不做的事

- 不为了“更短”删除必要条件和安全边界。
- 不把整本书改成口号、口诀或卡片集合。
- 不为了换技术栈重写已经稳定的 SVG 和 Python 出片流水线。
- 不在没有读者试验前，把主观审美直接做成全库硬门。
- 不把示例阈值包装成可直接上板的产品参数。

这轮改造的判断标准只有一个：读者是否更容易建立因果链，并能自己把它重新推出来。
