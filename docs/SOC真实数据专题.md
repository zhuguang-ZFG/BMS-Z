# SOC 真实数据实验：先标定，再用独立工况检验

> **本篇你会学到**　怎样读取真实电池记录、统一电流方向、辨识参数，并分清“计算参考 SOC”和“独立测得的真值”。
> **预计用时**　跑通约 20 分钟，读图与完成参数实验约 1–2 小时。
> **前置**　跑通过 [SOC 合成对比](../code/soc/README.md)，理解一阶 RC 与 EKF。

本实验使用 NASA RW3 的实测时间、电流、电压和温度。**数据没有独立测得的 SOC 真值。** 下文 SOC 误差均相对于计算参考，不能据此宣称实际电池的绝对 SOC 精度。

## 1. 离线运行

在仓库根执行：

```bash
python -m pip install -r code/requirements.txt
python code/soc/real_data.py --plot
```

Windows 也可用 `py -3` 代替 `python`。随仓库提供的小样本已完成确定性格式转换，运行不联网、不需要 MATLAB，也不需要 scipy。

结果写入 `code/soc/real-data-output/`：`calibration.json` 记录标定参数，`trace.csv` 记录逐点结果，`report.json` 记录来源与指标，`comparison.png` 同时画出 SOC、电压与电流。

命令退出码 0 表示数据校验与计算完成，**不表示误差达到产品标准**。曲线不好看也是实验结果，不应通过删除样本来把它变成“通过”。

## 2. 数据来自哪里

来源：[NASA PCoE 数据目录](https://www.nasa.gov/intelligent-systems-division/discovery-and-systems-health/pcoe/pcoe-data-set-repository/)中的 Randomized Battery Usage，以及 [Zenodo 固定记录 15277374](https://zenodo.org/records/15277374)。记录许可为 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。

署名：Brian Bole、Chetan Kulkarni、Matthew Daigle，NASA Ames Research Center。原始归档要求引用其 2014 年论文 *Adaptation of an Electrochemistry-based Li-Ion Battery Model to Account for Deterioration Observed Under Randomized Use*。

本仓库从 `RW3.mat` 选择完整步骤，保留全部采样；没有把仿真值混进原始测量。每行带有从 0 开始的 `source_step`、`source_sample`，可追溯到源文件。具体选择、原始文件哈希和转换说明都在 [metadata.json](../code/soc/data/nasa_rw3/metadata.json)。

| 分组 | 原始步骤，从 0 开始 | 样本数 | 用途 |
|---|---|---:|---|
| `ocv` | 0 | 19120 | 0.04 A 低电流放电，构造准静态 OCV 曲线 |
| `capacity` | 2 | 725 | 参考放电，标定该条件下的容量 |
| `pulse` | 5、6、7 | 3003 | 静置、约 600 秒放电脉冲、再静置，辨识一阶 RC |
| `validation` | 32–49 | 2613 | 后续随机负载，只做回放与评价 |

**先划分，再拟合。** 标定函数只读前三组。随机负载的电压与温度不参与拟合；测试会把验证组全部替换成 NaN，确认标定结果不受影响。但这仍是同一颗电芯早期的一次留出工况验证，尚未跨电芯、跨寿命阶段或跨环境温度验证。

## 3. 数据整理的四个关键点

**电流方向。** 源数据放电为正，仓库约定充电为正。转换器对源电流取负；例如原始 +4 A 放电，CSV 中写成 −4 A。

**时间。** `relativeTime` 会在每个步骤重新开始，不能直接拼接。本实验按源文件的全局 `time` 排列，在每组内减去第一条时间戳，保留步骤间的真实间隔。第一条观测的累计电量为零。

**积分。** 按相邻采样的真实时间差做梯形积分。进入 EKF 时，区间平均电流用于状态预测，电压采样时刻的瞬时电流用于欧姆压降。这样负载切换处不会混用两种电流。

**异常处理。** 运行前检查 CSV 的 SHA-256、列名、样本数、有限数、电压单位、电流方向与时间递增性。损坏文件直接报错，不自动排序、补值或换单位。对自己的数据清洗，应另存结果并记录变换过程。

## 4. 参数怎样得到

容量由 `capacity` 组电流积分得到，默认约 **2.009 Ah**。低电流组自己的积分容量约 **2.119 Ah**，两者对应不同测试条件，本实验保留这个差别。

准静态 OCV 表由低电流放电构造：以该组积分电量归一化 SOC，在 21 个 SOC 点插值并做单调约束。**它是低电流端电压近似，不是充分静置后直接测得的 OCV 表**；低电流容量与参考放电容量不同，也会影响 SOC 坐标的一致性。

RC 参数来自独立的长脉冲：

1. 脉冲开始和结束时分别算电压跳变量除以电流跳变量，再取平均估计 R0。
2. 对后续静置电压拟合 `K + A·exp(−t/τ)`；复用 [hppc_demo.py](../code/soc/hppc_demo.py) 的网格搜索与最小二乘，搜索范围为 1–1000 秒。
3. 按脉冲实际时长修正幅值，得到 R1，再算 C1 = τ/R1。

默认约得 R0 = **82.0 mΩ**、R1 = **49.1 mΩ**、τ = **73.5 s**。R0 起始沿与结束沿分别约 87.0 和 77.0 mΩ，说明单个常量只是近似；不应把平均值写成该电芯所有 SOC 和温度下的参数。

这组脉冲约 600 秒，**不是合成示例的 10 秒 HPPC**。本轮只标定了一个较高 SOC 工作点的一阶参数，未形成完整的 SOC–温度参数表。

## 5. 计算参考与默认结果

随机负载前的源步骤 31 是满充记录，末端电压 4.2 V。本实验假定验证起点 SOC 为 1，用原始测量电流和前面标定的容量计算：

$$SOC_{ref}(t)=1+\frac{\int_0^t I(\tau)\,d\tau}{3600Q_{cal}}$$

这个参考使用了与估算器相同的测量电流，也依赖容量和满充边界假设，因此会共享测量误差。它适合比较初始误差和模型失配，不能独立证明真实 SOC 精度。

三个估算器的初值统一为 0.9，容量统一取约 2.009 Ah。默认没有额外加入电流偏置。EKF 的电压观测方差固定为 `(0.020 V)²`，没有用验证数据自动寻优。

在随库数据上运行，四舍五入得到：

| 估算器 | 相对计算参考的 RMSE，百分点 | 末端误差，百分点 |
|---|---:|---:|
| 纯安时积分 | 10.00 | −10.00 |
| 原教学 OCV 和 RC 参数的 EKF | 20.74 | −5.54 |
| 独立标定 OCV 和 RC 参数的 EKF | 4.92 | +6.19 |

RMSE 按时间加权，避免采样密集的片段自动获得更大权重。这里 4.92 是**相对计算参考的 SOC 百分点**，不是独立的电池精度指标。

电压诊断也值得看：将计算参考 SOC 输入开环模型，原教学参数的电压 RMSE 约 **186.3 mV**，标定参数约 **21.8 mV**。这一项使用未加扰动的标定参数和原始电流，是模型一致性检查；同样依赖计算参考，不是盲测得到的 SOC 预测。

**无真值时，滤波器自己会喊吗。**上面的指标都对着计算参考算——场上没有参考 SOC 时，`report.json` 的 `diagnostics` 一段是无真值口径：只收 EKF 每步的电压残差（新息），统计与 RMSE 同样按时间加权。原教学参数的新息 RMS 约 **15.1 mV**，标定参数约 **3.7 mV**，参数坏没坏，不用真值也听得出来。但有两个不能误读的地方：其一，两者的新息均值都接近零（−0.3 对 0.5 mV）——EKF 会把静态模型误差吸进 SOC 状态，**残差体面不等于 SOC 正确**，对照上表 20.74 对 4.92 个百分点；其二，NIS（新息平方除以滤波器自报的方差 S=C·P·Cᵀ+R，含不确定度 P；P 收敛后 S≈R）均值 0.53 对 0.03，都低于 1，说明 20 mV 的 R 假设偏保守——NIS 接近 1 才算新息与自报方差相符，低于 1 只是「设松了」，不是「滤波器完美」。

**三个读图问题：**

- 原参数 EKF 为什么可能比纯积分差？电压校正遇到不匹配的 OCV 和内阻，会把状态推向错误方向；滤波器名称不保证结果。
- 为什么截止时计算参考仍约 13%？负载下电压达到截止值，并不等于按参考容量计算的电量恰好归零。
- 为什么标定后仍有误差？验证段实测温度约从 21.7°C 到 36.8°C；本模型没有温度补偿，只用了单个 SOC 点的 RC，还有准静态 OCV 与容量基准差异。

## 6. 亲手改变三个条件

```bash
python code/soc/real_data.py --initial-soc 0.6 --out .tmp-rw3-initial --plot
python code/soc/real_data.py --current-offset-a 0.02 --out .tmp-rw3-offset --plot
python code/soc/real_data.py --resistance-scale 2 --out .tmp-rw3-resistance --plot
```

每次先写预测，再对照 `report.json` 与曲线：

1. 初始值错得更大时，哪条曲线会保持偏差，哪条可能靠电压恢复？
2. +20 mA 偏置会把 SOC 往哪个方向推？参考曲线用原始电流，偏置只加在估算器输入上。
3. 把标定 EKF 的 R0、R1 同时乘 2，在哪些负载处影响更明显？这也改变了 R1·C1；扰动只作用于标定 EKF，电压诊断保留原模型。

交付内容：命令、报告、图、预测和差异解释。不要只挑最好看的一次，也不要拿这段验证数据反复调参后继续称为独立验证；调参后需另选新的验证工况。

## 7. 从原始 ZIP 重新导出

日常运行可跳过这一节。需要复核来源时，按 [固定数据记录](https://zenodo.org/records/15277374)下载 `2. Battery_Uniform_Distribution_Discharge_Room_Temp_DataSet_2Post.zip`，再执行：

```bash
python -m pip install scipy
python code/soc/prepare_nasa.py --archive path/to/archive.zip --out .tmp-rw3-rebuilt
python code/soc/real_data.py --data .tmp-rw3-rebuilt --out .tmp-rw3-verified
```

源 ZIP 的 MD5 为 `aa53dce833e0ce7ee75376846dec4e59`。转换器先校验归档，再读取指定 MATLAB 成员，不向磁盘展开整个 ZIP。输出 CSV、源成员和原始归档的 SHA-256 都记录在元数据中。再导出的 CSV 哈希应与随库版本一致。

## 8. 验收与边界

- 能指出原始测量列、标定参数和计算参考各是什么。
- 能说明为什么步骤局部时间不能直接拼接。
- 能从一个原始步骤重新得到容量或 R0，并核对单位与电流方向。
- 能解释标定后改进和残余误差，知道下一步需要哪些额外测量。
