# 共学：电芯建模五天

> **本篇你会学到**　仿真里那颗「真值电芯」是怎么写出来的：一条 OCV 曲线为什么长这样、`dOCV/dSOC` 为什么被 EKF 当成观测矩阵、R0 与 R1 各自的压降差在哪、`exp(-dt/τ)` 这个离散递推凭什么等价于连续世界，以及**参数写错哪一个会当场崩**。
> **预计用时**　5 天，每天大约 30–60 分钟。
> **前置**　做过 [SOC 五天](01-soc五天.md) 或读过 [阶段 4 §4.4](../stages/stage-4-SOC-SOH算法.md)。装好 Python 3.10+，在仓库根 `pip install -r code/requirements.txt`。不接电池。

⚠️ 本篇的「电芯」是**解析函数**，不是任何一颗真电芯：`code/soc/cell_model.py` 用 3.2 V 平台加两端 tanh 抬头生成 OCV，再叠 R0 与一阶 RC。量级取自 18650 NCM 的典型范围，数值是合成的。它教的是「模型里每个符号对应哪一段电压」，不是某颗电芯的规格书。

## 第 1 天：一条 OCV 曲线的四项

**读**　[阶段 4 §4.3 OCV 法](../stages/stage-4-SOC-SOH算法.md) 与 §4.4 的开头：OCV 是「荷电的尺子」，问题是它经常够不着——要等静置、要过平台。

**看**　[铁锂平台示意：dV/dSOC 与噪声换算](../circuits/assets/ocv-plateau-distrust.svg)。它的图说点明了生成方式：**平台斜率加两端 tanh 抬头**——正是今天要读的那四项。

**看码**　`code/soc/cell_model.py` 第 16–24 行：

```python
return (
    3.2
    + 0.8 * soc
    + 0.20 * np.tanh((soc - 0.05) * 30.0)
    + 0.05 * np.tanh((soc - 0.90) * 15.0)
)
```

四项各管一段：常数 3.2 是**基准项**（另三项都叠在它上面），`0.8 * soc` 是中段斜率，`0.20 * tanh(...)` 负责**低 SOC 抬头**，`0.05 * tanh(...)` 负责**高 SOC 抬头**。注意 3.2 不是「0% 那一端的实际电压」——`soc = 0` 时低 SOC 抬头项取到它的下限 −0.20，实测 OCV 是 **2.9690 V**（就在下面第 1 条命令的输出里）。

**跑**（仓库根，把四项拆开对账）：

```bash
cd code/soc && python3 -c "
from cell_model import ocv
import math
s = 0.5
terms = (3.2, 0.8*s, 0.20*math.tanh((s-0.05)*30), 0.05*math.tanh((s-0.90)*15))
print('3.2 + 0.8*0.5 + 0.20*tanh(13.5) + 0.05*tanh(-6.0)')
print('= %.4f + %.4f + %.4f + %.4f = %.4f' % (*terms, sum(terms)))
print('ocv(0.5) = %.4f' % float(ocv(0.5)))
"
```

2026-10-09 输出：

```text
3.2 + 0.8*0.5 + 0.20*tanh(13.5) + 0.05*tanh(-6.0)
= 3.2000 + 0.4000 + 0.2000 + -0.0500 = 3.7500
ocv(0.5) = 3.7500
```

手算和对上了：SOC 0.5 处低端 tanh 已经饱和（贡献满 0.20），高端那个还在负区间（−0.05），合起来 3.7500 V。再看两端与导数：

```bash
cd code/soc && python3 -c "
from cell_model import ocv, docv_dsoc
for s in (0.0, 0.05, 0.2, 0.5, 0.9, 1.0):
    print('SOC %.2f: OCV=%.4f V  dOCV/dSOC=%.3f V' % (s, float(ocv(s)), float(docv_dsoc(s))))
"
```

2026-10-09 输出：

```text
SOC 0.00: OCV=2.9690 V  dOCV/dSOC=1.884 V
SOC 0.05: OCV=3.1900 V  dOCV/dSOC=6.800 V
SOC 0.20: OCV=3.5100 V  dOCV/dSOC=0.803 V
SOC 0.50: OCV=3.7500 V  dOCV/dSOC=0.800 V
SOC 0.90: OCV=4.1200 V  dOCV/dSOC=1.550 V
SOC 1.00: OCV=4.2453 V  dOCV/dSOC=0.936 V
```

`dOCV/dSOC` 在 SOC 0.05 冲到 **6.8 V/SOC**，中段回落到 **0.800**——这就是 EKF 里观测矩阵 $C$ 要的那个数：同样 1 mV 电压噪声，在陡的地方只换到很少的 SOC，在平台区能换走一大截。

**交**　贴两段输出，并用一句话说明中段为什么正好是 0.800 V/SOC。

**口诀**　常数是基准，斜率管中段，两个 tanh 管两头。

**今天你解锁了**　你能把一条 OCV 曲线拆成四项，说出每一段陡缓是谁造成的。

**短自测**　如果把手算里的中段斜率从 0.8 改成 0.4，SOC 0.5 的 OCV 会变成多少？

<details>
<summary>先自己答再展开</summary>

3.7500 − 0.4 × 0.5 = 3.5500 V。斜率项直接线性缩放：`0.8*soc` 在 soc=0.5 贡献 0.4，改半后只贡献 0.2。两个 tanh 项在这一点已经饱和，不动。
</details>

## 第 2 天：立刻掉的那一下：R0

**读**　[阶段 4 §4.4](../stages/stage-4-SOC-SOH算法.md) 的等效电路段：$U = \mathrm{OCV} + I R_0 + U_{rc}$。前半句是今天的，后半句是明天的。

**看**　[内阻压降与回弹](../circuits/assets/internal-resistance.svg)。黄点沿 20 mΩ 那条线走：带载端电压先掉 $I \times R$，卸载再回弹——**20 mΩ 正是本篇模型的 R0**，这条动画和代码是同一个数。

**看码**　`TheveninCell.terminal_voltage()` 只有一行：

```python
return ocv(self.soc) + current_a * self.r0 + self.u_rc
```

`current_a * self.r0` 就是那一瞬间的台阶。符号约定是**充电为正**：充电时它抬高端电压，放电时压低。

**跑**（同一颗电芯，只改电流）：

```bash
cd code/soc && python3 -c "
from cell_model import TheveninCell
c = TheveninCell(10.0, 0.020, 0.015, 3000.0, soc0=0.5)
v0 = c.terminal_voltage(0.0); v1 = c.terminal_voltage(2.0)
print('I=0 A  -> %.4f V' % v0)
print('I=2 A  -> %.4f V' % v1)
print('差 = %.2f mV ；手算 I*R0 = %.2f mV' % ((v1-v0)*1000, 2.0*0.020*1000))
"
```

2026-10-09 输出：

```text
I=0 A  -> 3.7500 V
I=2 A  -> 3.7900 V
差 = 40.00 mV ；手算 I*R0 = 40.00 mV
```

40.00 mV 和手算**逐位相同**——因为这一步是纯代数，噪声还没进来。对比一下：若 R0 是 60 mΩ，同样 2 A 会掉 120 mV。R0 不是「电池状态」，是**电池型号与老化**的属性。

**交**　贴输出，并写下你自己的电芯在 2 A 下的 R0 是多少（可以用阶段 4 §4.10 的方法从真实记录里标）。

**口诀**　电流一加就掉、一撤就弹的那一段，是 R0。

**今天你解锁了**　你能在端电压公式里指出哪一项对应「快得来不及极化」的那个台阶。

**短自测**　为什么这一步用 `terminal_voltage()` 直接算，而不用 `step()` 推进？

<details>
<summary>先自己答再展开</summary>

因为 `step()` 会**同时**推进 RC 极化与安时积分——那是「过了一段时间之后」的电压。今天的台阶要在**同一时刻、同一 SOC**下只比较电流的影响，所以必须绕开时间推进，否则算出来的是 R0 与 RC 的混合，手算就对不上了。
</details>

## 第 3 天：拖尾巴的那一段：RC

**读**　[阶段 4 §4.4](../stages/stage-4-SOC-SOH算法.md) 里一阶 RC 的微分方程，以及 [HPPC 五天](07-hppc五天.md) 第 2 天：τ 与两个点的关系。

**看**　[阶跃：R0 与 RC 尾巴](../circuits/assets/rc-step-r0-tail.svg)。先掉的是 R0，再拖尾巴的是 RC——注意图上 τ 约 8 s 是**示意**，本篇模型的 τ 是 45 s，认形状不认数。

**看码**　`step()` 的前两行：

```python
a = np.exp(-dt_s / (self.r1 * self.c1))
self.u_rc = a * self.u_rc + self.r1 * (1.0 - a) * current_a
```

**跑**（跑 45 拍，和两个解析式对账）：

```bash
cd code/soc && python3 -c "
import numpy as np
from cell_model import TheveninCell
c = TheveninCell(10.0, 0.020, 0.015, 3000.0, soc0=0.5)
for _ in range(45): c.step(2.0, 1.0)
a = np.exp(-1.0/45.0)
print('跑 45 拍后 u_rc = %.3f mV' % (c.u_rc*1000))
print('解析式 R1*I*(1-e^-1) = %.3f mV' % (0.015*2.0*(1-np.exp(-1))*1000))
print('离散式 R1*I*(1-a^45) = %.3f mV' % (0.015*2.0*(1-a**45)*1000))
"
```

2026-10-09 输出：

```text
跑 45 拍后 u_rc = 18.964 mV
解析式 R1*I*(1-e^-1) = 18.964 mV
离散式 R1*I*(1-a^45) = 18.964 mV
```

三个数逐位相同，说明离散递推**就是**连续解在整数拍上的取值：τ = R1·C1 = 45 s，跑满一个 τ 正好爬到 $R_1 I (1 - e^{-1}) = 18.964$ mV 的 63.2%。每拍新加进来的那一点点是：

```bash
cd code/soc && python3 -c "
import numpy as np
r1, c1, dt = 0.015, 3000.0, 1.0
a = np.exp(-dt/(r1*c1))
print('tau = R1*C1 = %.1f s' % (r1*c1))
print('a = exp(-1/tau) = %.6f' % a)
print('R1*(1-a) = %.4f mΩ  （I=2A 时每拍极化 %.4f mV）' % (r1*(1-a)*1000, r1*(1-a)*2*1000))
"
```

2026-10-09 输出：

```text
tau = R1*C1 = 45.0 s
a = exp(-1/tau) = 0.978023
R1*(1-a) = 0.3297 mΩ  （I=2A 时每拍极化 0.6593 mV）
```

**交**　贴三段输出，并回答：把 τ 改成 90 s（R1 或 C1 加倍），跑满 45 拍后的 `u_rc` 会更大还是更小？

**口诀**　R0 管台阶，RC 管尾巴；一拍加一点，加到 τ 才六成。

**今天你解锁了**　你能把「极化」这个模糊的词换成一个 τ、一个每拍增量和一个可对账的公式。

**短自测**　为什么写 `a = exp(-dt/τ)` 而不是更省事的 `a = 1 - dt/τ`？

<details>
<summary>先自己答再展开</summary>

`1 - dt/τ` 在 dt 接近或大于 τ 时会变成 0 甚至负数——一步就把极化清空、还翻符号。`exp` 对任何 dt > 0 都落在 (0, 1) 区间，dt 很大时自动退化成「一步到位」，不会发散。这也是仿真里 dt 一变就出事的地方：换采样率时先看这两个式子还成不成立。
</details>

## 第 4 天：分母写错会怎样

**读**　[阶段 4 §4.2 安时积分](../stages/stage-4-SOC-SOH算法.md)：$\mathrm{SOC} = \mathrm{SOC}_0 + \frac{1}{Q}\int I\,dt$——分母 $Q$ 是满充容量，也是整条式子里最容易被当真的那个数。

**看**　[库仑计与校准点](../circuits/assets/coulomb-counting.svg)。积分读数沿斜线漂离真实水位，满充校准点把它拉回去——分母偏了不报警，只会一直漂。

**看码**　`step()` 里的安时积分：

```python
self.soc += current_a * (dt_s / 3600.0) / self.q_ah
```

**跑**（同样 4 A、同样一小时，只改分母）：

```bash
cd code/soc && python3 -c "
from cell_model import TheveninCell
c = TheveninCell(10.0, 0.020, 0.015, 3000.0, soc0=0.5)
for _ in range(3600): c.step(4.0, 1.0)
print('10Ah 电芯充 4A 一小时 -> SOC %.4f（Δ=%.4f）' % (c.soc, c.soc-0.5))
d = TheveninCell(9.5, 0.020, 0.015, 3000.0, soc0=0.5)
for _ in range(3600): d.step(4.0, 1.0)
print('容量写小 5%%（9.5Ah）同样电流 -> SOC %.4f（Δ=%.4f）' % (d.soc, d.soc-0.5))
print('差 %.4f 个 SOC 点' % ((d.soc-c.soc)*100))
"
```

2026-10-09 输出：

```text
10Ah 电芯充 4A 一小时 -> SOC 0.9000（Δ=0.4000）
容量写小 5%（9.5Ah）同样电流 -> SOC 0.9211（Δ=0.4211）
差 2.1053 个 SOC 点
```

一小时 4 A 是 4 Ah，除 10 Ah 正好 0.4000 个 SOC 点——手算与代码逐位相同。分母写成 9.5 Ah，同一段电流就多走 **2.1053** 个点：**误差不报警、不抖动，只是稳定地漂**。这就是 §4.2 说的「梦游」，也是校准点（满充/静置锚点）存在的理由。

**交**　贴输出，并算一算：如果一整轮放完 8 Ah，分母错 5% 会让末端 SOC 差几个点。

**口诀**　分母错了不响不跳，只是每天多走一点。

**今天你解锁了**　你能把「容量标定为什么值钱」换成一个具体的点数，并说出它为什么不会被自检发现。

**短自测**　既然分母错了会漂，为什么不能每拍都重新标定容量？

<details>
<summary>先自己答再展开</summary>

因为标定要**一次完整的、边界清楚的充放**（或至少一段可信的低电流记录），这不是每拍都有的条件。日常运行里既不知道真实剩余容量，也没有可用的满充满放点，所以工程上的做法是：平时用积分＋锚点把漂移压住，标定在特定时机做（阶段 4 §4.10 那类记录），再把结果写回分母。第 5 天会看到：分母错得离谱时，EKF 靠电压观测能自己把它兜住多少。
</details>

## 第 5 天：把模型改坏

**读**　[阶段 4 §4.5 卡尔曼滤波](../stages/stage-4-SOC-SOH算法.md)：两个不完美信息源的联姻——积分准但会漂，电压观测不漂但分辨率差。

**看**　[Thevenin+EKF 与纯积分对比](../circuits/assets/ekf-estimation.svg)。它的图说写明曲线来自 `compare.run(seed=42)`——**今天用的就是同一段工况、同一个种子**，所以动画里的 RMSE 和我下面跑出来的数是一回事。

**跑**（同一段 4.7 h 工况、同一个种子，只改喂给 EKF 的参数）：

```bash
cd code/soc && python3 -c "
import numpy as np, compare
from estimators import EKFEstimator
from cell_model import TheveninCell
def rmse(make):
    rng = np.random.default_rng(42)
    cell = TheveninCell(compare.Q_TRUE_AH, compare.R0, compare.R1, compare.C1, soc0=0.8)
    cur = compare.drive_cycle(compare.N_STEPS, compare.DT_S, 42)
    est = make(); err = []
    for k in range(compare.N_STEPS):
        i_true = cur[k]; v_true = cell.step(i_true, compare.DT_S)
        i_meas = i_true + compare.I_OFFSET_A + rng.normal(0.0, compare.I_NOISE_A)
        v_meas = v_true + rng.normal(0.0, compare.V_NOISE_V)
        err.append(est.step(i_meas, v_meas, compare.DT_S) - cell.soc)
    e = np.array(err); return 100*float(np.sqrt(np.mean(e**2))), 100*float(e[-1])
cases = [('出厂 R0=20mΩ', 0.020, 0.015, 3000.0, 9.5), ('R0 十倍 200mΩ', 0.200, 0.015, 3000.0, 9.5),
         ('R1 十倍 150mΩ', 0.020, 0.150, 3000.0, 9.5), ('C1 十倍 30000F', 0.020, 0.015, 30000.0, 9.5),
         ('容量砍半 5.0Ah', 0.020, 0.015, 3000.0, 5.0), ('容量 11Ah', 0.020, 0.015, 3000.0, 11.0)]
for name, r0, r1, c1, q in cases:
    print('%-16s RMSE %.2f%%  末端 %.2f%%' % ((name,) + rmse(lambda r0=r0, r1=r1, c1=c1, q=q: EKFEstimator(0.7, q, r0, r1, c1))))
"
```

2026-10-09 输出：

```text
出厂 R0=20mΩ       RMSE 0.20%  末端 0.00%
R0 十倍 200mΩ      RMSE 41.51%  末端 -1.89%
R1 十倍 150mΩ      RMSE 36.14%  末端 -4.47%
C1 十倍 30000F     RMSE 1.00%  末端 0.00%
容量砍半 5.0Ah       RMSE 0.20%  末端 0.00%
容量 11Ah          RMSE 0.20%  末端 0.00%
```

这张表是本篇最值钱的一屏，读法三条：

1. **电阻错就崩**：R0 写成十倍，RMSE 从 0.20% 冲到 **41.51%**；R1 十倍是 **36.14%**。因为电阻直接乘在**瞬态电流**上，而工况里到处是阶跃——模型对不上，滤波器每拍都在被拽。
2. **C1 错无所谓**（1.00%）：τ = R1·C1，而这段工况的静置段很长，极化早就走完了；慢过程错一点，观测上看不出来。
3. **容量错也无所谓**（5.0 Ah 与 11 Ah 都是 0.20%）：容量只影响积分的**长期**漂移，而卡尔曼每拍都用电压观测把它拉回来——**观测钉得住它看得见的量**。

第四天那张「分母错了就漂」的表和今天这张不矛盾：第四天是**纯积分**（没有观测），今天是**EKF**（有观测）。同一个错，两个架构两种命运。

**交**　贴输出，并回答：把 R0 改小十倍（2 mΩ）会更接近还是更远？

**口诀**　错在电阻上，滤波器当场喊；错在容量上，它慢慢兜。

**今天你解锁了**　你能指着参数表说出「哪个参数错了会毁掉精度、哪个错了不急」，并解释为什么——因为观测只能钉住它看得见的量。

**短自测**　为什么这段工况里 R0 错十倍的伤害，比 C1 错十倍大两个数量级？

<details>
<summary>先自己答再展开</summary>

时间尺度。R0 是**瞬时**项：电流一变，端电压立刻差 $I \cdot \Delta R$，全落在观测方程里，滤波器必须立刻解释这个差——只能把 SOC 猜歪。C1 只出现在 τ 里，而 τ 影响的是「需要多久走到稳态」；这段工况的静置段（1800 s、8300–10100 s）远长于 τ=45 s，极化在该动的时候都动完了，C1 差十倍只让尾巴形状略有不同。
</details>

**练完你会怎样**：你能把一颗电芯模型拆成四项 OCV、一个 R0、一个 τ，并说出每个参数错了会在哪一段电压上留下痕迹、EKF 能不能自己兜住。
