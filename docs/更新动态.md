## 共学一口气到十一期

共学之前只有七个主题，现在补齐了「只有电脑也能把整条链路走完」的那四块。 [PC 全链路五天](共学/08-pc全链路五天.md) 从采样一路走到判故：100 拍里 99 帧到、1 帧坏 CRC、4 次重同步（一次坏 CRC 加三个垃圾字节），过压注入从 tick 46 开始、tick 48 判 `OVP`、tick 49 电流才归零——残差先叫、保护后到。[电芯建模五天](共学/09-电芯建模五天.md) 讲清一条 OCV 曲线背后是方程不是查表：端部斜率 6.800 V/SOC、中段 0.800 V/SOC，R0 十倍误差能把 RMSE 顶到 41.51%，而 C1 十倍只到 1.00%。[无真值诊断五天](共学/10-无真值诊断五天.md) 教你在没有参考 SOC 时看新息：参数错跟着电流走（相关 −0.288）、传感器坏只是整体偏；NASA 回放那段明确写着 `independent_soc_truth = False`，新息的 15.137 mV 对 3.699 mV 只说明自洽，不说明精度。[数据准备五天](共学/11-数据准备五天.md) 管的是「别人测的数据先验身份」：25461 行按用途切四段、`csv_sha256` 在 metadata／实测文件／报告三处一致、改 1 个字节直接被拦；负控还顺手证明了哈希管不住「有没有选对行」。四篇的每条命令都在 2026-10-09 本机实测过再写进「跑」，并按逐字校验器对账（8/8、7/7、6/6、13/13）。

`.lychee.toml` 整站排除的域名不在 CI 里，真关停了没人知道，所以每月人手点一遍。2026-10-09 这一轮（[Issue #50](https://github.com/zhuguang-ZFG/BMS-Z/issues/50)）16 个域名逐个点过，**0 确认死链**：`nxp.com`／`e2e.ti.com`／`eet-china.com` 三条对本机出口的态度分别是 404/403/超时，用真实 Chromium 打开都是 200；`tao.hvcis.com` 停在 Cloudflare 挑战页，既不算活也不算死，维持排除。`catarc.org.cn` 10-04/05 两次全站 502 时写的是「恢复后再移出」，这轮连续 3 次 200（391306 B）、浏览器能直接打开 PDF，按当初的条件移出 `exclude`（17→16）重新受巡检——这是按既定条件收窄，不是临时放宽。另记一条**假 404**：探针把 `.lychee.toml` 注释里的说明文字吃进了 URL，下一轮别当新死链。

## gh 抖一下，不再当成对不上

发布记录/分类/仓库简介三道本地门比的是 GitHub 现值，而 `gh` 会撞分钟级抖动——同一小时内实测绊到三次：同一个 v1.4.0 的 run 号先报 TLS handshake timeout、再报 EOF，而 10 分钟前同一张表还全绿。取数失败原先被直接当成「发布记录对不上」判红。现在五处调用统一走带退避的 `gh_json`：命中网络类错误按 3s、6s 重试，重试完仍失败**照样报错**，并把「重试 3 次仍失败」写进红灯原因；404 与没登录一次就报，不白等。判据没动，只是不再让网络抖动假报。

## HPPC 的两种当场骗人的拟合

共学第 7 期 [HPPC 五天](共学/07-hppc五天.md)上线：一条脉冲的三段读法（起点跳变 97.8 mV 反推 R0 32.6 mΩ、尾巴钉 τ、幅值要除充电占比——10 s 脉冲只充到 24.7%，不除就全盘错）、两种当场骗人的拟合（用 40 s 窗的渐近线，修正后 R1 仍差 19.3%；再叠上「忘了乘 charge_factor、直接拿 |amp|÷|I|」就是 77%；把 30 s 附近的均值当渐近线 K，幅值会从 11.8 mV 缩到 5.8 mV），以及真数据反例（0.1 mV/s 的电压漂移能把 τ 吸到网格顶 119.5 s）。每天「看」位挂一张现有动画，`tests/test_hppc.py` 由 3 条增至 6 条契约测试。同一轮推翻了两处脚本注释里写错的「实测」数——扫遍末段窗口复现不出 33.6 s 与 -9%，30.5 s 其实是有噪 40 s 窗那个数被串错了地方。

## 把三个代码模块接成一套实验

100 拍场景检查过充去抖、切断输出对下一拍电流的影响、短路与过温，以及首次快照不被后续故障覆盖。通信中故意破坏一帧 CRC，接收端应丢掉它并找回下一帧。教程给出三道修改题，要求先预测再对照日志。

## 用真实数据检验模型参数

运行 `python code/soc/real_data.py --plot`，先用低电流与脉冲记录标定容量、准静态 OCV 和一阶 RC，再在后续随机负载上比较原教学模型和标定模型。报告保留模型失配与温度变化带来的残差，并明确 SOC 参考由测量电流计算，不能作为独立真值宣称实际精度。

## 发版这一串账装上对账门

这一批 31 个提交里 12 个是 `ci:`，几乎全花在「发一版要留下的那些数不再靠手抄」上。`check_docs.py` 比 v1.3.0 多出 **18 个 `check_*` 函数**：11 个在 CI 上跑文本对账，7 个只在本地跑真值（git 标签、`gh` 的现值，runner 上拿不到）。

- [维护说明](维护说明.md#发布记录) 那张「发布记录」表有了门：表的版本集合要同时等于 CHANGELOG 的版本小节集合与底部 compare 落款集合；发布时间必须是 `2026-01-01 00:00:00` 这种写法；「未记录」只许出现在最后两列；记了收口提交的行要把三个 workflow 逐个点名。本地真值侧还多看两件事——收口提交得是标签提交的**后代**（不能就是标签提交本身），核验里每个 run 号得真是那条 workflow 在收口提交上跑绿的。
- CHANGELOG 节首那句「共 N 条，覆盖 `vX` 之后 M 个提交」不再手打，由 `python3 tools/release_stats.py --from v1.3.0 --to v1.4.0` 现数。工具和门是两套实现，所以各数一遍再比：措辞漂移、正则认不出、少认一节，都会被当场点名。本版实测 30 条 / 31 个提交。
- 读者第一眼看到的那三处版本号（README 的「📣 最近更新」、门户卡片、[更新动态](更新动态.md) 导读句）由 CI 对回发布记录表：链接文字和 URL 里的版本都要等于表里最新那一行，同句日期要等于发布日。把 Release 链接摘掉也红——没有链接可锚，那句话就对不了账。
- 本地门共**十三步**，五道只在本地跑。每道新门上线前都先证明它会红：逐条改坏、要求非零退出、再加反向对照，改动全部按字节还原，红绿清单写进 [维护说明](维护说明.md)。

## 代码少算错三处

这三处在打 1.1.0 标签之后、文档大改之前就进了仓库。固件和协议的行为因此和旧说明不同，算法文件本身这一版社区页没有再改。

- 均衡该停会停：电流归零、拔枪，或电压掉出均衡门槛，同一拍关掉。拔枪后剩下的一点正电流，不再被当成「充满了」。
- 坏字节后面的好帧还能找回来。长度或 CRC 失败之后会接着扫，流结束时也可以 `flush()`。合法数据里碰巧出现的帧头，仍当数据。
- SOC 三条曲线在同一步上比较。以前真值和估计值会错开一拍，图上看起来像算法的错。
