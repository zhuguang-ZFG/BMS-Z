# 共学：真实数据五天

> **本篇你会学到**　真实记录怎样分组建账、一阶 RC 参数怎样从脉冲里读出来、参数不匹配时滤波器会发生什么，以及整条链怎样接回保护与通信。
> **预计用时**　5 天，每天大约 45–90 分钟。第 5 天另需编译器。
> **前置**　做过 [SOC 五天](01-soc五天.md) 或读过阶段 4 §4.4–§4.5。装好 Python 3.10+，在仓库根执行过 `pip install -r code/requirements.txt`；第 5 天需要 gcc。不接电池。

⚠️ 数据是 NASA 一颗电芯（RW3）的实测子集。下面所有 RMSE 都相对**计算参考**，不是独立测得的 SOC 真值，更不是你手里那颗电芯的精度。别拿验证段调完参，再把它叫独立验证。

## 第 1 天：先划分，再拟合

**读**　[SOC 真实数据实验 §2](../SOC真实数据专题.md#2-数据来自哪里)。一张分组表把同一条记录切成四份：`ocv`、`capacity`、`pulse` 做标定，`validation` 只做回放。加粗那句话就是今天全部：先划分，再拟合。

**看**　[OCV–SOC 曲线](../circuits/assets/ocv-soc-curve.svg)。SOC 五天第 3 天拿它当「查表的尺子」；今天身份变了——这张表在本实验里是**待标定的产物**，由低电流组一步步构造出来。图上的毫伏是示意。

**跑**（在仓库根）：

```bash
python3 code/soc/real_data.py --plot
```

PowerShell：

```powershell
python code/soc/real_data.py --plot
```

2026-10-09 在本仓库跑通（Python 3.13、numpy 2.5，约 3 秒），开头几行是：

```text
{
  "kind": "measured_nasa_rw3_replay",
  "samples": 2613,
  "duration_s": 2588.92,
```

末行应指出输出目录 `code/soc/real-data-output/`。你的终端应印出同样的 `samples` 与 `duration_s`；多一位或少一位，把原文贴出来，不要手改。Windows 上 `python` 换成 `py -3` 的说明在[专题 §1](../SOC真实数据专题.md#1-离线运行)。

**交**　贴 `samples` 与 `reference_kind` 两行原文，加一句：验证组的电压和温度，进没进标定。

**口诀**　先划分，再拟合。回放的账不进标定。

**今天你解锁了**　你在自己电脑上跑完了一颗真实电芯的标定加回放，并知道四个分组各干什么。

**短自测**　脚本怎样自己证明「验证组没参与拟合」？

<details>
<summary>先自己答再展开</summary>

标定函数只读前三组；测试会把验证组全部替换成 NaN 再跑一遍标定，确认参数不变。回放组只出题，不偷看答案。
</details>

## 第 2 天：两个容量都对

**读**　[§4 参数怎样得到](../SOC真实数据专题.md#4-参数怎样得到) 里容量那两段。参考放电积分出 2.009 Ah，低电流组自己积分出 2.119 Ah——同一颗电芯，两个数都对，因为测试条件不同。

**看**　[Peukert 型容量](../circuits/assets/peukert-capacity.svg)。倍率越高放出来的安时越少，k=1 的水平线在旁边作对照。图上的数字是示意；它讲的正是「容量跟着条件走」这件事。

**跑**（昨天已生成 `real-data-output/`；换电脑就先重跑第 1 天）：

```bash
python3 -c "import json; c=json.load(open('code/soc/real-data-output/calibration.json',encoding='utf-8')); print('capacity_ah =',round(c['capacity_ah'],3)); print('low_current_capacity_ah =',round(c['low_current_capacity_ah'],3))"
```

PowerShell：

```powershell
python -c "import json; c=json.load(open('code/soc/real-data-output/calibration.json',encoding='utf-8')); print('capacity_ah =',round(c['capacity_ah'],3)); print('low_current_capacity_ah =',round(c['low_current_capacity_ah'],3))"
```

2026-10-09 输出两行：

```text
capacity_ah = 2.009
low_current_capacity_ah = 2.119
```

**交**　贴这两行，并用一句话说清：为什么这两个数不互相打脸。

**口诀**　容量不是常数。换了条件，就换了一个数。

**今天你解锁了**　你能对同一颗电芯说出两个都对的容量，并指出各自的条件。

## 第 3 天：沿上读 R0，尾巴里藏时间常数

**读**　[§4](../SOC真实数据专题.md#4-参数怎样得到) 里 RC 那三步：脉冲两头算电压跳变除以电流跳变得 R0 的两个沿，静置尾巴拟合 `K + A·exp(−t/τ)`，再修正幅值得 R1、C1。

**看**　[阶跃 R0 与 RC 尾巴](../circuits/assets/rc-step-r0-tail.svg)。SOC 五天第 4 天它在 10 秒合成脉冲上服务过；今天的脉冲约 600 秒、来自实测，同一副眼镜换了镜片。图上秒数是示意。

**跑**：

```bash
python3 -c "import json; c=json.load(open('code/soc/real-data-output/calibration.json',encoding='utf-8')); print('r0_on_mohm =',round(c['r0_on_ohm']*1000,1)); print('r0_off_mohm =',round(c['r0_off_ohm']*1000,1)); print('r0_mohm =',round(c['r0_ohm']*1000,1)); print('r1_mohm =',round(c['r1_ohm']*1000,1)); print('tau_s =',round(c['tau_s'],1))"
```

PowerShell：

```powershell
python -c "import json; c=json.load(open('code/soc/real-data-output/calibration.json',encoding='utf-8')); print('r0_on_mohm =',round(c['r0_on_ohm']*1000,1)); print('r0_off_mohm =',round(c['r0_off_ohm']*1000,1)); print('r0_mohm =',round(c['r0_ohm']*1000,1)); print('r1_mohm =',round(c['r1_ohm']*1000,1)); print('tau_s =',round(c['tau_s'],1))"
```

2026-10-09 输出五行：

```text
r0_on_mohm = 87.0
r0_off_mohm = 77.0
r0_mohm = 82.0
r1_mohm = 49.1
tau_s = 73.5
```

两个沿差着 10 mΩ：R0 取平均只是近似，这组参数也只属于一个较高 SOC 工作点，不是全工况的参数表。

**交**　贴五行输出，并写一句：为什么取两个沿的平均，而不是挑更小的那个报数。

**口诀**　沿上读 R0，尾巴里藏时间常数。

**今天你解锁了**　你把一阶 RC 的三个数从真实脉冲里读了出来，还知道它们只是一个 SOC 点的近似。

## 第 4 天：参数错了，滤波器照样推歪

**读**　[§5 计算参考与默认结果](../SOC真实数据专题.md#5-计算参考与默认结果)。计算参考用同一套测量电流算出来，它不是真值；三个估算器同一初值、同一容量，差别只在参数从哪来。

**看**　[库仑计与 EKF 回路](../circuits/assets/coulomb-ekf-loop.svg)。蓝线每拍先预测、再被电压残差拉回——前提是残差算得准。OCV 和内阻不匹配时，同一条校正通道会把状态往错的方向推。图上的账是示意。

**跑**：

```bash
python3 -c "import json; r=json.load(open('code/soc/real-data-output/report.json',encoding='utf-8')); [print(k, round(v['rmse_pp'],2), round(v['end_error_pp'],2)) for k,v in r['metrics'].items()]; print('voltage_rmse_mv =', {k: round(v,1) for k,v in r['voltage_rmse_mv'].items()})"
```

PowerShell：

```powershell
python -c "import json; r=json.load(open('code/soc/real-data-output/report.json',encoding='utf-8')); [print(k, round(v['rmse_pp'],2), round(v['end_error_pp'],2)) for k,v in r['metrics'].items()]; print('voltage_rmse_mv =', {k: round(v,1) for k,v in r['voltage_rmse_mv'].items()})"
```

2026-10-09 输出四行（列依次是 RMSE、末端误差，单位百分点）：

```text
coulomb 10.0 -10.0
ekf_generic 20.74 -5.54
ekf_calibrated 4.92 6.19
voltage_rmse_mv = {'generic': 186.3, 'calibrated': 21.8}
```

原教学参数的 EKF 比纯积分还差 10 个点；换成独立标定的参数，电压诊断从 186.3 mV 缩到 21.8 mV。再打开 `real-data-output/comparison.png` 对着曲线看。

顺带看一眼 `report.json` 里的 `diagnostics` 段：新息 RMS generic 15.1 / calibrated 3.7 mV——**不用参考 SOC** 也能听出参数坏没坏；但两者的新息均值都近 0，静态误差被吸进了 SOC 状态。为什么「残差体面」救不了 generic，留给你对着上面的表想。

**交**　从 [§6 亲手改变三个条件](../SOC真实数据专题.md#6-亲手改变三个条件) 里挑一个：**先写下预测**，再跑，贴报告差异。不要三个都跑完只挑最好看的那个。

**口诀**　名字不保结果。参数错了，校正照样推歪。

**今天你解锁了**　你见过「EKF 比纯积分还差」，并且能说出为什么。

**短自测**　标定后仍剩 4.92 个点，为什么不能在这段验证数据上反复调 Q/R 把它压下去？

<details>
<summary>先自己答再展开</summary>

残差来自模型本身：验证段温度从 21.7 °C 走到 36.8 °C、模型没有温度补偿，RC 只标了一个 SOC 点，准静态 OCV 与容量基准也有差异。在同一验证段上反复调参，等于把「独立验证」用掉了；调完参数要另选一段没参与调参的工况。
</details>

## 第 5 天：把链路接回保护与通信

**读**　[PC 综合实验 §2](../PC综合实验专题.md#2-每拍是谁先做什么) 与 [§3 按时间找到故障](../PC综合实验专题.md#3-按时间找到故障)。一张 ASCII 图把负载、电芯模型、采样、EKF、C 状态机、组帧串成一条线；时间表里第 48 拍确认过充、第 61 拍短路。

**看**　[DTC 故障快照](../circuits/assets/dtc-snapshot.svg)。越过阈值那一拍，快照区冻结电压电流温度和时间戳，后面的波动不再改写。图上的 4.20 V 是示例阈值。

**跑**（需要 gcc 或 clang；缺编译器会明确报错）：

```bash
python3 code/firmware/pc_demo.py
```

PowerShell：

```powershell
python code/firmware/pc_demo.py
```

2026-10-09 跑通，中段与末段是：

```text
  "received_frames": 99,
  "bad_crc": 1,
  "resyncs": 4,
```

`checks` 里 7 项全为 `true`，最后 `"passed": true`。默认 100 拍采样、99 帧有效遥测、1 次 CRC 错误。这些是脚本结果，不是电芯实测。

**交**　贴 `passed` 那一段，再打开 `pc-demo-output/samples.csv` 找第 48 拍和第 61 拍各一行，用自己的话写：「当前故障」和「快照原因」在短路之后各是什么、为什么不同。[三道修改题](../PC综合实验专题.md#6-三道修改题) 是下一步，不打卡也行。

**口诀**　采样在先，决定在后。第一现场不涂改。

**今天你解锁了**　你把估算、保护和通信在同一条日志里追了一遍——从一次电流采样，追到接收端的一帧字节。
