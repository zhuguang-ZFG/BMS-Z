# 七段流程

## 1. 选

候选问题必须能在一句话里说完，并能由一个输入贯穿到答案。优先选择读者已经遇到、但容易误判的现场，例如“满电一拧把为什么掉两格”。

每个候选给出：

- 开场现象或判断题；
- 唯一学习目标；
- 贯穿全片的输入、样本或故障；
- 讲法：猜谜、判断、痛点原理或一条主线；
- 时长建议，以及更短时要删掉什么。

用户完成确认 1 后再进入查证。

## 2. 查

从对应阶段正文、伴读书、代码与原始资料建立 `mNN-*.FACTS.json`。事实分五类：

- `T1`：标准、厂商手册、论文、原始数据；
- `T2`：教材、官方课程或带原始引用的权威二手资料；
- `T3`：社区材料，只能当线索；
- `project`：仓库已经复算并由测试钉住的结论；
- `demo`：教学算例，必须写算式、假设或生成图来源。

每条事实至少有 `id`、`claim`、`level` 和 `sources`。本地来源写仓库相对路径与定位说明；外链写完整 URL。事实不够时删旁白，不补一个“听起来合理”的数。

## 3. 写

先写 `STORYLINES.md` 的两到三条真分支，再选一条落 `SPEC.md` 和 JSON。旁白按真实口语写，数字带条件；同一段不要连续使用“不是……而是……”“首先／其次／最后”等同构句式。

每个 beat 在 `facts` 中列出它使用的事实 ID。纯转场也要能说明它承接了哪条已经登记的事实；不要用无来源的金句填空。

用户完成确认 2 后再进入配音和捕获。

## 4. 配

先出 15–20 秒开场试听，确认音色和语速。MiMo 内置音色的本机配置入口是 `python tools/video/set_mimo_key.py`，输入不回显；默认模型为 `mimo-v2.5-tts`。Windows SAPI 仍是离线兜底。克隆声音或上传参考音频前，必须另行确认本人所有或已获授权。

时间轴只认实测旁白时长。改一个字后重新生成对应音频，不拿旧音频配新字幕。

## 5. 编

JSON 是唯一分镜真源。优先复用阶段正文已经引用的 SVG；新增技术图先进入项目的动画画风与数值门禁。

画面遵守 BMS-Z 手绘视觉：

- 纸面留白、圆珠笔式边注和少量贴纸感只用于导览；
- 孔雀蓝表示读数与主线，赭石／那不勒斯黄表示电流、算式和提示，红色只给风险；
- 同一拍最多两个主要文字组；
- 运动要表示电流、状态、数据、热或时间，不能只靠闪烁制造“动感”。

## 6. 检

先跑 `spec.py --check`，再按流水线生成接触表。至少检查：

- 事实 ID 全部存在、无孤儿事实；
- 屏幕数字与 `FACTS.json` 一致；
- 字幕没有切断数字或单位；
- 画面连续，技术曲线和标签未被装饰遮挡；
- 响度、真峰值、帧数、黑白帧与构造恒等式通过；
- 关闭动画或声音后仍有可读路径。

## 7. 发

确认 3 后运行 `publish.py`。发布包从分镜和实测时间轴生成，不手抄标题、章节时间或验收清单。正文只承诺片中已经证明的结论；`FACTS.json` 随项目保留，供复核与改版。
