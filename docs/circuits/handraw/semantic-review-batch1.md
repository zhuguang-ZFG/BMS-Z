## 两处旧版失败：期望、实际与首次分歧（已修复，保留根因）

### `bms-roadmap` f6 / end

- 期望：首页当前资源计数与机器盘点一致，或明确标注日期/历史基线。
- 实际：统计卡无日期地写「167 张」；当前 `check_docs` 统计是 177。
- 最小复现：直接打开 `exports/bms-roadmap-end.webp`，读取左下统计卡。
- 首次分歧：`storyboard/bms-roadmap/frame-06.svg` 第 21 行已经写入 167，不是浏览器缓存造成。
- 后续修复合同：修正当前统计或改为明确的历史快照；同步源、位图帧、动画与 end，再复核。不能只改报告文字。

### `hppc-pulse` f1 / start

- 期望：prompt 帧大纲第 1 步是预静置；电流为 0，压降曲线保持 0 mV，跳变属于第 2 步。
- 实际：首帧字幕仍称静置，但已有电流上跳与电压下跌。
- 区分实验：比较源 SVG、storyboard f1 与 start；三个位置都存在跳变，排除「只有导出错序」的解释。
- 首次分歧：`storyboard/hppc-pulse/frame-01.svg` 第 24–26 行的 path 已越过静置区，字幕在第 38 行仍写静置。
- 导出器按文件名排序，另做有损 WebP 重编码；因此帧与静态导出像素不完全相同不构成错序证据。
- 后续修复合同：将预静置绘制截断在注入前，保留第 2 帧的注入/跳变；同一验证必须先在旧图失败、修复后通过，并实际观察新 start 与动画首两帧。
