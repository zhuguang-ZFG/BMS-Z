## 陪练卡跟上两个实验

[AI 陪练卡](AI陪练卡.md)沿用四问结构补上两张卡：真实数据五天与 PC 综合实验。出题只考机制、类比不给新数、批改只对照仓库；两张卡的固定提醒各自写死「验证组用掉一次就少一次」「一秒一拍验证不了真实短路」。擂台页脚同步接上第 4 期的直接前驱。

## 不用真值也听得见坏参数

两条线同口径：只看采样对模型的残差。[真实数据实验](SOC真实数据专题.md)的 `report.json` 多出 `diagnostics` 一段——generic 新息 RMS 15.1 mV 对 calibrated 3.7 mV，参数坏没坏不用参考 SOC 也听得出来；[PC 综合实验](PC综合实验专题.md)每拍记录新息进 `samples.csv`，验收加第 8 项——过充注入拍 71.7 mV、短路注入拍 585 mV 对恒流段基线 0.2 mV。温度不进观测方程，所以温度注入不引起新跳变，这条边界也写进了教程。

## 把三个代码模块接成一套实验

[PC 综合实验](PC综合实验专题.md)复用已有电芯模型、SOC 估算、C 状态机和帧解析器。在仓库根运行 `python code/firmware/pc_demo.py`，就能生成逐拍采样、故障事件、原始字节流、接收日志与验收报告；需要 Python 依赖和 gcc。

100 拍场景检查过充去抖、切断输出对下一拍电流的影响、短路与过温，以及首次快照不被后续故障覆盖。通信中故意破坏一帧 CRC，接收端应丢掉它并找回下一帧。教程给出三道修改题，要求先预测再对照日志。

## 用真实数据检验模型参数

[SOC 真实数据实验](SOC真实数据专题.md)附 NASA RW3 的实测子集与确定性转换器，原始数据保留 CC BY 4.0 许可和署名。日常回放离线运行；源步骤、变换说明和校验值随数据一起提供。

运行 `python code/soc/real_data.py --plot`，先用低电流与脉冲记录标定容量、准静态 OCV 和一阶 RC，再在后续随机负载上比较原教学模型和标定模型。报告保留模型失配与温度变化带来的残差，并明确 SOC 参考由测量电流计算，不能作为独立真值宣称实际精度。

## 发版这一串账装上对账门

这一批 31 个提交里 12 个是 `ci:`，几乎全花在「发一版要留下的那些数不再靠手抄」上。`check_docs.py` 比 v1.3.0 多出 **18 个 `check_*` 函数**：11 个在 CI 上跑文本对账，7 个只在本地跑真值（git 标签、`gh` 的现值，runner 上拿不到）。

- [维护说明](维护说明.md#发布记录) 那张「发布记录」表有了门：表的版本集合要同时等于 CHANGELOG 的版本小节集合与底部 compare 落款集合；发布时间必须是 `2026-01-01 00:00:00` 这种写法；「未记录」只许出现在最后两列；记了收口提交的行要把三个 workflow 逐个点名。本地真值侧还多看两件事——收口提交得是标签提交的**后代**（不能就是标签提交本身），核验里每个 run 号得真是那条 workflow 在收口提交上跑绿的。
- CHANGELOG 节首那句「共 N 条，覆盖 `vX` 之后 M 个提交」不再手打，由 `python3 tools/release_stats.py --from v1.3.0 --to v1.4.0` 现数。工具和门是两套实现，所以各数一遍再比：措辞漂移、正则认不出、少认一节，都会被当场点名。本版实测 30 条 / 31 个提交。
- 读者第一眼看到的那三处版本号（README 的「📣 最近更新」、门户卡片、[更新动态](更新动态.md) 导读句）由 CI 对回发布记录表：链接文字和 URL 里的版本都要等于表里最新那一行，同句日期要等于发布日。把 Release 链接摘掉也红——没有链接可锚，那句话就对不了账。
- 本地门共**十三步**，五道只在本地跑。每道新门上线前都先证明它会红：逐条改坏、要求非零退出、再加反向对照，改动全部按字节还原，红绿清单写进 [维护说明](维护说明.md)。

## 代码少算错三处

这三处在打 1.1.0 标签之后、文档大改之前就进了仓库。固件和协议的行为因此和旧说明不同，算法文件本身这一版社区页没有再改。

- 均衡该停会停：电流归零、拔枪，或电压掉出均衡门槛，同一拍关掉。拔枪后剩下的一点正电流，不再被当成「充满了」。
- 坏字节后面的好帧还能找回来。长度或 CRC 失败之后会接着扫，流结束时也可以 `flush()`。合法数据里碰巧出现的帧头，仍当数据。
- SOC 三条曲线在同一步上比较。以前真值和估计值会错开一拍，图上看起来像算法的错。
