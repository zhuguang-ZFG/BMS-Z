# AI 陪练卡

> **本篇你会学到**　怎样让对话模型出题、打比方、批改自测、起草代码草稿，并把它的每句话和每段 diff 拿回仓库对账，而不把它说的电压当成能上板的阈值。
> **预计用时**　一张知识卡 10–15 分钟；「写代码」五关一轮按实际编译与测试时间算。第一次先把「先读」「开工协议」「六个角色」看完，再挑卡开练。
> **前置**　对应阶段的教程已经打开。模型没有读过你的 datasheet，除非你把原文贴进去。

每次开练先抄两段：固定提醒管安全与口径，会话守则管它怎么回答。

> 数值以 BMS-Z 仓库正文和电芯/芯片 datasheet 为准。你给出的任何阈值都只是讨论，不能直接用于实物。锂电会起火：不要建议短接真电池，不要把通信芯片放进安全回路，过充、过放、过温和短路都要停在保护上。仓库里标了「示意」「示例」的数，保持这两个词。

> 会话守则：只根据我贴的原文回答；没贴的写「上下文没有」，不要用记忆补。每个数值都要给出处（哪一篇、哪一节、哪一句），给不出就标「推测」。我问保护阈值、寄存器值或接线步骤时，不要给数值，改答机制。回答最后列「证据清单」：用了哪些原文、哪些是推测、我还需要查什么。不要迎合我；不确定就说不确定。

翻到要练的那张卡，把卡内的「固定提醒」也一起贴上——它写的是这一阶段特有的边界。

模型若开始报一个「建议设成 4.xx V」，把它拉回来：请改问机制，不要给保护点。

## 先读

这套卡不是答案库，是练习剧本。它只做四件事：让模型出题、打比方、批改你的自测、起草代码草稿；不让它替你读数、定阈值、下判定、合并代码。

一次陪练只走三步：

1. **贴原文**　把正在读的那一节贴进上下文，至少一段。没贴的，模型只能凭印象答。
2. **选角色**　从下面六个角色里选一个，一次只做一件事。角色混着用，回答会又像老师又像裁判。
3. **回仓库对账**　把模型给的每个数值、单位、位宽、地址拿回正文找原句。找不到的，记「待查」，不记「它说过」。

第一次来，只做这一件事：打开阶段 0 §0.1.6，贴 1–3 段原文和上面两段，发一句「请出 3 道只考机制的题，先别给答案」。答完回仓库对账，找不到出处的记「待查」。

> **边界从哪来**　三圈、证据、签字与五个探针的口径，见 [阶段 7 · BMS × AI](stages/stage-7-BMS与AI.md)。这套卡只是把它变成可复制的练习。

> **一句**　模型给候选，程序给判定，人签字。练习时也一样：它批改，你对照仓库；它报阈值，你停。

## 开工协议

### 上下文包

每次开练，先把这张单子填好再发第一条消息。空着的格子不要用「它应该知道」补。

```text
【阶段/专题】阶段 4 · 4.5 卡尔曼滤波
【我贴的原文】…（1–3 段，带小节标题）
【我的问题】…（只问机制，不问阈值）
【本轮角色】出题官 / 类比教练 / 审稿人 / 反方 / 安全员 / 书记员
【输出格式】结论 + 证据清单（原文 / 推测 / 待查）
```

### 第一条消息

把固定提醒和会话守则贴完，再补一句：

> 下面是我贴的原文。请只在这几段里回答；没写的，明确说「上下文没有」。先不要给我任何能直接上板的数值。

### 什么时候不该开模型

- 你手上没有原文，只有记忆。
- 你要的是一个能直接写进固件的阈值、寄存器值或延时。
- 你要它替你决定「这样接安不安全」。
- 现场正在带电操作，或故障还在扩大。

这四种情况先回到正文、手册和实物保护；模型不在这条链上。

## 六个角色

| 角色 | 让它干 | 不让它干 | 开场句 |
| --- | --- | --- | --- |
| 出题官 | 出 3 道只考机制的题，先不给答案 | 编新数字、替你填阈值 | 「请出 3 道题，只考机制；先别给答案。」 |
| 类比教练 | 用一个生活类比讲机制，再指出类比在哪失效 | 用类比替代 datasheet | 「讲完请反问我：这个类比哪里不成立？」 |
| 审稿人 | 只对着你贴的原文挑错，标出缺证据的句子 | 替你重写一份带新事实的答案 | 「只对照我贴的原文，缺证据的句子标出来。」 |
| 反方 | 只追问证据，攻击你的结论 | 替你换一个结论、编反例数字 | 「请当反方，只问证据，不要替我下结论。」 |
| 安全员 | 检查文字里有没有危险建议 | 批准实物操作、替代保护回路 | 「只做安全审查：哪些话会让读者去碰真电池或绕过保护？」 |
| 书记员 | 把本轮整理成错题本三列 | 补你没说过的结论 | 「整理成：我错的、正确口径、出处；没出处的写待查。」 |

> **注意**　「安全员」只帮你看文字，不是安全评审，也不替代实物保护和人签字。它说「没问题」，不等于可以上电。

## 六种提示

每张卡都按同一顺序排六条，不是凑数：前四条练记忆和理解，后两条专门查证据与边界。

| 类型 | 用来做什么 | 什么时候用 |
| --- | --- | --- |
| 出题 | 逼自己主动回忆，暴露「看着会」 | 刚读完一节 |
| 类比 | 把机制换成一个生活模型 | 卡在抽象概念 |
| 批改 | 拿自己的话对照原文，找差异 | 自测写完后 |
| 边界 | 问清模型不能替你做什么 | 想让它下结论时 |
| 证据链 | 把每个数值、位宽、地址钉回原文 | 它给了具体数 |
| 反例 | 换问法、构造失效场景，检验适用条件 | 觉得「它说得都对」时 |

后两条最容易省，也最容易在真项目里救你：证据链挡住编数字，反例挡住「只讲常态」。

## 一次陪练的流程

15 分钟够走一轮。时间紧就只做 3–10 分钟那一段，但别省最后对账。

| 时段 | 做什么 | 留下什么 |
| --- | --- | --- |
| 0–3 min | 打开正文，贴 1–3 段原文，填上下文包 | 一个有出处的上下文 |
| 3–10 min | 选一个角色，做 2–3 条卡上提示；一次只问一个 | 回答 + 证据清单 |
| 10–13 min | 回仓库逐条对账：数值、单位、位宽、地址 | 一张取证单 |
| 13–15 min | 记一行错题：我错在哪、正确口径、下次怎么问 | 错题本一行 |

**做完不要立刻问下一题。** 先把这一轮里模型说得最肯定的一句拿出来，用五个探针过一遍；过不了，就先别信它。

## 证据对账与停手规则

### 取证单

把模型的话拆成四栏，一行只记一句。填不出的格子不要猜。

| 模型的话 | 自称出处 | 我在仓库找到的原句 | 判定 |
| --- | --- | --- | --- |
| 建议过充保护设 4.25 V | 无 | 无（上下文没有 datasheet） | 编数字，打回 |
| CC-CV 主段先恒流再恒压 | 阶段 0 §0.1.6 | （粘贴原句） | 机制一致；预充另算，截止电压仍以 datasheet 为准 |

四个判定只有这几种：

- **可用**　原文有这句，单位和适用条件也对得上。
- **降级**　机制讲得通，但数值没出处；只能当讨论，不能上板。
- **待查**　仓库没找到，不等于错；记下要查哪本手册、哪一页。
- **打回**　编数字、串型号、与贴进去的原文冲突，或建议绕过保护。

### 评分表

每轮只评自己，不评模型。四个维度，各 0–2 分。

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 机制 | 只会背结论 | 能说因果，漏边界 | 能说清因果、边界和失效条件 |
| 证据 | 全是记忆 | 部分能回链 | 每个数值都能指到原文 |
| 边界 | 给了阈值或越界建议 | 被提醒后收回 | 主动区分讨论值与上板值 |
| 复述 | 照抄模型 | 能用自己的话讲 | 能举反例并说明适用条件 |

8 分制：**≥6 分，且「机制」「边界」都不能是 0 分**，这一轮才算过。过不了就换一张卡，别在同一题上反复要它「再想想」。

### 停手规则

出现下面任意一条，停止这一问，不要继续追问「再想想」：

- 它给出能直接写进固件的阈值、寄存器值、延时或接线步骤。
- 它说「一般来说」「业内通常」，但给不出处。
- 它和你贴进去的原文冲突，还坚持自己是对的。
- 它建议短接真电池、绕过保护、带电操作，或把通信芯片放进安全回路。
- 它越问越肯定，却拿不出新证据。
- 它向你要凭据、密钥或 OTA 私钥。

前三条的处置是**改问题**：从「设多少」改成「由哪几层决定、各层依据什么」。后三条的处置是**结束本轮**，回到正文、手册和实物保护。

### 一段示范

> 你：过充保护应该设多少伏？
> 模型：建议 4.25 V，留一点余量。
> 你：停。上下文里没有 datasheet。请改答：过充保护由哪几层决定，各层依据什么；不要给数值。
> 模型：保护 IC 看电芯规格，AFE 负责采样，主控做策略，系统还要有独立兜底。
> 你：把每一句标出来源；没贴原文的写「推测」。

这段示范只演示动作，不演示结论。模型第二段里的分工也要回正文核对；它听起来对，不代表它读过你的板子。

## 写代码的五个关卡

模型可以起草代码、补测试、读 diff，但它交的是**草稿**，不是结果。改代码在三圈里属于「要签字」：草稿可以，合并要人点。下面五关一关不过，就不看下一关。

### 关卡 1 · 需求单

先写任务单，再让它写代码。任务单只有四行：

- **要什么**　一句可验收的行为，带输入和输出；不写「优化一下」。
- **怎么验**　一条能复算的命令，或一条现在会红、改完会绿的测试。
- **只许改**　列出文件；默认一个源文件加它的测试。
- **不许碰**　安全回路、保护阈值与寄存器值、依赖清单、生成产物、凭据与 OTA 私钥。

任务单没有验收条件，模型就会自己发明一个；发明出来的那个通常最容易过。

### 关卡 2 · 最小改动

一次只修一个问题。允许它加一个函数、补一条分支、紧贴现有风格写；允许它先交测试，再交让测试变绿的实现。不允许它顺手重构、重命名、换格式化工具，把 diff 撑大；不允许它新增依赖或改版本；不允许它手改 `docs/circuits/assets/` 下的生成图而不改生成器；更不允许它为了让测试变绿去改测试的期望值、加 skip 或删用例。

diff 一大，先让它拆；拆不开，说明它没理解任务。

### 关卡 3 · 跑真门

「应该能过」不算证据。按改动范围跑仓库已有的门，原样贴命令、退出码和关键输出：

| 改了什么 | 跑什么 | 通过长什么样 |
| --- | --- | --- |
| 只改文档 | `python .github/scripts/check_docs.py` | 打印 `ok: … relative file links exist`，没有 `FAIL` |
| Python 代码 | `python -m ruff check .`，再到对应目录 `python -m pytest tests/ -q` | ruff 打印 `All checks passed!`；pytest 无 failed |
| 协议或 PC 链路 | `cd code/protocol && python -m pytest tests/ ../firmware/tests/ -q` | 测试全绿；PC 综合实验随这一门实际编译 C |
| 固件 C | `cd code/firmware && gcc -std=c99 -Wall -Wextra -Werror -o test_bms bms.c test_bms.c && ./test_bms` | 编译零警告，测试进程退出码 0 |
| 擂台估计器 | `python challenges/01-soc/score.py --estimator challenges/01-soc/my_estimator.py:MyEstimator` | 打印档位与 RMSE；不许读真值轨迹 |
| 站点 | `npm run docs:build`，再 `python .github/scripts/check_pages.py docs/.vitepress/dist` | 构建成功；页数、链接、锚点、图片全过 |
| 全仓收口 | `bash scripts/local-gates.sh` | 各门打印 PASS/SKIP，没有 FAIL |

CI 还会跑 `challenges/` 的两个擂台基线并构建站点；本地门另有生成图、社交卡、发布记录等对账。命令以 [code/README.md](../code/README.md) 和 `scripts/local-gates.sh` 的现文为准，提示词里不要凭记忆写一条。

### 关卡 4 · 差异审查

不要听它怎么说，看 diff。五个地方逐一过：

| 看什么 | 危险信号 | 处置 |
| --- | --- | --- |
| 测试 | 断言变宽、加 `skip`、删用例、期望值跟着实现改 | 打回；测试是契约，不是障碍 |
| 异常 | `except Exception: pass`、静默返回默认值、错误码被吞 | 打回，除非原文明确要求降级并计数 |
| 行为 | 顺手改默认值、单位、符号或调用顺序 | 拆成单独改动，补一条能抓住它的测试 |
| 依赖 | 新包、版本漂移、lock 文件变化 | 先讨论，不放进这次任务 |
| 生成物 | 手改 SVG、缓存或输出产物 | 打回；改生成器再生成，用对账门验证 |

审查只做三件事：指出哪一行、说清为什么危险、要求补哪条测试。不要让它一边审一边重写——重写会把证据一起改掉。

> **练手**　[`challenges/03-ai-review/`](../challenges/03-ai-review/README.md) 有一份故意埋了五类问题的 diff：可见测试全绿，隐藏检查才会红。先写审查记录，再对照答案；`python challenges/03-ai-review/verify.py` 是对答案用的自检。

### 关卡 5 · 人签字

最后一关是交付单。模型可以起草，签字只能由人签。没有这张单，不合并。

#### 代码交付单

```text
【任务】…（一句可验收的行为）
【改动】…（文件 + 每个文件改了什么；≤5 行/文件）
【没有碰】安全回路 / 阈值与寄存器 / 依赖 / 生成产物 / 凭据
【新增或修改的测试】哪条先红、现在为什么绿
【本机跑的】命令 + 退出码 + 关键输出（原样粘贴，不转述）
【已知风险】这次改动仍然证明不了什么（仿真不是硬件、单元测试不是集成）
【回滚】改哪几个文件、按什么顺序退回
【签字】姓名 + 日期；阈值与安全相关改动需要第二个人
```

> **GitHub 版**　[代码交付模板](../.github/ISSUE_TEMPLATE/06-code-delivery.md) 把下面八行拆成 Issue 表单；PR 模板也会提醒同样的字段。

交付单里最容易空的是「已知风险」。空着不代表没有，代表没想。

#### 一段返工现场

> 模型：我把 `test_bad_crc_is_dropped_and_counted` 的断言从 `frames_bad_crc == 1` 改成 `>= 0`，测试绿了。
>
> 你：停。这是把契约改宽，不是修 bug。请回退测试，说明为什么坏 CRC 没有被计数；实现不许改测试的期望值。
>
> 模型：`feed()` 在 CRC 校验失败后直接复位，没有走到计数那一行。
>
> 你：只改这一处，补一条「坏帧计数为 1 且后续好帧仍能解析」的测试；贴 diff 和 pytest 输出。

判定：第一段的「测试绿」是**打回**，不是通过。测试变绿只证明当前断言被满足；把断言改宽，等于把门拆了再报平安。

#### 写代码的停手规则

出现下面任意一条，停止这一轮：

- 它要改保护阈值、安全回路、寄存器值、去抖时间或切断时序，且拿不出 datasheet 原句。
- 它要禁用、跳过、放宽测试，或删除失败用例。
- 它要往仓库里塞依赖、脚本、二进制，或让你运行来路不明的命令。

## 写代码

固定提醒：模型写的是草稿，合并要人签字。安全回路、保护阈值、寄存器值、依赖和生成产物不交给它；每条「通过」都要有本机命令、退出码和原始输出，不以它说「应该能过」为准。

对应正文：[code/ · 教程配套参考实现](../code/README.md)。关卡、交付单与返工现场见[写代码的五个关卡](#写代码的五个关卡)。

1. **需求拆解**　「我要改的是：让 `challenges/01-soc/my_estimator.py` 的估计器胜过擂台基线，且不读真值轨迹。请先不要写代码：列出最小改动涉及的文件、必须新增的测试、它能用的输入通道，以及这次明确不碰的东西（`score.py`、真值轨迹、保护阈值、依赖）。哪一项你判断不了，就写「需要我补原文」。」
2. **测试先行**　「请只给一条测试，风格照抄我贴的 `code/protocol/tests/test_frames.py`。它要能抓住『CRC 校验失败但 `frames_bad_crc` 没有加一』这个错误实现：把 `frames.py` 里那一行删掉时这条测试必须红，现状下必须绿。先不要改实现，也不要动现有测试的期望值。贴完告诉我从 `code/protocol` 目录跑哪条命令、应该看到什么失败信息。」
3. **代码审查**　「下面是一段 diff（粘贴）。只做审查，不要重写：逐项检查测试有没有被放宽、异常有没有被吞、行为有没有漂移、有没有新依赖、有没有手改生成物。每条给出文件、行号和要补的测试；没有问题的项也要写「未发现」。不要替我下「可以合并」的结论。」
4. **故障注入**　「只根据我贴的 `frames.py` 和测试，给 `FrameParser` 设计 5 个对抗输入：垃圾前缀、坏 CRC、非法长度、数据域里的伪帧头、逐字节喂入。每个都对应一条现有或应新增的测试，并写出预期是「收到」「丢弃并计数」还是「原文未定义」。不要发明新的协议字段或计数口径。」
5. **证据链**　「这是我刚跑的命令和输出（粘贴原文）。请填成代码交付单：任务、改动文件、新增哪条测试、命令、退出码、关键输出、已知风险。没有原样输出的项写「未跑」，不要补我没贴的输出；最后说明这次改动证明不了什么。」
6. **边界**　「我想让你直接把过充保护阈值写进 `bms.c`，并跳过那条一直红的测试。请拒绝，并说明：为什么阈值只能来自 datasheet 与仓库正文、为什么不能改测试来变绿、按仓库规矩应该改哪一层。不要给我任何新的阈值或毫秒数，也不要贴一段改好的 `bms.c`。」

## 错题本与周复盘

错题本只记**你**的错，不记模型的笑话。一行一个错，出处必须能点回正文。

| 日期 | 卡 | 我原来的说法 | 正确口径 | 出处 | 下次怎么问 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |

三条规矩：

1. 出处写正文的小节号或链接；找不到就写「待查」，不要写「AI 说的」。
2. 「正确口径」用自己的话写，不抄模型的整段。
3. 「下次怎么问」要写成一句能直接粘贴的话，下一轮原样用。

每周复盘只问五句：

- 这周哪一条是模型说对了、我也能回链的？
- 哪一条它说得很顺、但我找不到出处？
- 我有没有把仿真、合成或「示意」的数当成实测？
- 我有没有把「没看到」当成「没发生」？
- 下周先补哪一段原文？
