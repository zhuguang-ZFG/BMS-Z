## 3. 锚点冻结口径

1. 既有标题锚点**只增不删**：旧锚点（站外收藏、书内交叉引用、`完整查阅` 页旧链）必须继续可解析。
2. 现有守卫：`check_docs.py` 校验 Markdown 相对链接与锚点存在性；`check_pages.py` 在站点产物侧校验每页入口、链接与锚点。
3. W0 新增页（[视觉缺口表](视觉缺口表.md)、[kp_gap_audit](kp_gap_audit.md)、[工具可用性快照](工具可用性快照.md)）由 [SPEC §11](教材彻底改造SPEC.md) 与本页提供入口；删除入口等于把页面变成孤岛，`check_pages.py` 会报红。
4. 需要「改锚点」时：先在同页保留旧锚点（例如加 `<a id="old-anchor">` 或重复标题），再写决策行。

### 搜索索引预算处置（W0）

- 现象：W0 新增合同/审计页后，`@localSearchIndexroot.*.js` 达 **5018.9 KiB**，超过 4900 KiB 预算（R2 基线 4799.1 KiB）。
- 处置：**不抬预算**（`tools/check_site_bundle.mjs` 注释明确「再触顶时应先审内容增量」）。逐项审增量后，把**项目治理文档**排除出读者搜索索引：`docs/archive/**`、`docs/教材彻底改造SPEC.md` 与四张 W0 工作页加 `search: false` frontmatter（VitePress 本地搜索逐页排除；学习内容不动）。
- 复测：`npm run docs:build` → 搜索索引 **4727.9 KiB**（余量 172.1 KiB，约 3.5%）；普通 chunk 最大 771.6 KiB（预算 850 KiB）。
