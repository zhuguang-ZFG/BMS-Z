## 6.1 硬件精通

### 6.1.1 高压电池系统架构

几十到几百串的系统不再是一块板，而是三级结构：

```
        ┌─────────────┐
        │  BMU 主控    │ ← 对外 CAN / 绝缘检测 / 继电器驱动 / SOC 汇总
        └──────┬──────┘
               │ isoSPI / CAN（隔离）
   ┌───────────┼───────────┐
┌──┴──┐     ┌──┴──┐     ┌──┴──┐
│CMU 1│     │CMU 2│ ... │CMU n│  ← 每块从板管 12–18 串
└─────┘     └─────┘     └─────┘
BDU 配电盒：主正/主负继电器、预充回路、熔断器、电流传感器
```

板间通信的难点是共模：相邻从板的"地"隔着十几节电池的电位。isoSPI 的解法是变压器耦合——**信号穿墙，电位差留下**：

![isoSPI 菊花链动画](../circuits/assets/isospi-daisy.svg)

参考实现：[EnnoidMe/ENNOID-BMS](https://github.com/EnnoidMe/ENNOID-BMS)（330★，LTC68xx 菊花链 + 400V 电池包 + 接触器控制）。

高压系统还有一根"看不见的保险丝"——HVIL：

![高压互锁 HVIL 动画](../circuits/assets/hvil-loop.svg)

一根低压细线串遍所有高压接插件和维修开关，任何人拔枪或开 MSD，信号都比高压触点先断（针脚长短差保证这个时序），BMS 赶在人碰到端子前完成断接触器和母线泄放。

### 6.1.2 预充回路：合闸的艺术

母线电容（逆变器侧，几百 μF 到几 mF）完全放电时相当于短路——400V 直接合闸，瞬间电流数千安，继电器触点当场烧蚀粘连。解法是"先小水流灌满管道，再开主闸"：

![预充时序动画](../circuits/assets/precharge.svg)

时序三步：合预充继电器 K2（串电阻）→ 母线电压爬到电池电压 90–95%（约 $t \approx 3RC$）→ 合主继电器 K1、断 K2。

- 电阻选型：阻值按 $R \approx t/(3C)$；功率按单次冲击能量 $E = \frac{1}{2}CU^2$ 的**脉冲额定**（线绕/水泥电阻），不是连续功率；
- **预充失败判据**：超时母线电压上不来 → 外部短路或后端故障，**禁止合 K1**——量产 BMS 必备诊断，省的是整柜的保险。

### 6.1.3 绝缘检测（IMD）

高压包与机壳之间的绝缘电阻必须实时监测。主流**电桥法**：在 B+/B- 与机壳间交替投切已知电阻桥，测两组电压联立解出 $R_{iso+}$、$R_{iso-}$。

- 判据示例（以 GB/T 38661 或产品标准为准）：常见 <500Ω/V 报警、<100Ω/V 故障；
- 误差源：母线电压波动、Y 电容充放电——采样必须安排在投切后的稳态窗口内做，急不得。

![绝缘检测电桥法动画](../circuits/assets/imd-bridge.svg)

动画把"两次投切"演了一遍：B+ 侧投一次、B− 侧投一次，两组电压读数联立才能分别解出 R_iso+ 和 R_iso−——单侧绝缘下降时整包对地电位会偏移，只测一侧是要漏判的。

### 6.1.4 EMC 与热失控防护

- 采样链是模拟小信号，功率回路是 du/dt、di/dt 的噪声源：**分区布局、采样线双绞、通信隔离**；
- 继电器线圈：吸合后降 PWM 占空比保持（经济又降温），续流二极管不能省；
- 热失控链的 BMS 对策（回看 [热失控动画](../circuits/assets/thermal-runaway.svg)）：**dT/dt 温升速率**比绝对温度更早报警；熔断器是最后手段——它是不可复位的一次性保护，选型按 $I^2t$ 与 MOS/线束的耐受曲线配合。

### 6.1.5 并簇与环流：两包并联时 BMS 多管什么

储能常把多簇（或多包）并联扩容。电压不完全相等时，合闸瞬间会出现**环流**——电流在包与包之间窜，不经过负载，却能把接触器、线束和弱包打坏。

BMS / 系统侧最低要求：

1. **合闸前电压对齐**：簇间压差大于阈值（常见几十伏量级，按系统定）时禁止并簇；必要时先经预充/限流支路缓慢均压；
2. **每簇独立断路**：各簇有自己的接触器/熔断器，一簇故障可隔离，不拖死整柜；
3. **主从或协调层**：有一个能量管理/主控汇总各簇 SOC、SOP、故障，统一对 PCS 报"整柜允许功率"——单簇 SOP 简单相加在压差大时是错的；
4. **环流监测**：并簇母线上的异常电流（负载电流对不上各簇电流之和）要进故障策略。

并簇把"单包 BMS"升级成"多代理协调"——算法与通信都从板级问题变成系统问题。

![并簇环流动画](../circuits/assets/parallel-cluster-circulating.svg)

环流的账用示例值算一遍：1.5V 压差落在毫欧级的回路阻抗上，合闸瞬间就是几百安——不经过负载，全烧在接触器和线束上。所以第 1 条"先比压、再合闸"不是流程洁癖，是保命。

### 6.1.6 BMS 与热管理（TMS）的边界

BMS **不是**热管理系统，但热管理离开 BMS 的温度/功率信息几乎没法干活。边界划清，两边都不会越权：

| 谁 | 管什么 | 不管什么 |
|---|---|---|
| **BMS** | 测温（多点 NTC）、按温度降额 SOP、低温禁充/高温禁充放、dT/dt 热失控预警、请求"需要加热/需要制冷" | 不直接驱动水泵/压缩机占空比（除非产品把 TMS 并进同一控制器） |
| **TMS** | 加热膜/液冷回路/风机的执行与闭环控温 | 不擅自改充电电流上限——必须以 BMS 的允许功率为准 |

冬天"没劲儿 / 充得慢"：往往是 BMS 因低温收紧 SOP，并置位加热请求；TMS 把电芯打到允许窗口后，BMS 再放开功率。两边抢权（TMS 猛加热而 BMS 仍按冷电池限流，或反过来）是系统集成常见坑。

## 6.2 固件精通

### 6.2.1 量产状态机

在阶段 3 的最小集合上扩展成完整版图（巡游动画见 [状态机](../circuits/assets/state-machine.svg)）：

```
初始化 → 自检 → 待机 → 预充 → 就绪 ⇄ 充电 ⇄ 充电末端均衡
                         ⇅      ⇄ 放电
                        故障（分级：提示/限功率/断开）
                         ⇅
                        休眠 ⇄ 运输模式（深度低功耗）
```

三条铁律再背一遍：迁移集中一处；每个状态"进入/周期/退出"三动作明确；**任意状态可直接进故障态**。

### 6.2.2 故障管理（DTC 体系）

每个故障五要素：触发条件 + 去抖 + 等级 + 恢复条件 + 是否锁存。

**快照是灵魂**：触发瞬间冻结电压、电流、温度、SOC、时间戳。客户那边"昨天充不进电了"，没有快照你只能摊手；有了快照，你能在办公室看见事故现场的每一帧。故障码对外按 UDS 风格（车规）或自定义表（储能/消费）。

### 6.2.3 参数与标定系统

- 参数区：Flash 独立扇区，结构体 + 版本号 + CRC + **双备份**；
- 标定项：电流零漂（出厂必做，不做的话 SOC 出厂就偏几个点）、电压增益、NTC 偏移；
- 防写穿：写次数计数 + 磨损均衡；参数更新**先写备份区再切换**——更新中途掉电，旧参数还在。

### 6.2.4 Bootloader 与 OTA

- 双区（A/B）方案最稳：新固件写备用区 → 校验 → 标记切换 → 重启验证 → 失败自动回滚；
- 两条铁律：**bootloader 自身永不被 OTA 覆盖**；升级中断电必须能恢复原固件——做不到这两条，OTA 就是批量变砖机。

## 6.3 算法精通（阶段 4 的深化清单）

- **OCV 滞回建模**：状态里加滞回电压项（Plett Vol. II 的方法），解决"充放电曲线不重合"的系统误差；
- **双卡尔曼工程化**：快/慢滤波器的交替节奏、激励不足时冻结慢滤波器参数更新（可观测性保护）；
- **SOP 完整版**：多约束取最小 + 时长分级（2s/10s/30s）+ 温度查表降额（公式与符号约定见阶段 4）；
- **均衡策略工程化**：入口条件（充电末端、压差 > 阈值、温度允许）、目标选择（电压对齐 vs 容量对齐）、热约束下分时调度；大容量场景评估主动均衡（[电路详解 ③](../circuits/03-充电均衡与计量.md) 的拓扑对比）。

## 6.4 功能安全落地：以过充为例走一遍

ISO 26262 / GB/T 34590 的流程听起来抽象，走一遍就具体了：

1. **危害识别**：单体过充 → 热失控起火（回看 [热失控链](../circuits/assets/thermal-runaway.svg)）；
2. **场景分析**：充电中电压采样失效 / MOS 粘连 / 充电机失控；
3. **ASIL 定级**：由 HARA 结果决定——很多车用项目把防过充定为 ASIL C 或 D（仅为示例，须按场景、暴露率与车型风险评估定级）；
4. **安全目标**：任何单点失效不得导致单体电压超过安全限值；
5. **功能安全要求**：双通道独立保护——MCU 软件保护 + AFE/独立保护 IC 硬件保护；
6. **技术安全要求**：ADC 自检与开线检测周期按 FTTI（故障容忍时间间隔）推导，本例取 <100ms；MOS 驱动回路诊断；通信 CRC + 超时；独立看门狗；
7. **验证**：失效注入测试——拔采样线、短 MOS、停喂狗，逐项确认**硬件通道独立生效**。

一个单点失效 → 还有一道独立防线 → 电池仍然安全。这就是功能安全的全部朴素思想。深入研读：[《车用 BMS 功能安全设计方法论》（MDPI Energies 2021）](https://www.mdpi.com/1996-1073/14/21/6942)、[batterydesign.net《BMS 功能安全》](https://www.batterydesign.net/battery-management-system/functional-safety/)、[英飞凌知识库《ASIL 分解》](https://community.infineon.com/t5/Knowledge-Base-Articles/ASIL-decomposition-ISO-26262/ta-p/852405)。

## 6.5 量产与测试

**出厂标定与 EOL 清单**：电流零点（零电流读数写入参数区）、电压增益（标准源比对）；全串采样精度、通信收发、保护阈值抽测、绝缘电阻、静态功耗、固件版本与序列号烧录。

**HIL 测试**：电芯模拟器（入门可用电阻分压链，见 [EEVblog 实操帖](https://www.eevblog.com/forum/projects/lithium-battery-cell-simulatoremulator-for-bms-testing/)）+ **故障注入清单**：断任意采样线、短相邻采样线、NTC 开路/短路、通信中断、继电器粘连、电流超限——逐项验证 BMS 行为符合安全要求；边界工况：-20°C 启动、满充保持、深度过放恢复、长期静置唤醒。

**标准速查**（按产品选）：ISO 26262/GB/T 34590（功能安全母标准）、[GB/T 38661-2020](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=DB3ACC49AC4A146FAA311BB468ACA290)（车用 BMS 技术条件）、GB/T 39086-2020（车用 BMS 功能安全要求）、UL 1973/IEC 62619（储能）、UN 38.3（运输）、GB/T 32960（远程监控）。

## 6.6 毕业项目指南

**需求模板**（先写死再动手）：

```
串数/化学体系：16S LFP
持续/峰值电流：100A / 200A(10s)
保护清单：OVP/UVP/OCP×2/SCD/OTP/UTP/低温禁充/绝缘
均衡：被动 150mA，充电末端
算法：安时积分 + OCV 校准（+ EKF 加分项）
通信：UART（调试）+ CAN（系统）
结构：BMU 一体板 或 BMU + CMU×2
```

**里程碑**（每个都要可验证）：

1. 原理图评审（发 EEVblog / EEWORLD 求评）→ 2. PCB 投板焊接 → 3. 采样与驱动调通 → 4. 保护项全部实测通过 → 5. SOC 恒流误差 <5% → 6. 通信接入上位机 → 7. 完整文档（原理图说明、寄存器/协议文档、测试报告）

**发布清单**：开源仓库含 KiCad 工程、固件源码、BOM、测试报告、README（带实拍与接线图）→ 发社区接受评审。

**评审量规**（自评或请社区按此打分；「优秀」列就是产品级门槛）：

| 维度 | 达标（能用） | 良好（可交付） | 优秀（产品级） |

| 固件 | 状态机 + 保护去抖 | + 参数双备份、OTA 可回滚 | 诊断周期按 FTTI 推导 + 快照可读出 |

| 硬件 | 功能正常 | + 开线检测、预充时序实测 | + 绝缘检测实测 + EMC 预一致性摸底 |
| 文档 | README + BOM | + 原理图说明 + 寄存器/协议文档 | + 测试报告与复盘，他人可复现 |

## 6.7 自测题

1. BMU / CMU / BDU 三者各管什么？为什么板间通信必须隔离？
2. 预充电阻为什么按"脉冲额定"而不是连续功率选型？预充超时上不来电压，为什么**禁止**合主继电器？
3. 电桥法绝缘检测为什么要"交替投切"两组电阻？采样为什么必须安排在投切后的稳态窗口？
4. 故障五要素是哪五个？为什么说"快照是灵魂"？
5. 参数区为什么要双备份 + 先写备份再切换？
6. OTA 的两条铁律是什么？违反各自的后果？
7. 走一遍防过充的功能安全链：从危害识别到验证，双通道冗余体现在哪两个器件上？
8. FTTI 怎么约束 ADC 自检与开线检测的周期？
9. 故障注入测试清单里，"短相邻采样线"想验证什么？
10. 熔断器和 MOS 保护的分工是什么？为什么说熔断器是"最后手段"？
11. 两簇并联时为什么会有环流？合闸前 BMS/系统至少要检查什么？
12. BMS 与 TMS 各管什么？冬天动力受限时两者怎么配合？

<details>
<summary><b>参考答案（先自己想完再展开）</b></summary>

1. **BMU**（主控）：对外 CAN、绝缘检测、继电器驱动、整包 SOC/SOP 汇总、故障决策。**CMU**（从板）：每块管 12–18 串的电压与温度采样、执行被动均衡，把数据上报 BMU。**BDU**（配电盒）：主正/主负继电器、预充回路、熔断器、电流传感器——功率通断的执行机构。必须隔离的原因：相邻 CMU 的"地"参考在电池串的不同高度，隔着十几节电池、相差几十到几百伏；BMU 侧又常与整车低压地关联。不隔离就等于把这些电位差直接加到通信芯片的 I/O 上。
2. 因为母线电容储能 $E = \frac{1}{2}CU^2$ 这一份能量几乎全部在几百毫秒内变成预充电阻上的热。按连续功率选型会得出一个又大又贵的电阻，而实际需要的是**单次短时冲击耐受**能力——所以选线绕/水泥电阻，查它的单次脉冲能量额定（焦耳数）与重复动作间隔。禁止合 K1 的原因：电压上不来说明电流没在给电容充电，而是流去了别处——后端短路、绝缘失效、接触器粘连或母线故障。此时合主继电器 = 把电池直接接到一个故障回路上，数千安电流烧蚀触点甚至引发火灾。预充失败必须报故障并保持断开。
3. 因为要解的是**两个**未知量 $R_{iso+}$ 和 $R_{iso-}$（正母线对壳、负母线对壳的绝缘电阻），而一次测量只给一个方程。交替在 B+ 对壳、B− 对壳投入已知电阻，得到两组不同的电压测量值，联立两个方程才能把两个未知量分别解出来——只测一组无法区分到底是正侧还是负侧绝缘下降。必须等稳态是因为回路里有 **Y 电容**（母线对壳的滤波电容）：投切瞬间电容在充放电，电压处于指数过渡过程，此时采样得到的是暂态值，解出的绝缘电阻会严重偏离真值。必须等若干个时间常数后在稳态窗口采样。
4. 五要素：**触发条件、去抖、等级（提示/限功率/断开）、恢复条件、是否锁存**。快照是灵魂的原因：故障是**瞬时事件**，等用户反馈到你这里已经过了几小时甚至几天，现场工况早已消失。没有快照，"昨天充不进电了"这句话你无法复现、无法归因，只能摊手。有了触发瞬间冻结的电压/电流/温度/SOC/时间戳，你能在办公室看见事故现场那一帧——是某串过压、还是温度越线、还是电流尖峰，一目了然。量产 BMS 的售后能力基本等于它的快照质量。
5. 因为 Flash 写入是"擦除整扇区 → 重新写入"的**非原子**过程，中途掉电会留下一个既不是旧参数也不是新参数的半成品。若参数区只有一份，这块板子下次上电就读不出有效参数（阈值、标定系数全丢）——轻则不工作，重则按垃圾参数运行。双备份 + 先写备份区再切换有效标记，保证任何时刻**至少有一份完整且 CRC 正确的参数**：掉电发生在写备份区时主区完好，发生在切换标记时靠版本号/CRC 判定采信哪一份。配套还要写次数计数与磨损均衡，防止参数区被写穿。
6. ①**bootloader 自身永不被 OTA 覆盖**——违反的后果是升级包一旦出问题（或传输中断落在 bootloader 区），板子失去唯一的恢复入口，彻底变砖，只能拆机用调试器重烧；已发货的产品等于全部召回。②**升级中断电必须能恢复原固件**——违反的后果是用户升级途中拔电或电池耗尽，应用区留下半截固件又没有回滚机制，同样变砖。双区（A/B）方案同时满足两条：新固件写备用区 → 校验 → 标记切换 → 重启后验证通过才确认，失败自动回滚。
7. 链条：**危害识别**（单体过充 → 热失控起火）→ **场景分析**（充电中电压采样失效 / MOS 粘连 / 充电机失控）→ **ASIL 定级**（由 HARA 决定，很多车用项目取 ASIL C/D）→ **安全目标**（任何单点失效不得导致单体电压超过安全限值）→ **功能安全要求**（双通道独立保护）→ **技术安全要求**（ADC 自检与开线检测周期按 FTTI 推导、MOS 驱动回路诊断、通信 CRC + 超时、独立看门狗）→ **验证**（失效注入：拔采样线、短 MOS、停喂狗，逐项确认硬件通道独立生效）。双通道落在两个器件上：**MCU**（软件保护，第一级，快速可配置）+ **AFE 或独立的二级保护 IC**（硬件保护，第二级，不依赖 MCU 存活）。关键是两者的失效必须**不相关**——不共用采样链、不共用电源、不共用时钟，否则"冗余"是假的。
8. FTTI（故障容忍时间间隔）是"从故障发生到必须完成安全动作"的总预算。约束关系是：**故障检测时间 + 故障反应时间 ≤ FTTI**。而检测时间的最坏情况约等于"诊断周期 + 去抖确认时间"（故障刚好发生在一次诊断刚结束之后）。所以诊断周期要用 FTTI 减去反应时间与去抖时间后再留余量——文中示例取 <100ms。反过来说，如果诊断周期大于 FTTI，这项诊断在安全论证上等于**不存在**。
9. 验证两件事。①**读数合理性检查**：两根相邻采样线短接后，被短路的那节读数会掉到 0V 左右，而它的邻居变成两节之和（约 7–8V）。BMS 必须识别出"某串 0V"和"某串明显高于单体上限"这类**物理上不可能**的组合，而不是把 0V 当成严重过放、把 8V 当成真实值去执行错误动作。②**诊断的覆盖面**：开线检测能查断线，但查不出短接——需要独立的范围校验与一致性校验（单串上下限、各串之和与总压比对）。这项注入专门检验那条校验是否真的实现了。
10. **MOS/继电器**是**可复位**的主动保护：由 BMS 判断后断开、能恢复，承担日常的过流/短路/过充过放保护，阈值与延时可配置。**熔断器**是**不可复位**的被动保护：靠自身 $I^2t$ 特性在极端电流下熔断，不需要任何电子电路参与。它是最后手段的原因：①一旦熔断必须更换硬件，对产品是一次维修事件，所以额定值必须选在"MOS 保护和继电器都已失效（粘连/击穿）"的工况才动作；②选型必须与 MOS、线束的 $I^2t$ 耐受曲线**配合**——熔断特性要快于线束着火、慢于 MOS 的正常保护动作，否则要么烧线束，要么日常工况就误熔。
11. 两簇开路电压不完全相等时，合闸等于把两个电压源经很小的回路电阻并联，压差 ÷ 回路电阻 = **环流**（不经负载）。合闸前至少检查：簇间压差低于阈值、各簇无严重故障、必要时经限流/预充支路均压；并保证每簇可独立断开、有协调层汇总 SOP，且能监测"各簇电流之和与母线电流不一致"这类环流迹象。
12. **BMS** 负责测温、按温度降额 SOP、低温禁充/高温禁充放、热失控预警，并向 TMS **请求**加热或制冷；**TMS** 负责加热/液冷/风道等执行与控温，但不得擅自突破 BMS 的允许功率。冬天配合：BMS 收紧 SOP 并请求加热 → TMS 把电芯温度打进窗口 → BMS 再放开充电/放电功率。

</details>
