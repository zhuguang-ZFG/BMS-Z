## 高星项目的共同规律

### 1. 内容不是文件堆，而是课程图

高星项目会把“从哪开始、下一步是什么、什么算完成”写成结构，而不是让读者从目录自己猜。BMS-Z 因此新增：

- 核心问题稳定 ID；
- 先修关系与预计时间；
- 阶段、书、动画、视频、代码的一对多映射；
- 每个问题的验收输出。

### 2. 主线与资源库分开

路线图负责学习顺序，资源库负责查阅。BMS-Z 首页以后只回答三个问题：

1. 我从哪里开始？
2. 我想完成什么任务？
3. 我现在卡在哪个核心问题？

动画总表、书单、工具箱和导读继续保留，但不再抢占首次入口。

### 3. 看完不是完成，交付才是完成

freeCodeCamp 用项目，OSSU 用最终项目，system-design-primer 用问题与解答。BMS-Z 对应地要求每个阶段至少留下一个可复算产物：运行记录、计算表、故障时间轴、测试输出或评审单。

### 4. 内容规则要能自动检查

大项目依靠格式、链接、结构和来源检查维持规模。BMS-Z 已经有很强的工程质量门；本轮补上课程图检查，避免动画改名、视频换段或书稿移动后，入口仍指向旧位置。

## 明确不做

- 不把现有视频流水线重写成 Remotion、Manim 或 Motion Canvas；技术迁移本身不会让内容更易懂。
- 不照搬 roadmap.sh 的节点视觉；BMS-Z 的核心视觉仍是电池、电路、曲线和时间轴。
- 不把 32 章伴读书切成大量碎片；深度内容保留，入口和首次阅读层负责减负。
- 不把星标数当作设计投票。只有能改善“找到、理解、练习、验证”的机制才进入项目。

## 本轮已经采用

- [核心问题地图](核心问题地图.md)：问题驱动入口。
- `curriculum/concepts.json`：机器可读课程图。
- `tools/check_curriculum.py`：跨媒介映射与先修关系检查。
- 首页目标路线：面向任务而不是面向文件夹。
- [项目改造计划](项目改造计划.md)与[教学设计规范](教学设计规范.md)：为后续批量改造提供同一把尺子。
- `tools/gen_curriculum_pages.py`：核心问题页由课程 JSON 生成，手改生成物或漏同步字段会被 CI 拦截。
- 核心问题双测结构：先押答案，完成书/图/视频/练习后回到同一道题复答。
