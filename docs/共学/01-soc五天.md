# 共学：SOC 五天

> **本篇你会学到**　纯安时积分为什么会漂，校准点和 EKF 差在哪，以及怎么在固定仿真题上拿出一个 RMSE。
> **预计用时**　5 天，每天大约 45–90 分钟。
> **前置**　装好 Python 3.10+，在仓库根执行过 `pip install -r code/requirements.txt`。不需要电池。

⚠️ 下面的百分比是 `compare.py` 或擂台脚本印出来的**仿真结果**。模型、噪声和容量误差都写在脚本里。不要把它们抄进保护板。

## 第 1 天：油表会分叉

**读**　[阶段 4 §4.1](../stages/stage-4-SOC-SOH算法.md#41-问题定义给电池做油量表难在哪-理解)。四个捣蛋鬼：零漂、容量在变、开路电压不是一条死曲线、温度会让可用容量缩水。

**看**　[库仑计漂移动画](../circuits/assets/coulomb-counting.svg)。不看动画也能读：显示水位和真实水位会分开。底栏那条 +0.10 %/h 是示意直线，不是今天命令的输出。

**跑**（在仓库根）：

```bash
cd code/soc && python3 compare.py
```

PowerShell：

```powershell
cd code/soc ; python compare.py
```

2026-10-06 在本仓库跑通，三行是：

```text
纯安时积分            10.62%     -7.88%
积分+校准点            2.67%      0.00%
Thevenin+EKF      0.20%      0.00%
```

这是种子 42 的教学工况（约 4.7 小时仿真）：初始 SOC 给成 0.7、真值 0.8，容量按 9.5 Ah 假定、模型是 10 Ah，电流零漂 +2 mA。你的终端应印出同样三行。多一位或少一位，把原文贴出来，不要手改。

**交**　打卡里贴这三行，加一句：三条曲线吃的是同一段电流，分叉来自「怎么校正」。

**口诀**　同一块电池，三种听法。没有校正的那条，漂得最远。

**今天你解锁了**　你在自己电脑上看见了「估算器会分叉」，而且数字对得上仓库。

**短自测**　RMSE 和最后一列的末端误差，是同一个数吗？

<details>
<summary>先自己答再展开</summary>

不是。RMSE 看整段路程的偏差有多大。末端误差只看最后一步。纯积分两列都难看；带校准的那条，末端可以被锚拉回 0，路上仍有 RMSE。

## 第 2 天：没有锚就会梦游

**读**　[阶段 4 §4.2](../stages/stage-4-SOC-SOH算法.md#42-安时积分库仑计主力但它会梦游-分析)。核心就一行：`SOC += I * dt / Q`。

**看**　还是 [库仑计漂移](../circuits/assets/coulomb-counting.svg)。盯住黄点离开原点。口诀在图说里：安时一直在加。零漂会把油箱慢慢加歪，满充时拉回一次。

**跑**　再执行一次昨天的命令，只盯「纯安时积分」那一行的两列：`10.62%` 和 `-7.88%`。

```bash
cd code/soc && python3 compare.py
```

PowerShell：

```powershell
cd code/soc ; python compare.py
```

**交**　用两句话分开写：初始少给的那 10 个点，会把估计往哪边拉；电流零漂 +2 mA（充电为正）日积月累又往哪边推。不要新编一个百分比。

**口诀**　没有锚的积分，不会自己走回来。

**今天你解锁了**　你能向别人解释：末端 −7.88 个点，不是「电池真的少了 7.88%」，是估计比真值低。

## 第 3 天：尺子要静够了才准

**读**　[阶段 4 §4.3](../stages/stage-4-SOC-SOH算法.md#43-ocv-法好尺子但经常够不着-分析)。端电压里还夹着内阻和极化。静够了，才有资格叫开路电压。

**看**　[OCV–SOC 曲线](../circuits/assets/ocv-soc-curve.svg)，再看 [平台区为何不信电压](../circuits/assets/ocv-plateau-distrust.svg)。铁锂那种平的一段，几毫伏就能换成很大一块 SOC。图上的电压是示意。

**跑**

```bash
cd code/soc && python3 -c "from cell_model import ocv; print('ocv(0.5)=', f'{float(ocv(0.5)):.3f}')"
```

PowerShell：

```powershell
cd code/soc ; python -c "from cell_model import ocv; print('ocv(0.5)=', f'{float(ocv(0.5)):.3f}')"
```

本仓库输出：`ocv(0.5)= 3.750`。这是教学解析曲线在 SOC 0.5 处的值，**不是**某一颗三元或铁锂的规格。

**交**　打卡写这行输出，并写一句：为什么不能把 3.750 V 设成你的保护阈值。

**口诀**　平台上少信电压。静够了才查表。

**今天你解锁了**　你把「端电压」「开路电压」「保护阈值」分成了三件事。

## 第 4 天：先跳一下，再拖一条尾巴

**读**　[阶段 4 §4.4](../stages/stage-4-SOC-SOH算法.md#44-等效电路模型让电压在动态中也能用-分析)。$R_0$ 是电流一加就出现的跳。$R_1C_1$ 是松开以后慢慢回来的尾巴。

**看**　[阶跃 R0 与 RC 尾巴](../circuits/assets/rc-step-r0-tail.svg)。

**跑**

```bash
cd code/soc && python3 hppc_demo.py
```

PowerShell：

```powershell
cd code/soc ; python hppc_demo.py
```

末行应是：

```text
PASS：全部 SOC 点在容差内——方法闭环成立；换真实数据时流程相同，只是数据源从 TheveninCell 换成你的采集文件
```

表里的毫欧和法拉是合成辨识对教学模型的误差，不是台架实测。脚本自己把容差印在最后一行上面。

**交**　贴 PASS 那一行。用自己的话写：脉冲沿上先读谁，静置尾巴上再读谁。

**口诀**　一加电流先跳 $R_0$。松开以后，尾巴才回来。

**今天你解锁了**　你跑通了一次「合成 HPPC」，并且知道它还没换成真实采集文件。

## 第 5 天：把 RMSE 交到擂台上

**读**　[阶段 4 §4.5](../stages/stage-4-SOC-SOH算法.md#45-卡尔曼滤波两个不完美信息源的联姻-分析)。预测靠模型，校正靠电压残差。Q 大就更信测量，R 大就更信模型。

**看**　[EKF 估计](../circuits/assets/ekf-estimation.svg) 是 `compare.py` 种子 42 的仿真曲线：金线是纯安时，蓝线贴着真值。想看两条回路怎么套在一起，再打开 [库仑计与 EKF](../circuits/assets/coulomb-ekf-loop.svg)。那张才是「1 mA 一天 24 mAh」的示意账。

**跑**（回到仓库根，不要停在 `code/soc`）：

```bash
python3 challenges/01-soc/score.py
```

PowerShell：

```powershell
python challenges/01-soc/score.py
```

2026-10-06 的仿真基线（种子 `20261006`，5000 步）。脚本会先印「公开档」、再印噪声更大的「更吵档」第二组基线——打卡先比下面这张公开档：

| 估算器 | RMSE | 身份 |
|---|---:|---|
| 纯安时积分 | 10.113652% | **基线，要胜过它** |
| 积分+校准点 | 7.575092% | 仓库参考，不是基线 |
| Thevenin+EKF | 0.204740% | 仓库参考，不是基线 |

要上榜，就让你的估计在**同一套测量**上的 RMSE **小于** 10.113652%（分数，不是百分比的另一种算法；脚本按 $\sqrt{\mathrm{mean}(e^2)}$ 算，再印成百分数）。调用仓库里的 EKF 可以过线，请在打卡里写明「复现仓库 EKF」还是「我改了 Q/R」。榜单只收仿真，见 [擂台](../擂台.md)。

**交**　贴公开档里基线那一行，加上你自己的 RMSE 和做法一句。

**口诀**　两个不完美的消息，按你有多信任它们掺在一起。

**今天你解锁了**　你有一个能和基线比大小的仿真 RMSE。比赢了，就去擂台留名；比没赢，你也知道差在校正，不在「电脑算错」。
